# 2026-07-22 工作日志

## 云 API 错误排查

用户反馈 SQLTeacher 桌面应用提示 "cloud api 错误"。排查结果：

- 根因：`SqlTeacherApplicationConfig.cloudApiClient()` 的默认云地址为 `https://api.sqlteacher.invalid`，这是 RFC 2606 保留的占位域名，DNS 永远无法解析。
- 错误链路：`HttpCloudApiClient.send()` 连接失败 → IOException → `IllegalStateException("Cloud API is unavailable")` → 经 `CloudCenterController.message()` 显示在云中心状态栏。
- 项目自带本地云服务器 `com.sqlteacher.server.SqlTeacherCloudServer`（监听 127.0.0.1:8080，需单独启动），但桌面应用默认未指向它。
- `HttpCloudApiClient` 强制 HTTPS，仅允许 loopback HTTP。
- 解决方案：启动本地云服务器后用 `-Dsqlteacher.cloud.base-url=http://localhost:8080` 启动桌面应用；或暂不使用云中心功能。

## 关键文件位置
- 云客户端配置：`src/main/java/com/sqlteacher/infrastructure/spring/SqlTeacherApplicationConfig.java:121`
- HTTP 客户端实现：`src/main/java/com/sqlteacher/infrastructure/cloud/HttpCloudApiClient.java`
- 云中心 UI 控制器：`src/main/java/com/sqlteacher/desktop/controller/CloudCenterController.java`
- 本地云服务器：`src/main/java/com/sqlteacher/server/SqlTeacherCloudServer.java`

## 修复云 API 默认地址

用户要求将默认云地址改为真实域名。

- 修改文件：`src/main/java/com/sqlteacher/infrastructure/spring/SqlTeacherApplicationConfig.java:123`
- 改动：`"https://api.sqlteacher.invalid"` → `"https://api.sqlteacher.tech"`
- 全仓库搜索确认无其他位置引用旧域名 `api.sqlteacher.invalid`。
- 注意：Maven 环境异常（scoop 安装的 Maven 缺少 classworlds launcher），无法运行 `mvn compile` 自动验证；改动为纯字符串字面量替换，无语法风险。
- 用户仍需确保 `api.sqlteacher.tech` 域名已解析到实际运行的 `SqlTeacherCloudServer` 实例，否则仍会报 "Cloud API is unavailable" 或 HTTP 错误。
