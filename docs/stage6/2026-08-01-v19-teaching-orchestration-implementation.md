# v1.9 可验证教学编排功能收敛记录

> 实施日期：2026-08-01
> 本地数据库：app schema 10
> 云端数据库：Cloud schema 5
> 计划策略：`v1.9.0-r1`
> 范围：功能代码、自动化测试、正式版本发布与生产部署

## 完成范围

### 课程目标与计划

- 教师工作台支持创建、编辑、排序、停用/恢复课程目标，填写可验证完成条件。
- 支持目标之间的同课程先修关系，以及知识点、知识文章、不可变练习版本关联。
- 服务端拒绝自引用、环路、跨课程资源、停用资源和过期乐观版本。
- 目标版本进入稳定动作 ID；目标变化后旧动作状态不会静默套用到新版本。
- 确定性计划最多 7 项，稳定排序，优先处理先修缺口；AI、Embedding、Qdrant 和联网搜索均不参与优先级或完成判断。
- 本地真实练习诊断被归一化为最小证据引用，只保存事实 ID、版本、哈希和时间，不复制 SQL 正文或敏感数据。
- 学生首页统一合并本机诊断、正式任务、未读反馈和课程目标计划；云端不可用时保留本机诊断及最后有效的账号隔离计划。

### 生命周期与同步

- 动作支持 `OPEN`、`STARTED`、`COMPLETED`、`DISMISSED`、`INVALIDATED` 状态。
- 本地保存计划快照、事实水位、动作状态、差异解释和证据引用；过期快照不会继续展示。
- 开始、完成和忽略操作先写本地 Outbox，再以稳定操作 ID 上传；重复请求幂等。
- 服务端使用动作版本进行乐观冲突校验；可重试错误保留并退避，非重试冲突标记为拒绝，后续刷新采用服务端事实。
- 账号切换依靠 `owner_id/account_id` 隔离目标、快照、动作、Outbox 和辅导会话。

### 有依据辅导

- 知识中心要求辅导绑定课程范围和课程目标稳定标识。
- 延续发送前上下文预览、引用白名单、资料不足拒答和 AI 故障确定性摘要。
- 会话只保存目标、检索快照哈希、Provider、模型、结果码和降级状态，不保存完整问题或回答。
- 学生可提交“有帮助、仍不理解、引用有误”等枚举反馈；反馈受当前账号所有权约束。

### 教师编排与回看

- 教师可按课程目标查看班级未知、需支持、发展中和已掌握人数。
- 汇总只描述提交事实，不生成教师排名、黑盒有效性分数或因果结论。
- 干预采用“动作草稿 → 影响人数预览 → 短期确认令牌 → 目标版本复核 → 明确确认 → 审计”流程。
- 目标在预览后发生变化时，确认会被拒绝，教师必须重新生成草稿。
- 新增管理员规划健康摘要，报告目标、计划同步、已确认干预和辅导反馈数量，不暴露正文。

### 数据与恢复边界

- app schema 10 保存目标镜像、资源镜像、计划快照、动作、证据、Outbox 和辅导元数据。
- Cloud schema 5 保存目标图、动作状态、幂等操作、教学周期骨架、干预草稿/审计和聚合反馈骨架。
- 本地 schema 迁移支持重复执行并拒绝未来版本；Cloud schema 5 重复初始化安全并拒绝未来版本。
- “清理学习数据”同时删除计划派生数据、Outbox 和辅导元数据，保留题库与课程知识。

## 自动化验证

- `mvn -q test`：362 项通过、0 失败、0 错误；2 项真实 AI 环境测试按设计跳过。
- 30 条固定学习旅程覆盖不同目标数量、先修边、完成事实和三类资源，重复及反序输入保持同一结果。
- 10,000 条目标/资源事实确定性计划测试套件耗时约 0.158 秒，低于 750 ms 门禁；结果稳定限长为 7。
- 500 名学生课程目标汇总在完整 HTTP 集成测试中的整套测试耗时约 0.8 秒，汇总断言低于 2 秒门禁。
- HTTP 集成覆盖目标 CRUD/版本冲突、先修环路、三类资源、学生计划、动作状态、班级汇总、干预预览、版本失效和人工确认。
- 数据测试覆盖计划差异、状态保留、Outbox、幂等同步数据、账号隔离、辅导元数据最小化、反馈所有权、清理和未来 schema 拒绝。
- FXML/XML 资源测试覆盖新增学生辅导与教师编排控件的格式完整性。
