# 权属与待确认事项

以下事项不能仅凭代码仓库确认，必须由学校和全体权利相关方在递交前按事实填写、签署并留档。

## 1. 申请主体

- [ ] 学校法人证书或其他有效证件上的法定全称。
- [ ] 学校是否作为全体著作权人的申请代表。
- [ ] 是否允许学校与学生、教师或其他自然人共同登记，以及共同著作权人顺序。
- [ ] 校内归口部门、成果审批、盖章及授权流程。
- [ ] 每位自然人姓名、证件类型、号码、通讯信息是否与有效证件一致。

当前仅能按“合作开发、学校拟列第一著作权人/第一署名单位”准备，不能据此替代学校的正式权属决定。

## 2. 合作开发与权利归属

项目文档描述多人分工，仓库也存在多个提交身份。申请前应取得可证明最终权利人范围和排序的书面材料，并核实是否存在课程任务书、委托开发关系、劳动关系、资助协议或学校知识产权规定。

- [ ] 是否有合作开发协议、项目任务书或校内立项文件。
- [ ] 所有实际开发成员是否均应列为共同著作权人。
- [ ] 指导教师、学校、出资方或课程组织方是否有书面权属约定。
- [ ] 申请代表是否已获得其他共同著作权人的书面同意或授权。
- [ ] Git 提交邮箱、昵称与真实开发者身份的对应关系是否已留存。

## 4. 申请内容与隐私核对

- [ ] 功能说明只覆盖已实现能力，不把路线图、原型或规划功能写成已交付。
- [ ] Ollama 和网络 AI 被表述为可选外部运行依赖，不主张第三方模型或服务本身。
- [ ] JavaFX、Spring、Jackson、JDBC 驱动、SQLite、MySQL、MariaDB、Ollama 及其他第三方组件未被作为自研代码主张。
- [ ] 所有截图、日志、导出文件和源程序均已检查，未包含密码、API Key、访问令牌、学生个人信息和生产服务器地址。

## 5. 建议保存的内部证据

- 冻结提交、Git 日志、完整源码归档及 SHA-256。
- 合作开发协议、任务书、权属说明、授权书与校内审批材料。
- `mvn test` 结果、打包日志、安装包/app-image、验收记录和截图原件。
- 最终申请表、程序材料、说明书、权属证明及提交回执的 PDF 与哈希值。
