## 目标

2.2 解决两个直接影响入门体验的问题：

1. 用户不应为了开始一门课程，先理解 JDK、Python、MSVC、WSL、Ollama、模型和数据库驱动的安装关系；
2. 数据库能力不应继续被 `SQLITE / MYSQL / MARIADB` 三项枚举和连接工厂中的分支限制。

本版本采用“先接入、再分级验证、最后集中加固”的兼容优先顺序，同时坚持“能内置就零配置、能按用户管理就应用内安装、必须改系统就引导并复检”。核心本地学习能力仍可离线使用；某个兼容项不完整不能阻止应用启动。

兼容性完成不再要求每个组件、数据库和方言先达到相同的安全成熟度。2.2 先保证探测、选择、连接、运行和元数据读取能够工作，再按正式、兼容、实验三级向用户如实标注支持程度。现有单语句、预览、确认和有界结果等公共执行底线继续复用，但新增兼容项不以完成全部专属风险规则为前置条件。

## 现状盘点

### 可选组件

| 能力 | 2.1 现状 | 用户成本 |
| --- | --- | --- |
| Java 学习 | 安装包内有运行时，但本地编译依赖额外 JDK 和 `javac` | 用户容易把 JRE、JDK 和应用运行时混淆 |
| Python 学习 | 本地路径依赖名为 `Ubuntu` 的 WSL 发行版及其中的 `python3` | 安装 WSL、重启、初始化发行版、再装 Python |
| C/C++ 学习 | 只探测 Visual Studio/MSVC Developer Shell | Build Tools 体积大，工作负载选择不直观；已有 Cygwin/MinGW 无法复用 |
| 安全评价 | 依赖 WSL2、Ubuntu、systemd、namespace 工具和 Linux 编译器 | 属于系统级环境，无法由普通安装包可靠静默完成 |
| 本地 AI | 只探测本机 Ollama 和已经下载的模型 | 用户需要自行安装服务、启动并选择模型 |
| 数据库 | 应用内置 SQLite JDBC；MySQL/MariaDB 驱动已随应用分发，但服务器由用户准备 | 用户分不清“驱动已存在”和“数据库服务未安装” |

现有探测分散在 Runner、Ollama 状态服务和技术验证类中，只能回答“当前能否使用”，缺少统一的版本、来源、安装、修复、升级、磁盘占用和重启状态。

### 数据库耦合

- `DatabaseDialect` 是固定枚举，连接页面直接枚举其全部值；
- `JdbcConnectionFactory` 直接构造 MySQL 和 MariaDB 驱动对象；
- 连接配置只区分 SQLite 文件与通用服务器字段，无法表达 TLS、实例名等受控选项；
- SQL 风险分析只有 MySQL/MariaDB 的方言附加规则；
- 练习评测仍以 SQLite 为确定性基线，这一点应保留，不随外部数据库数量膨胀。

## 路线比较

| 路线 | 优点 | 主要问题 | 结论 |
| --- | --- | --- | --- |
| 巨型离线安装包 | 首次安装后组件齐全 | 安装包会快速膨胀；模型以 GB 计；MSVC/WSL 有独立许可、管理员权限和重启流程；各组件更新周期不同 | 不采用 |
| 只增加帮助文档和下载链接 | 实现快、维护成本低 | 仍要求初学者自己判断版本、PATH、工作负载和失败原因 | 不足以解决目标 |
| 直接调用 `winget` 安装一切 | 能利用官方包源 | `winget` 不保证存在；部分组件仍需管理员权限或重启；难以管理模型和应用专属版本 | 只作为安装策略之一 |
| 混合式组件中心 | 可复用已有环境，也能提供应用管理的版本；安装失败可恢复；基础应用保持轻量 | 需要建立组件模型、下载验证和恢复状态 | **推荐** |

## 推荐方案一：统一组件中心

### 组件模型

在应用层建立与 UI、PowerShell 和具体厂商无关的契约：

- `ComponentDescriptor`：组件 ID、用途、许可链接、预计下载/磁盘级别、是否需要管理员权限或重启；
- `ComponentProbe`：返回 `READY / MISSING / OUTDATED / BROKEN / RESTART_REQUIRED` 和稳定原因码；
- `ComponentInstallStrategy`：`BUNDLED / MANAGED_ARCHIVE / WINGET / EXTERNAL_INSTALLER / GUIDED_SYSTEM`；
- `ComponentActionService`：下载、校验、安装、修复、取消和卸载应用管理的组件；
- `CapabilitySnapshot`：把多个底层组件汇总成“可运行 Java”“可运行 Python”“可用本地 AI”等教学能力；
- `ComponentCatalog`：随 SQLTeacher 版本发布的固定目录，不在运行时执行远端下发的任意命令。

“环境准备”页面在首次进入相关活动时按需出现，也可从设置中主动打开。探测在后台执行并缓存，不阻塞 JavaFX 线程；每项只显示用户需要理解的结果、下载级别和下一步。

### 分层处理

| 层级 | 组件 | 2.2 处理方式 |
| --- | --- | --- |
| 随应用提供 | Java 运行时、SQLite、JDBC 驱动、基础课程 | 安装后立即可用，无额外提示 |
| 应用管理、当前用户安装 | Temurin JDK 17/21/25、`uv` 与受管 Python、Ollama/模型 | 优先复用合格现有版本；缺失时由组件中心下载、校验并安装到应用数据目录或调用官方用户级安装器 |
| 系统级引导 | MSVC Build Tools、WSL2/Ubuntu、安全评价工具链 | 明确显示管理员权限、磁盘和可能重启；用户确认后启动官方流程，应用重启后自动复检 |
| 外部服务 | 关系数据库、兼容数据库、本地/网络 AI 服务 | 不强制安装服务器；优先提供连接预设、通用连接测试和可立即使用的内嵌数据库替代实验 |

具体选择依据：

- Ollama 官方 Windows 安装器不需要管理员权限，也提供独立 CLI 压缩包，适合受控的用户级安装；模型应单独展示大小和许可，不能假设 Ollama 的许可覆盖模型。参考 [Ollama Windows 文档](https://docs.ollama.com/windows)。
- Temurin 提供 Windows 安装器、压缩包、WinGet 包及带校验和信息的 API，适合固定 Java 21 特性版本后放入应用管理目录。参考 [Adoptium 安装方式](https://adoptium.net/installation) 与 [Adoptium API 示例](https://github.com/adoptium/api.adoptium.net/blob/main/docs/cookbook.adoc)。
- `uv` 能发现已有 Python，也能安装应用管理的 Python；2.2 应使用固定版本的可执行文件和独立安装目录，不执行 `irm | iex` 一类远端脚本管道。参考 [`uv` Python 管理文档](https://docs.astral.sh/uv/guides/install-python/)。
- MSVC 官方提供独立 Build Tools 和命令行工作负载，但安装规模和系统影响较大，适合引导而非塞入 SQLTeacher 安装包。参考 [MSVC Build Tools 文档](https://learn.microsoft.com/en-us/cpp/overview/acquire-msvc)。
- `wsl --install` 可能启用系统功能并要求重启，只能作为用户确认后的系统操作。参考 [WSL 安装文档](https://learn.microsoft.com/en-us/windows/wsl/install)。

### 本地编译器路线

1. Java：兼容用户指定、PATH、`JAVA_HOME`、注册表和受管目录中的 JDK 17、21、25；课程可声明目标版本，默认仍为 Java 21。Runner 使用组件中心返回的绝对路径，不依赖单一全局 PATH。
2. Python：兼容 `py.exe`、PATH、官方 CPython、`uv` 受管 Python、Conda、WSL 多发行版和用户指定解释器；本地 IDE 优先使用 Windows 原生 Python，WSL 不再是普通练习的硬前置。
3. C/C++：建立工具链适配器，兼容 MSVC、Cygwin GCC/G++、MinGW-w64、LLVM/Clang 和用户指定编译器。自动安装可先覆盖 MSVC Build Tools，其他工具链先完成探测、选择和命令模板。
4. 安全评价：继续保持可选；组件中心可以诊断和引导安装，但不得在隔离条件不满足时退回本地运行并冒充安全评价。
5. AI：除本机 Ollama 外，兼容自定义 Ollama 地址和 OpenAI-compatible 本地端点，为 LM Studio、llama.cpp server 等实现保留统一的模型发现与对话适配接口；不把某个厂商名称写死为 AI 能力本身。

## 推荐方案二：数据库提供者注册表

### 三级兼容矩阵

| 数据库/协议 | 类型 | 2.2 级别 | 接入方式 |
| --- | --- | --- | --- |
| SQLite | 内嵌文件数据库 | 正式支持 | 继续作为零配置课程和确定性评测基线 |
| DuckDB | 内嵌分析数据库 | 正式支持 | JDBC 可直接创建内存或文件库，适合数据整理、分析 SQL 和公开数据课程；无需数据库服务器。参考 [DuckDB JDBC 文档](https://duckdb.org/docs/current/clients/java) |
| H2 | 内嵌/服务器数据库 | 正式支持 | 为 Java、Spring 和 JDBC 教学提供常见内存数据库兼容环境 |
| MySQL | 外部服务器 | 正式支持 | 保持现有能力并补齐 TLS 预设 |
| MariaDB | 外部服务器 | 正式支持 | 保持现有能力并补齐 TLS 预设 |
| PostgreSQL | 外部服务器 | 正式支持 | 教学和工程使用广泛，官方 JDBC 驱动可直接分发。参考 [pgJDBC 下载与设置](https://jdbc.postgresql.org/download/) |
| SQL Server / Azure SQL | 外部服务器 | 正式支持 | 官方 Type 4 JDBC 驱动无需本机客户端库，并支持 Java 21。参考 [Microsoft JDBC 驱动下载](https://learn.microsoft.com/en-us/sql/connect/jdbc/download-microsoft-jdbc-driver-for-sql-server) |
| Oracle Database | 外部服务器 | 兼容支持 | 使用 JDBC Thin 驱动和常用服务名/SID字段；Oracle官方支持从Maven Central获取驱动。参考 [Oracle JDBC 指南](https://docs.oracle.com/en/database/oracle/oracle-database/21/jjdbc/jdbc-developers-guide.pdf) |
| IBM Db2 | 外部服务器 | 兼容支持 | 支持用户提供或组件目录中的 JCC 驱动，先保证连接、测试和标准元数据 |
| 达梦 DM8 | 外部服务器 | 兼容支持 | 使用官方 `com.dameng:DmJdbcDriver8` 驱动。参考 [达梦 Java 接入文档](https://eco.dameng.com/document/dm/zh-cn/start/JAVA_NEW.html) |
| TiDB | MySQL 兼容协议 | 兼容预设 | 复用 MySQL Connector/J，保留 TiDB 产品身份和差异提示。官方说明其 JDBC 驱动为 MySQL Connector/J，见 [TiDB FAQ](https://docs.pingcap.com/tidb/stable/tidb-faq/) |
| OceanBase MySQL 模式 | MySQL 兼容协议 | 兼容预设 | 复用 MySQL Connector/J；官方文档确认 MySQL 租户支持标准 MySQL JDBC，见 [OceanBase JDBC 文档](https://en.oceanbase.com/docs/enterprise-oceanbase-database-en-10000000000385185) |
| GaussDB/openGauss 系 | PostgreSQL 兼容协议 | 兼容预设 | 支持 PostgreSQL 驱动或用户选择厂商驱动，先复用 PostgreSQL 元数据和错误分类 |
| 其他 JDBC 数据库 | JDBC 4.x | 实验兼容 | 用户指定驱动 JAR、驱动类和 JDBC URL；提供连接测试、SQL 工作区和标准 `DatabaseMetaData`，不宣称完整方言支持 |

MongoDB、Redis、Neo4j 等非 JDBC 数据库不伪装成 SQL 方言。2.2 为它们预留独立 `DataProvider` 扩展点，但是否加入查询页面取决于关系数据库兼容层完成后的工作量。

### 架构调整

- 以稳定字符串 `providerId` 和 `dialectFamily` 替代在持久化和 UI 中直接依赖枚举序号；例如 TiDB 可拥有独立产品 ID，同时复用 MySQL 方言家族；迁移已有 `SQLITE / MYSQL / MARIADB` 配置时保持兼容；
- `DatabaseProviderDescriptor` 描述显示名、默认端口、连接字段、受控高级选项和驱动状态；
- `JdbcDatabaseProvider` 负责创建连接和设置超时、只读、TLS、禁止多语句及禁止本地文件导入等驱动参数；
- 正式与兼容预设继续使用声明式字段；实验兼容模式允许高级用户输入 JDBC URL、驱动类和本地 JAR 路径，配置中只保存路径和非秘密参数；
- 元数据读取继续优先使用标准 `DatabaseMetaData`，提供者只补充已验证的差异；
- 驱动加载使用每驱动独立的 `URLClassLoader` 和注册句柄，切换、删除或升级时显式释放；同一厂商的多个驱动版本可以并存；
- 练习数据集和权威评测仍固定在 SQLite；外部方言用于探索、项目和连接实验，不要求同一题目在六种方言上产生完全相同结果。

### 兼容优先下的公共执行边界

所有提供者先接入同一条公共 Java 执行链：单语句解析、预览、必要确认、有界执行和审计。完整方言风险规则改为正式支持升级条件，不再阻止数据库以“兼容”或“实验”级别进入 2.2。

兼容接入完成后再集中补齐：

- PostgreSQL 的服务器文件/程序、锁、延迟函数和管理语句；
- SQL Server 的文件导入、外部数据源、过程调用、等待/延迟和管理语句；
- DuckDB 的扩展安装/加载、外部文件和远端资源访问能力；
- 各驱动默认关闭多语句和危险文件导入，服务器连接提供可验证 TLS 预设；
- Oracle、Db2、达梦及兼容协议数据库的产品差异规则；
- 实验 JDBC 连接在 UI 中明确显示其驱动和方言未经过项目验证。

公共执行链不会为了兼容而移除，但2.2不要求先完成每个数据库的专属攻击语法清单、TLS模板和生产级认证方式，后续可根据实际使用频率将兼容项升级为正式支持。

## 下载、许可与恢复规则

1. 每次安装前展示来源、版本、许可、下载/磁盘级别、管理员权限和重启要求，并由用户确认；
2. 只从固定 HTTPS 官方来源下载，校验 SHA-256；对 EXE/MSI 同时验证 Authenticode 发布者；
3. 下载到临时文件，校验后原子切换到 `app-data/components/<id>/<version>`；失败保留旧版本并提供重试；
4. 组件进程输出按大小截断并脱敏，不记录环境变量、凭据、连接字符串或模型提示；
5. 应用只能卸载自己管理的组件，不能删除用户原有 JDK、Python、Ollama、WSL、MSVC 或数据库；
6. 离线时展示可理解的降级结果，不循环弹窗，也不阻止 SQLite、课程地图和本地学习记录。

## 实施顺序

2.2 是小版本，不使用 Alpha/Beta/RC 流程，但按以下内部里程碑串行收敛：

### M1：兼容注册表与现有环境探测

- 建立组件、工具链、AI提供者和数据库提供者注册表；
- 汇总 Ollama/OpenAI-compatible、本机JDK/Python/MSVC/Cygwin/MinGW/LLVM/WSL状态；
- 先完成手动路径选择、版本探测、优先级和失败回退；
- 将现有硬编码分支迁移到注册表，不要求本阶段实现自动下载。

### M2：数据库广覆盖

- 完成 SQLite、DuckDB、H2、MySQL、MariaDB、PostgreSQL、SQL Server 正式提供者；
- 完成 Oracle、Db2、达梦兼容提供者和 TiDB、OceanBase、GaussDB 协议预设；
- 增加实验 JDBC 驱动目录、驱动类/URL 配置、标准元数据和连接测试；
- 连接页面完全由提供者声明字段，不再硬编码 SQLite/服务器二选一。

### M3：受管组件与多工具链运行

- Temurin JDK 多版本下载、`uv` 受管 Python和Ollama安装/模型下载；
- Runner兼容原生Python、Conda、WSL，兼容MSVC、Cygwin、MinGW和LLVM；
- 支持自定义 Ollama 与 OpenAI-compatible 本地服务地址；
- 复用已有环境优先，不覆盖用户 PATH 和全局配置。

### M4：傻瓜化安装与集中加固

- MSVC、WSL/Ubuntu 的官方安装引导、管理员/重启提示和自动复检；
- 安装取消、断点恢复、磁盘不足、离线和损坏组件的可恢复体验；
- 按使用频率为兼容数据库补充专属风险、TLS和错误分类，将成熟项升级为正式支持；
- 更新用户指南、第三方许可、SBOM 和 Windows 打包合同。

## 测试分层

为避免数据库和组件数量线性拖慢日常测试，2.2 不把所有在线安装和真实服务器组合塞进默认 `mvn test`：

| 层级 | 默认执行 | 内容 |
| --- | --- | --- |
| 快速契约测试 | 是 | 用假探测器、假进程、假下载器验证组件状态机；所有数据库提供者共享连接、元数据和错误呈现契约 |
| 内嵌集成测试 | 是 | SQLite、DuckDB、H2 内存/临时文件的真实 JDBC 测试 |
| 外部数据库矩阵 | CI/发布门禁 | 正式数据库独立矩阵；兼容数据库至少验证驱动加载和配置构造，能接入真实服务时再提升门禁 |
| 在线组件与安装器烟测 | 发布门禁 | 固定组件目录、校验和、取消/恢复、app-image 中的组件中心入口；不污染开发机全局环境 |

共享契约用于减少重复测试代码。专属方言测试随支持级别增加：实验兼容不要求复制正式数据库的完整测试矩阵。

## 完成标准

- 全新 Windows 用户无需额外组件即可打开应用并完成 SQLite、DuckDB 和基础课程活动；
- Java 或 Python 活动缺少工具链时，可在应用内一次确认后准备受管环境并自动复检；
- Ollama 缺失、服务未启动、模型未下载三种状态能被准确区分并给出对应操作；
- MSVC/WSL 的系统级安装明确提示管理员权限和重启，不静默改变系统；
- 已有 JDK 17/21/25、CPython/Conda/WSL Python、MSVC、Cygwin、MinGW、LLVM、Ollama 和兼容 AI 端点能被优先发现，且可手动指定路径；
- 正式数据库均能创建配置、测试连接、读取元数据并进入统一执行链；
- Oracle、Db2、达梦和三类兼容协议预设至少完成连接测试、标准元数据和SQL工作区；
- 用户可为其他 JDBC 4.x 数据库配置本地驱动、驱动类和URL，并明确看到“实验兼容”标记；
- 旧连接配置无损迁移，密码仍不落盘；
- 断网、磁盘不足、下载损坏、用户取消和组件重启后均有可恢复状态；
- 新增第三方二进制和驱动进入许可清单、SBOM、校验和及敏感内容扫描门禁。

## 不纳入 2.2

- 把 Ollama 模型、数据库服务器、MSVC 或完整 WSL 发行版塞入主安装包；
- 静默提权、自动重启、无确认执行包管理器或远端脚本；
- Docker Desktop/Kubernetes 作为学习前置条件；
- 为所有实验 JDBC 驱动承诺完整方言、迁移、存储过程和生产级认证兼容；
- 在关系数据库注册表尚未稳定前同时实现 MongoDB、Redis、Neo4j 的完整查询工作区；
- 改变 SQLite 权威练习评测和本地离线学习闭环。
