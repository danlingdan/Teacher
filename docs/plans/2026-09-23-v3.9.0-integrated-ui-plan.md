## 1. 目标、边界与成功定义

3.9.0 的主线是让学生和教师在**同一导航、同一对象上下文、同一状态语言**下完成任务，
同时提升常用页面在桌面窗口中的可读性。先修断开的路径，再统一状态和布局，最后做视觉精修。
保留 Tauri/React 桌面形态、Java sidecar 权威业务逻辑、离线优先和本地免登录主路径。

完成标准不是“所有页面换皮”：指定任务能从入口直达对象、操作后能找到结果与下一步；
960×640 到常见桌面尺寸及系统缩放下关键操作可达；学生/教师/未登录状态准确，错误可恢复；
浅色/深色/高对比/紧凑密度和中英文模式不出现关键流程回归。

本版不因 UI 改造变更 SQL/AI 安全策略、判分、学习权威状态、云端权限或同步数据边界；
不引入第二套桌面 UI、全新组件库、用户行为遥测或全站主题重做。若调研证据显示需要服务端
对象定位接口，须单独设计兼容、鉴权、测试和部署门禁，不能把 URL 参数当授权。

## 3. 实施顺序与决策门

1. **G0 证据冻结**：完成 INT-0，核对 3.8.0 留项、用户反馈、窗口截图。给每个问题标严重度、频次、
   角色和对应任务。基线未形成前不决定重排全部七个主入口。
2. **G1 交互方案**：输出主导航图、学生/教师两条任务流、对象路由参数表和主要页面线框；
   对“保持七入口 + 加任务跳转”与“少量分组重命名”做任务测试。产品词汇、URL 兼容、登录返回
   和权限边界在此冻结。
3. **G2 纵向实施**：先 INT-1，再 INT-2/INT-3；每条切片含页面、路由、组件、聚焦测试和文档。
   Java/服务端变更只有在现有端点不能定位对象时才加入，须保持 additive IPC v1 与云端兼容。
4. **G3 视觉与无障碍**：VIS-1/VIS-2/ACC-1 按工作区分批；VIS-3 依据 G0 决定是否纳入。
   每批保存同夹具、同窗口、同主题的前后截图，避免“改好看了”无法验证。
5. **G4 交付审查**：逐项核对任务矩阵、回归、性能与打包态 E2E，更新用户手册、能力总览、
   验收记录与发布说明。实际版本范围若超出单版本容量，先保 P0 任务闭环，P2 回积压清单。

## 4. 验收矩阵与门槛

| 维度 | 最低门槛与方法 |
| --- | --- |
| 任务闭环 | INT-0 定义的学生、教师、离线/未登录及 SQL 五组脚本在 3.9.0 打包态可重复完成；每个对象深链有正常、失效、无权限、登录后返回四类测试。完成时间与误入次数相对 G0 基线报告，**不预设未经测量的改进百分比**。 |
| 状态和数据 | 加载、空、筛选无结果、失败、离线、权限不足逐项核对；跨入口同步偏好一致；账号切换、班级切换、浏览器后退不显示前一主体的私有数据。 |
| 桌面布局 | 按 VIS-1 尺寸与缩放矩阵截图并人工检查导航、编辑器、表格、长文案、对话框及焦点；主题至少亮/暗/高对比，密度至少默认/紧凑。 |
| 可访问性 | 自动 axe 与组件测试加手动键盘走查；对照 WCAG 2.2 适用 AA 准则核对文本对比、重排、焦点和目标尺寸，并记录例外及人工判断。 |
| 质量与安全 | 聚焦 Vitest、`npm --prefix ui-web test`、`npm --prefix ui-web run build`、打包态桌面 E2E；涉及 Java/IPC/权限/SQL 时按仓库验证梯度执行 Maven 与合同测试，跨模块或安全改动跑全量 `mvn test`。不得以 UI 测试替代 Java 权限与 SQL 执行门禁。 |
| 发布证据 | `git diff --check`、文档链接检查、无生成物/秘密入 Git；若改安装器或新 IPC，按打包及发布门禁验证。发布状态另在验收/发布文档记录。 |

## 5. 风险和取舍

- **“全面”导致范围扩散**：以任务和状态清单覆盖整个界面，以纵向切片改动；未测出问题的页面保留。
- **路由参数成为权限漏洞**：参数只负责定位；Java 服务、云端服务和现有 RoleGuard 继续各自执行检查。
- **视觉重构带来行为回归**：CSS 归位与导航行为分批，截图和 E2E 使用相同夹具；先修遮挡，后做装饰。
- **全量英文改造吞没版本**：关键路径先落显式词条，其他残留登记，不把局部覆盖宣传为完整双语。
- **新 UI 依赖云端**：离线课程、练习、数据工作台仍可用；云端不可用时给出可执行的本地路径。

计划制定轮只交付了调研与计划文档；后续实施结果在验收记录中逐批记录。
