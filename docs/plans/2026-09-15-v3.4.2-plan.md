### G. 发布工作流提效（LEG-15）——用户同日追加

- **LEG-15（P2）本地已验证时 CI 跳过测试、直接构建**。现状：`.github/workflows/release.yml` 由 tag 推送触发（:3-6），每次发布全量重跑 `mvn -B test`（:66-73，含 WSL 探测降级 -Pfast :48-64）与 `npm test`（:95）——而本仓库为单开发者流程，发布前提本就是本地全量测试通过，CI 重跑纯属重复；且 GitHub 托管 runner 无 WSL 时 Java 测试降级 `-Pfast`，本就弱于本地全量。动作：
  - **验证凭据文件**：新增小脚本（`packaging/write-verification-receipt.ps1`）在本地测试通过后生成 `verification-receipt.json`（内容：git SHA、`mvn test` 摘要（用例数/失败 0）、`npm test` 摘要、时间戳、JDK/Node 版本），随发布提交入库并打 tag——即发布流程顺序调整为：本地全量测试 → 生成凭据 → 提交 → 打 tag → 推送。
  - **CI 条件跳过**：release.yml 在测试步骤前读取凭据——**存在且 `commit` == `GITHUB_SHA` 且两项摘要均为成功时跳过测试步骤**（Java 侧跳过 `mvn test`，npm 侧跳过 `npm test` 但保留 `npm ci` + `npm audit`）；凭据缺失、SHA 不符或有失败记录时**一律回退现状全量测试**（fail-safe：宁可慢不可漏）。
  - **保留不变**：编译打包（package-v3.ps1 内部构建链）、SBOM、签名、无控制台校验、合同校验全部照旧——只跳过测试执行，不跳过构建与校验。
  - **可审计**：凭据文件随 Release 资产上传，发布说明状态行标注"测试执行：本地全量（CI 凭据跳过）"或"CI 全量"。
  - **制度同步**：`sqlteacher-windows-release` SKILL.md 的发布门禁清单明确——CI 跳过场景下**本地全量 `mvn test` + `npm test` 是不可省略的唯一执行处**；`docs/guide/06-testing-packaging-acceptance.md` 回写新流程。
  - 测试/验证：分支上用等价触发各演练一次（凭据齐全→跳过路径、删除凭据→回退路径）；正式发布首跑核对 Release 资产含凭据且说明行正确。
