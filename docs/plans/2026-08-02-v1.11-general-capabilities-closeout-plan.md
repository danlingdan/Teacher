# SQLTeacher v1.11 通用能力收尾计划

> - 制定日期：2026-08-02
> - 发布基线：`v1.10.1` / `672f836`，当前 `main` 为 `1.10.1`
> - 目标版本：`v1.11.0`
> - 实施方式：单人、多阶段串行交付
> - 核心方向：收尾 v1.10 明确转入 v1.10.x 的 12 项通用能力，补齐平台通道与服务依赖后形成正式入口；不扩展 SQL 教学专业功能

## 1. 规划结论

v1.10.0 建立并交付了桌面软件的通用能力地基：可信更新、问题反馈、诊断包、生命周期、设置治理、网络/代理、后台任务、通知中心、无障碍、隐私与供应链透明。v1.10 实施记录（`docs/stage7/2026-08-02-v110-general-software-implementation.md`）明确将 12 项能力转入 v1.10.x，原因集中在“依赖额外平台通道或服务，缺少完整验证前不应进入正式入口”。

v1.11.0 是这条通用能力线的收尾版本，把 v1.10.x 转入项逐项补齐、验证并形成正式入口：

```text
升级体验
→ 断点续传（HTTP Range）
→ 受控更新镜像
→ 分阶段更新发布

反馈与数据
→ 截图附件（白名单格式 + 元数据清理）
→ 反馈撤回与本人数据导出

账号生命周期
→ 可信邮箱密码重置
→ 活跃会话管理
→ 云端账号数据导出与注销

桌面体验收尾
→ 命令面板
→ 完整英文界面
→ Windows 原生通知（显式启用）
→ 按流量计费 / 低电量任务策略
→ 安装修复入口
```

配套的 Cloud 服务与发布基础设施同步升级：Cloud API 能力协商升到 `1.11`，新增反馈撤回/导出、会话、账号、密码重置、分阶段发布与截图附件端点；镜像站与邮件通道纳入部署与运维边界。

v1.11.0 的成功不完全由“新功能数量”决定，而是由“12 项转入项全部具备可验证的正式入口、无未验证的平台/服务依赖、v1.10 已有能力无回归”决定。

## 4. 产品与安全原则

延续 v1.10 的既定原则，v1.11.0 不放松以下约束：

- 不静默下载、不静默安装、不后台下载可执行文件、不远程执行命令；所有下载产物仍须通过签名与 SHA-256 校验。
- 镜像不能修改清单内容、不能引入新的信任根；主源与镜像使用同一签名信封与哈希。
- 截图附件必须由用户主动选择并预览确认；清除无关元数据；不自动采集屏幕、不把剪贴板或全屏内容隐式上传。
- 反馈撤回、账号导出与注销都以“本人可验证身份/凭据”为前提；不暴露其他用户内容，不做公开全文列表。
- 密码重置依赖可信邮件通道；邮件不含明文密码，Token 一次性且限时；错误提示统一以“若邮箱存在将收到邮件”规避枚举。
- 注销前必须冷静确认并重新认证，提供取消窗口与保留例外说明；导出包只含本人数据。
- 原生通知默认关闭，正文只使用白名单短语，不携带业务正文；点击只导航固定页面。
- 分阶段发布不改变产物签名与哈希；批次按匿名随机桶划分，不以硬件、网络地址或学习行为画像。
- 完整英文不改变安全规则与 SQL 安全文案的语义；缺失键在测试中失败，不在运行时混杂语言。
- 所有新增 Cloud 端点保持 64 KiB 正文上限、限流、幂等与保留清理；诊断、日志与反馈正文继续脱敏。

## 6. 详细设计

### 6.1 V111-01 下载断点续传（HTTP Range）

目标：弱网/中断场景下更新下载只重传剩余字节。

- 客户端下载任务持久化记录：目标 URL、`ETag`/`Last-Modified`、文件大小、已下载字节、临时文件路径（`app-data/updates`）。
- 恢复时先 `HEAD` 或带 `Range` 的请求确认服务端仍返回同一 ETag 与大小；不一致则丢弃临时文件完整重下。
- 服务端不支持 Range（返回 200 而非 206）时安全完整重下，不拼接损坏文件。
- 下载完成后整体 SHA-256 与清单校验保持 v1.10 语义，任何一项失败不得进入安装状态。
- 中断/失败自动清理或隔离临时文件；低磁盘保护沿用 v1.10 存储治理。

验收：模拟 50% 中断后续传仅传剩余字节；ETag 变化/文件被篡改时重下；不支持 Range 的服务器可正确重下；最终 SHA-256 通过。

### 6.2 V111-02 截图附件

目标：用户用一张截图说明界面问题，隐私可控。

- 仅“用户主动选择文件”（`FileChooser` 或从剪贴板选择图片），绝不自动抓屏。
- 限制 PNG/JPEG，解码后校验真实图像格式与尺寸，大小默认 ≤ 2 MiB。
- 提交前预览并确认；服务端按白名单 MIME 与大小上限接收，按二进制存储，保留策略与反馈一致（默认 180 天、最长 365 天）。
- 发送前清除 EXIF/GPS/设备等无关元数据；不允许任意附件类型与超大图片。
- 截图可选纳入诊断包（白名单目录），不自动上传。

验收：带 GPS 元数据的样例图片上传后被清理；非白名单格式/超限被拒；未确认不上传；自动抓屏在测试中被禁止。

### 6.3 V111-03 受控更新镜像

目标：官方域不可达时仍有可信下载通道。

- 镜像清单仍是主源签名的信封，客户端不信任镜像提供的清单，只允许镜像提供与主源一致的安装包字节。
- 镜像域名白名单化（默认关闭或仅在连续失败后启用），镜像地址可审计。
- 镜像产物校验：下载后 SHA-256 与主源清单一致；不一致即失败并回退官方域。
- 便携 ZIP 同样适用镜像；镜像不能修改版本、发布时间或说明链接。

验收：主源不可达时镜像可用；镜像被篡改（字节级）时校验失败；镜像配置无白名单外域名；切换行为有审计记录。

### 6.4 V111-04 命令面板

目标：键盘优先的快速导航。

- 全局快捷键（如 `Ctrl+K`）打开面板；搜索页面名（中文+英文别名）与安全命令。
- 安全命令分类：导航类直接执行；危险动作（重置、清理、退出、注销）只导航到原页面并沿用原确认流程。
- 面板不显示敏感数据（账号、SQL 正文、反馈内容）；快捷键可自定义且避免与编辑器冲突（沿用 v1.10 快捷键规范）。

验收：键盘全程可达；中文/英文别名可命中；危险命令无绕过确认的直达执行路径。

### 6.5 V111-05 完整英文界面

目标：正式交付英文界面，与简体中文并行。

- 第一阶段：盘点全部硬编码中文（19 个 FXML + 19 个控制器），建立键清单，分批迁移到 `messages_zh_CN.properties`。
- 第二阶段：提供 `messages_en.properties` 完整翻译；新增“ResourceBundle 键完整性测试”与“Locale 切换无混杂测试”。
- 语言跟随系统 Locale，可在设置页手动覆盖；日期/数字/大小/版本按 Locale 稳定格式化（复用 v1.10 格式基础）。
- 教学相关文案（SQL 风险提示、判题反馈）翻译必须保持语义一致，不得弱化安全提示。

验收：键完整性测试通过；英文环境下无中文残留、中文环境下无英文残留（固定抽样断言）；FXML 无硬编码文案新增（测试门禁）。

### 6.6 V111-06 反馈撤回与数据导出

目标：用户对本人反馈有撤回与导出权。

- 状态机：`open → withdrawn`（不可恢复）；仅未处理反馈可撤回；已进入处理中的反馈不可撤回但可导出元数据。
- 导出：按查询 Token/登录身份验证后，导出本人反馈元数据（编号、类型、提交时间、状态）；不含内部审计、错误详情扩展或其他用户内容。
- 服务端：撤回幂等（重复撤回返回成功或明确已撤回）；导出与撤回都有限流与鉴权；保留策略不变。
- 撤回与导出操作记入 v1.10 本地操作历史（白名单对象类别）。

验收：撤回他人反馈失败；重复撤回幂等；导出包仅含本人记录；未登录访客只能撤回/导出自己的查询 Token 关联记录。

### 6.7 V111-07 可信邮箱密码重置

目标：忘记密码可自助重置，且流程可信。

- 前置：账号资料支持绑定邮箱；绑定邮箱需验证（一次性验证邮件）。
- 流程：请求重置 → 服务端生成一次性、限时（默认 30 分钟）、限次 Token → 邮件发送 → 客户端校验 Token 后允许设置新密码 → 撤销全部会话并使旧 Token 失效。
- 防枚举：无论邮箱是否存在统一返回“若邮箱存在将收到邮件”；Token 尝试次数受限。
- 邮件通道：走生产邮件服务（SPF/DKIM 配置），正文不含明文密码、不含 Token 之外的账号信息；退信与发送失败有日志与限流。
- 无邮件环境：提供 P1 的本地一次性重置码替代通道（V111-19），与邮件通道互斥选择。

验收：Token 过期/重复使用失败；重置后旧密码无法登录且全部会话撤销；枚举探测无法区分邮箱是否存在；邮件正文无明文密码。

### 6.8 V111-08 活跃会话管理

目标：用户可查看并撤销其他会话。

- 服务端维护会话表：会话 ID、用户、设备摘要、来源摘要、创建/最后活动时间、撤销标记。
- 用户查看活跃会话列表（脱敏设备/来源，不显示完整 IP 或地理位置细节）；可按会话撤销。
- 撤销目标会话后其访问令牌立即失效；当前会话始终受保护，不被误撤销。
- 密码重置、改密与注销时撤销全部会话（与 v1.10 行为一致）。

验收：撤销后目标会话请求被拒；当前会话不受影响；会话列表脱敏；撤销操作幂等。

### 6.9 V111-09 云端账号数据导出与注销

目标：个人数据控制闭环。

- 导出：生成本人云端数据包（账号资料、反馈、任务/提交等白名单数据，结构化格式），限时下载链接；导出请求限流并记录审计。
- 注销：冷静确认（明确影响预览）→ 重新认证 → 异步处理 → 取消窗口（默认 7 天）→ 保留例外（法律/合规要求，默认 30 天）→ 注销完成后登录失败。
- 注销不删除本地访客数据（延续 v1.10 边界）；云端会话全部撤销；账号数据按保留策略清理。
- 导出与注销均只允许本人操作，防枚举与暴力尝试。

验收：导出包仅含本人数据且格式可读；注销有冷静期且窗口内可取消；注销后登录失败；保留例外按配置执行；本地数据不受影响。

### 6.10 V111-10 分阶段更新发布

目标：稳定版可分批开放并随时暂停。

- 清单扩展：稳定通道附加 `rollout` 信息（阶段百分比、暂停开关、发布时间）；不改变现有签名信封与哈希字段。
- 客户端按匿名随机桶（基于固定盐与版本号、平台做确定性散列，不含身份与硬件信息）决定是否可见；手动检查仍可看到正式发布状态并引导到官方下载页。
- 同一签名产物对所有用户一致；分阶段只影响“何时可见”，不影响“看到什么”。
- 运维：发布工具支持按百分比推进与紧急暂停；暂停后未可见批次不再下发。

验收：随机桶逻辑确定性可测（相同输入相同输出）；暂停后新批次不可见；手动检查可见正式发布；不收集个人化画像数据。

### 6.11 V111-11 按流量/电量任务策略

目标：避免在按流量计费网络或低电量时产生大流量与耗电。

- 网络：检测当前网络是否为按流量计费（Windows `NetworkCost` 或配置项），用户可手动标记；按流量计费时暂停更新下载、知识索引、备份等非关键任务，仅允许用户主动任务与安全检查。
- 电量：低电量（如 ≤ 20%）时暂停非关键任务并提示；用户主动任务可明确覆盖。
- 暂停/恢复进入任务中心快照，原因码可读；策略设置入设置治理与导入导出白名单。

验收：按流量计费/低电量下非关键任务被暂停并给出原因；用户主动任务可覆盖；恢复后任务从暂停点继续或明确失败重试。

### 6.12 V111-12 Windows 原生通知

目标：有限系统通知，默认关闭。

- 用户显式启用后，在更新可用、任务完成、备份失败等白名单事件上发送有限系统通知。
- 正文只使用白名单短语（如“更新可用”“备份完成”），不包含反馈、SQL、Prompt、学生信息或错误正文。
- 点击通知只导航到固定页面（更新与支持页、任务中心）；通知默认关闭；沿用 v1.10 通知偏好与免打扰。
- 实现：优先 JavaFX 生态可用方案（`java.awt.SystemTray` 冒泡或等效原生通道）；不引入大型原生依赖；失败时静默降级到应用内通知中心。

验收：默认关闭；启用后才通知；正文白名单短语（测试断言不含敏感类别）；点击导航固定页面；无托盘常驻与开机启动。

### 6.13 V111-13 安装修复入口

目标：程序文件损坏可引导修复。

- 启动/运行期检测正式程序关键文件缺失或与安装清单哈希不符。
- 检测到异常时提示用户引导重新运行安装器（修复/重装），下载仍走受控更新链路，不从网络单独下载任意 DLL/JAR。
- 修复过程不修改 `app-data` 用户数据；修复后首次启动走 v1.10 升级确认流程。
- 便携版给出手动替换程序目录的明确说明。

验收：关键文件缺失/篡改可检出并引导重装；修复不触碰用户数据；无任意文件网络下载。

### 6.14 V111-14 Cloud API 1.11 与后端

- 能力协商升到 `1.11`，最低客户端保持 `1.9.0`；新增能力位：`feedbackWithdrawal`、`feedbackExport`、`sessions`、`accountExport`、`accountDeletion`、`passwordReset`、`rollout`、`screenshotAttachment`。
- 新端点统一鉴权/限流/幂等/正文 64 KiB 上限/保留清理；错误码接入既有错误模型。
- 反馈截图存储与清理：按反馈保留策略过期删除；诊断键拒绝规则扩展到附件元数据。
- 密码重置 Token、会话表、注销任务、导出任务均有状态与审计，维护查询只读。

### 6.15 V111-15 发布与运维门禁

- 镜像站：部署与官方产物一致的文件与清单同步脚本；镜像仅提供主源签名信封与相同 SHA-256 产物。
- 邮件通道：配置生产 SMTP（SPF/DKIM），建立发送限流、退信日志与失败告警；邮箱验证与重置邮件走同一通道。
- 分阶段发布工具：`rollout` 清单生成、百分比推进与紧急暂停脚本；发布值守手册更新。
- 密钥轮换演练：更新签名密钥轮换全流程演练一次（生成、内置公钥切换、旧钥兼容窗口）。
- 升级演练：真实 Windows 上验证 v1.10.1 → v1.11.0 原位升级保留 `app-data`；回退与重装路径。

## 7. 建议代码边界

- `application.update`：断点续传任务模型、镜像策略、`rollout` 客户端逻辑；`infrastructure.update`：Range 下载器、镜像客户端、恢复存储。
- `application.support`：截图附件校验/元数据清理、反馈撤回/导出用例；`infrastructure.support`：附件上传客户端、EXIF 清理实现。
- `application.account`（新增或并入现有账号边界）：邮箱绑定、密码重置、会话管理、账号导出/注销用例；`infrastructure.cloud`：对应 Cloud 客户端；服务端 `server/` 增补 `V111` Store 与端点。
- `application.system`：按流量/电量策略、原生通知开关、安装修复检测；`desktop`：命令面板、i18n 迁移、设置页入口。
- 保持依赖方向：`desktop → application → domain`；`infrastructure → application/domain`；业务逻辑不进控制器。

- 升级路径：v1.10.1 正式安装版原位升级至 v1.11.0 保留 `app-data`；回退与重装路径经过真实 Windows 验证。

## 11. 风险与裁剪顺序

| 风险 | 缓解 |
|---|---|
| 邮件通道是最大外部依赖 | 阶段 1 先确认 SMTP 落地；失败则启用 P1 本地重置码替代通道（V111-19），邮件通道保留接口。 |
| 完整英文工作量大（19 FXML + 19 控制器） | 阶段 1 冻结键清单分批迁移；界面与主流程文案优先，帮助文档可 P1；键完整性测试持续防回退。 |
| 原生通知受平台限制 | 优先 `java.awt.SystemTray` 冒泡或等效方案，不引入大型原生依赖；失败静默降级应用内通知。 |
| 分阶段发布影响可见性判断 | 客户端随机桶确定性 + 手动检查不受阶段限制；首发仍全量，工具就绪后再启用分批。 |
| 镜像引入额外信任面 | 镜像不提供清单、只提供与主源一致的字节；篡改即校验失败并回退官方域。 |
| 账号注销/导出数据范围争议 | 白名单数据包 + 影响预览 + 冷静期与取消窗口；保留例外默认冻结。 |

裁剪顺序（时间不足时按序放弃，先保证更新信任、隐私与账号安全）：

1. 保留：断点续传（V111-01）、可信密码重置（V111-07）、活跃会话管理（V111-08）、完整英文（V111-05）、Cloud 1.11（V111-14）。
2. 中等：截图附件（V111-02）、反馈撤回/导出（V111-06）、账号导出/注销（V111-09）、安装修复（V111-13）。
3. 最后：命令面板（V111-04）、原生通知（V111-12）、按流量/电量策略（V111-11）、受控镜像（V111-03）、分阶段发布（V111-10）——其中 V111-03/V111-10 可先只交付“能力就绪 + 工具”，首发仍全量直连官方域。

裁剪任何 P0 由项目负责人确认，并记录原因与替代方案。

## 12. 完成定义

v1.11.0 只有同时满足以下条件才可宣布完成：

- v1.10.x 全部转入项逐项有“纳入/裁剪/转 P1”的最终结论，纳入项均以正式入口交付并通过验收。
- 更新下载支持断点续传且最终 SHA-256 校验不变；官方域不可达时受控镜像可用，镜像篡改不能进入安装状态。
- 反馈支持预览确认的截图附件且元数据被清理；未处理反馈可撤回、本人反馈元数据可导出，越权与幂等回归通过。
- 账号绑定邮箱后可经可信邮件通道重置密码；Token 一次性限时，重置后旧密码失效并撤销全部会话；无账号枚举。
- 用户可查看并撤销活跃会话，当前会话不受影响；云端数据可导出且账号注销含冷静期、取消窗口与保留例外。
- 命令面板键盘可达且危险动作不绕过确认；英文界面键完整性测试通过且运行时无中英混杂。
- 原生通知默认关闭、显式启用后正文为白名单短语且点击只导航固定页面；按流量计费/低电量策略可暂停非关键任务且用户主动任务可覆盖。
- 正式程序文件缺失或哈希异常可检出并引导修复，修复不触碰 `app-data`，不从网络下载任意文件。
- Cloud API 1.11 新端点全部有鉴权、限流、幂等与保留边界；最低客户端与旧协议兼容；错误码与既有错误中心一致。
- v1.10.0/v1.10.1 的更新信任、反馈隐私、诊断边界、SQL 安全、账号隔离与性能门禁全部无回归。
- 全量测试、EXE/ZIP、SHA-256、签名清单、SBOM、镜像同步、邮件通道、分阶段工具、升级/回退/重装路径与公开 Release 全部通过。
- `main`、`v1.11.0` 标签、Maven 版本、更新清单和公开 Release 指向同一已验证提交与产物。
