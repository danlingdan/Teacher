- 制定日期：2026-08-09

## 结论摘要

整体代码纪律性极高：SQL 执行收敛到唯一强制入口、AI 输出永不触碰 `Connection`/结果集、凭据走 DPAPI 加密 + char[] 生命周期、认证与迁移实现教科书级。未发现"模型/云端拿到 JDBC Connection""密码写入日志""UI 直连数据库"等确定高危问题。

但存在 **5 个高危项** 需要优先处理：其中 2 个是真实安全边界问题（练习包 `setupSql` 绕过风险分析、MySQL 注释结构绕过多语句检测），2 个是确定性功能 bug（带截图反馈必 413、加载遮罩计数残留），1 个是安全策略默认值 fail-open。其余为纵深防御、FX 线程阻塞与健壮性短板。

## 高危

### S1. 练习数据集 `setupSql` 绕过全部风险分析直接执行（安全）

- 位置：
  - `src/main/java/com/sqlteacher/infrastructure/database/JdbcExercisePracticeService.java:420-423`（`initializeDataset` 直接 `statement.execute(sql)` 执行拆分后的每条语句）
  - `src/main/java/com/sqlteacher/infrastructure/database/DeterministicSqlExerciseEvaluationService.java:158-161`（评测时同样直接执行）
  - 不可信入口：`JdbcExerciseManagementService.java:203-244` → `ExercisePackageCodec.java:36-62`，导入的 JSON 练习包 `setupSql` 字段无任何内容/语句类型校验
- 问题：`setupSql` 既不经过 `DefaultSqlRiskAnalysisService`，也没有语句白名单。SQLite 下可包含 `ATTACH DATABASE '<app.db 路径>' AS x`、`VACUUM INTO '<任意路径>'`、`PRAGMA query_only=off` 等。
- 后果：恶意/被篡改的练习包被导入后，可把 `app.db`（含其他学生提交的 SQL 全文、连接 profile、知识库）的敏感表复制进会话库，学生在练习页提交 `SELECT * FROM x.attempts` 即可读出应用数据；也可通过 `VACUUM INTO` 向任意磁盘路径写 SQLite 文件。
- 修复方向：练习包导入时对每条 `setupSql` 语句做 Java 侧白名单解析（仅允许 `CREATE TABLE`/`INSERT`），拒绝 `ATTACH`/`VACUUM`/`PRAGMA`/`ALTER`/`DROP`/`DELETE`/`UPDATE`；会话初始化连接设置 `PRAGMA trusted_schema=off`，会话目录外路径一律拒绝。

### S2. MySQL 注释结构可绕过多语句/危险语句文本检测，Generic JDBC 无驱动层兜底（安全）

- 位置：
  - `src/main/java/com/sqlteacher/infrastructure/database/DefaultSqlRiskAnalysisService.java:190-243`（`hasMultipleStatements` 状态机把 `/*...*/` 整体当注释跳过）
  - `DefaultSqlRiskAnalysisService.java:269-337`（`removeComments` 剥离 `/*!...*/` 版本化注释）
  - `DefaultSqlRiskAnalysisService.java:178-184`（MySQL 危险函数/文件输出正则直接匹配 token，可用注释拆词绕过）
  - 兜底缺口：`JdbcConnectionFactory.java:120` 仅对 MySQL/MariaDB 显式 `setAllowMultiQueries(false)`；`DynamicJdbcConnection.java:35`（Generic）与 `openServerDatabase`（SQL Server 等，`JdbcConnectionFactory.java:178-221`）无法在驱动层禁用多语句
- 问题：MySQL 版本化注释 `/*! ... */` 会被 MySQL 解析器展开执行，但风险分析器将其当注释删除。
- 后果：`SELECT 1 /*!; DROP DATABASE x*/` 被分析为单条 SELECT（LOW、可执行、无需确认），MySQL 展开后实为两条语句；`INTO/**/OUTFILE`、`SLEEP/**/(` 可绕过 `MYSQL_FILE_OUTPUT`/`MYSQL_DANGEROUS_FUNCTION` 检测。官方驱动路径被 `allowMultiQueries=false` 二次拦截，但 Generic 路径没有第二道防线。
- 修复方向：风险分析前先做"注释规范化"（所有注释替换为空格后重新 tokenize，再做多语句与危险关键词匹配）；对 Generic JDBC 目标，执行前强制增加一次"去除注释后文本"级别的复检，或要求 Generic 连接只能以只读方式打开。

### S3. 带截图的问题反馈必然被 413 拒绝（功能损坏）

- 位置：
  - `src/main/java/com/sqlteacher/server/SqlTeacherCloudServer.java:804,1027-1031`：`support` handler 用 `objectRequest`，其底层 `requestBytes()` 用 `readNBytes(64*1024+1)`，超过 64 KiB 即抛 `PayloadTooLargeException` → HTTP 413
  - `src/main/java/com/sqlteacher/server/V110SupportStore.java:179`：`parseScreenshot` 允许 2 MiB 截图（base64 后约 2.7 MB 文本）
  - 客户端 `src/main/java/com/sqlteacher/infrastructure/support/HttpProblemReportService.java:43-49`：把截图 base64 直接放进 JSON 请求体
- 问题：请求体上限（64 KiB）与截图业务上限（2 MiB）矛盾。
- 后果：任何带截图的问题反馈在客户端打包阶段就注定被服务端 413 拒绝，属于稳定复现的功能损坏；2 MiB 上限形同虚设（永远达不到）。
- 修复方向：将 `support/reports` 请求体上限提升到与截图业务上限匹配（≥3 MiB），或把截图改为独立的分块上传端点并在服务端分别限流。

### S4. 关闭学习项后全局加载遮罩计数残留，UI 假死最长 60 秒（功能 bug）

- 位置：`src/main/java/com/sqlteacher/desktop/controller/HomeController.java:140-151`（`onDismissAction`）与 `:154-180`（`refreshDiagnosis`）
- 问题：`onDismissAction` 成功分支 `Platform.runLater(this::refreshDiagnosis)`，但未先 `GlobalLoading.hide()`；而 `refreshDiagnosis()` 第一行是 `GlobalLoading.show(...)`。计数序列为 show(1) → show(2) → 刷新完成后 hide(1)，`GlobalLoading`（`src/main/java/com/sqlteacher/desktop/GlobalLoading.java:55`，`AtomicInteger` 计数器）最终残留 1。
- 后果：用户每次点击"忽略"学习项后遮罩保持显示并拦截全部鼠标交互，直到 `GlobalLoading` 内置 60 秒超时 `forceHide` 才消失。
- 修复方向：成功分支改为先 `GlobalLoading.hide()` 再刷新（与错误分支一致），或让 `refreshDiagnosis` 复用已有遮罩计数。

### S5. SQL 安全设置默认 fail-open（策略）

- 位置：`src/main/java/com/sqlteacher/infrastructure/config/FileSqlSafetyModeService.java:71,79-81`
- 问题：`load()` 在配置文件不存在（:71）或读取失败（:79-81）时返回 `true`，即 `unrestrictedModeEnabled` 默认开启。
- 后果：新安装用户的 SQL 执行默认不受安全限制，与"教学安全优先"定位相悖；文件损坏时静默放宽限制（fail-open）。
- 修复方向：默认返回 `false`（受限模式），读取失败时以 warn + 受限模式降级（fail-closed）。

## 确认安全的方向（未发现问题）

- **SQL 注入**：server 与 infrastructure 的所有查询均使用 PreparedStatement；唯一字符串拼接（`SqlTeacherCloudServer.java:1779` 的 `Instant.now()`、`adminAudit` 的 `where`、`V14CloudStore` 的 `placeholders`）均来自程序生成值或受 `[A-Z0-9_]{3,80}` 白名单校验的枚举，无用户可控拼接。
- **AI 边界**：模型/AI 不执行 SQL、不接触 `Connection`/结果集；AI 输出仅作草稿，执行前有强制风险分析 + 确认；网络 AI 端点强制 HTTPS 且禁用重定向。
- **凭据**：DPAPI 加密存储 + char[] 生命周期管理；grep 未发现把 password/token/secret 写入日志的调用；server 异常响应均为固定文案。
- **命令注入**：runner 三个文件的 `ProcessBuilder` 均以 List 传参（无 shell 解释）；WSL 沙箱有 output 限制、cgroup 隔离、fail-closed 能力探测。
- **更新链路**：`SecureUpdateService` 对 manifest 做 Ed25519 签名校验、下载 host 白名单 + HTTPS + 每跳重定向校验 + SHA-256 + 大小校验 + 安装前复验。
- **SSRF**：`JdkSafeWebContentFetcher` 拒绝 localhost/.local，DNS 解析后检查私网地址。
- **目录穿越**：`FileGeneralSoftwareService.removeTree`、`FileDiagnosticBundleService.export`、runner 的 workspace 均有 `startsWith(root)` 守卫。
- **认证与迁移**：PBKDF2 31 万次迭代、token 只存 SHA-256、刷新轮换、admin 最后一人保护、SQLite 迁移（`addColumnIfMissing` + schema 版本号 + 向前不兼容检查）。
- **分层**：domain/application 无 desktop/infrastructure/JavaFX 反向依赖，无 `return null` 集合。
