# SQLTeacher v1.10 通用软件能力与用户支持计划

> - 制定日期：2026-08-02
> - 发布基线：`v1.9.0` / `c705fb3`，当前 `main` 为 `1.9.0` / `6b4ec55`
> - 目标版本：`v1.10.0`
> - 实施方式：单人、八阶段串行交付
> - 核心方向：安装更新、反馈诊断、应用生命周期、账号与个人数据、设置与数据治理、网络与任务、帮助与可访问性、隐私安全与供应链

## 1. 规划结论

v1.10.0 不继续扩展 SQL 教学、课程知识、RAG 或学习诊断能力，而是一次性系统补齐一款可长期安装、升级、运行、排障和维护的 Windows 桌面软件应具备的通用能力。当前项目已经有稳定的 Maven 版本号、Windows EXE/ZIP、固定升级 UUID、SHA-256 清单、GitHub Release 和 HTTPS Cloud API，但安装后的版本生命周期、应用内更新、问题反馈、崩溃恢复、配置治理、网络诊断、后台任务、帮助文档、可访问性和供应链透明度仍不完整。

v1.10.0 定位为“桌面软件基础能力完善版本”。可信更新与用户支持仍是主闭环，但同时覆盖首次启动、正常运行、异常恢复、配置迁移、空间治理、帮助与退出卸载等完整生命周期：

```text
发布端生成安装包与校验值
→ 生成并签名更新清单
→ 客户端后台或手动检查更新
→ 用户查看版本说明并确认下载
→ 客户端校验签名、文件大小和 SHA-256
→ 用户确认退出并启动安装器
→ 新版本启动后确认升级结果

用户遇到问题或应用异常
→ 进入问题反馈 / 下次启动恢复提示
→ 填写复现步骤并预览可选诊断信息
→ 用户明确确认后提交或导出诊断包
→ 服务端返回反馈编号
→ 维护者按版本、错误码和状态完成分流处理

首次启动 / 日常运行
→ 单实例与窗口状态恢复
→ 新手指引、快捷键和离线帮助
→ 统一通知与后台任务状态
→ 网络、存储、备份和配置可诊断
→ 安全退出并保存必要草稿
→ 升级、回退或卸载时不误删用户数据
```

## 2. 基线与现实缺口

### 2.1 已有基础

| 能力 | 当前基线 |
|---|---|
| 版本来源 | `pom.xml` 为 `1.9.0`，JAR 写入 `Implementation-Version`，发布标签必须与 Maven 版本一致。 |
| Windows 发布 | `package-stage1.ps1` 生成 app-image、EXE、便携 ZIP 和 `SHA256SUMS.txt`；EXE 使用固定 `--win-upgrade-uuid`。 |
| Release 自动化 | 标签触发完整测试、Windows 打包、产物检查、GitHub Release 创建与发布。 |
| 网络边界 | 客户端默认只连接 `https://api.sqlteacher.tech`；Cloud API 仅监听服务器 loopback，由 Nginx 提供公网 HTTPS。 |
| 桌面入口 | 已有“设置”页面及“版本、备份与恢复”页签，可以增加独立的“更新与支持”页签。 |
| 日志与错误 | 已使用 SLF4J + Logback，并有部分错误码、脱敏和敏感配置保护，但没有统一崩溃编号和用户可控诊断包。 |
| 测试基线 | v1.9.0 发布记录为 362 项通过、0 失败、0 错误，2 项真实 AI 环境测试按设计跳过。 |

### 2.2 主要缺口

- 没有稳定版更新清单、语义版本比较、后台检查、跳过版本或稍后提醒状态。
- 没有安装包来源校验；现有 SHA-256 清单可发现损坏，但不能单独证明清单来源可信。
- 没有下载进度、取消、失败重试、校验失败清理和安装器交接流程。
- 没有“关于 SQLTeacher”、当前版本、构建信息、发布说明和支持入口。
- 没有通用问题反馈表、提交回执、服务端反馈存储、限流和处理状态模型。
- 没有全局未捕获异常边界、异常退出标记、下次启动恢复提示和安全诊断导出。
- 用户不能在发送前确认究竟会提交哪些信息，也没有明确的数据保留边界。
- 当前发布流程不会生成签名更新清单，也不会验证旧版本到新版本的真实升级路径。
- 没有单实例约束、异常退出标记、安全模式、窗口越界恢复和统一的未保存内容退出确认。
- 设置分散在不同存储中，缺少格式版本、原子写入、损坏隔离、按类别重置以及排除凭据的导入导出。
- 没有统一网络状态、系统/手动代理、连接测试、离线提示和失败重试策略入口。
- 用户看不到后台同步、下载、索引、备份等长任务的进度、取消、失败原因与重试结果。
- 没有通用通知中心、首次使用指引、上下文帮助、快捷键总览、隐私说明和第三方许可证清单。
- 缓存、日志、更新残留和诊断文件没有统一的空间占用视图与安全清理入口。
- 缺少冷/热启动、界面响应、空闲资源、关闭耗时等通用性能门禁和低磁盘保护。
- Windows 安装、升级、重装、卸载后的用户数据保留规则不够明确，安装包代码签名和 SBOM 尚未成为正式门禁。

## 4. 产品与安全原则

- **更新是建议，不是远程控制**：服务端只发布有签名的版本元数据；客户端不接受脚本、命令行参数或任意可执行指令。
- **用户最后确认**：下载前说明文件大小和来源，安装前再次确认；不在用户工作过程中强制退出。
- **离线功能不因版本过旧失效**：`minimumSupportedVersion` 只用于提示云端兼容性，不能充当离线核心功能的远程停用开关。
- **签名先于解析**：客户端先验证更新信封签名，再解析其中的版本、URL 和哈希，避免使用未认证字段发起下载。
- **下载地址受限**：只允许 HTTPS 和固定主机白名单；限制重定向次数，重定向后的每个主机仍需通过白名单。
- **反馈默认最少**：默认只发送用户主动填写内容和应用版本；任何诊断类别均需单独显示、可取消勾选。
- **不把日志当作天然安全数据**：即使日志已有脱敏，也不默认上传原始日志；优先生成结构化、限长的诊断摘要。
- **不自动报告崩溃**：崩溃记录先保存在本机，下次启动必须由用户选择是否提交。
- **支持能力不依赖登录**：访客也能导出诊断包并反馈；直连服务端的匿名提交受更严格的大小和频率限制。
- **不引入遥测**：v1.10.0 不收集启动次数、页面访问、学习行为或设备指纹；反馈提交不等于用户同意产品分析。
- **设置可恢复**：所有通用设置写入都采用临时文件、刷新、原子替换和旧版本保留；损坏配置隔离后回到安全默认值。
- **后台工作可见**：持续超过 500 ms 的通用任务进入任务中心；能取消的任务必须可取消，不能取消的阶段必须说明原因。
- **退出不丢工作**：检测未保存草稿和关键任务；只恢复必要、低敏感的编辑状态，不恢复密码、Token 或高风险确认状态。
- **系统集成最小化**：不默认开机启动、不常驻托盘、不注册无关文件类型；调用浏览器、资源管理器和安装器使用固定动作与参数边界。
- **依赖与许可证可查**：用户可以离线查看第三方组件、版本、许可证和版权声明；不得遗漏被打入正式包的运行时依赖。
- **重新认证不等于丢工作**：会话到期先保护本地草稿，再引导重新登录；任何自动重试都必须重新检查当前账号和权限。
- **错误必须可行动**：面向用户显示“发生了什么、是否影响数据、下一步做什么、错误码”，详细异常只进入脱敏诊断。
- **外部动作显式**：打开浏览器、资源管理器、安装器、复制敏感摘要、导入压缩包或覆盖文件前都要经过固定校验和必要提示。
- **维护状态不是离线**：服务端维护、客户端过旧、鉴权失效、限流与真实断网分别建模，避免无意义重试和错误指导。
- **系统事件要重新校验**：唤醒、网络切换、时钟/DPI 变化后重建短期连接与显示状态，但不自动重放高风险操作。
- **支持日志有时限**：提高日志级别必须由用户开启、显示可能风险、自动到期并仍执行脱敏；永不记录 Secret 和业务正文。

## 5. 范围与优先级

### 5.1 P0：正式版必须完成

| 编号 | 工作项 | 最低交付与验收标准 |
|---|---|---|
| V110-01 | 版本与构建信息 | 统一从构建元数据读取版本、构建提交、打包类型和运行环境；设置页可复制，不在多处手写版本号。 |
| V110-02 | 签名更新协议 | 冻结更新信封、载荷、Ed25519 签名、`keyId`、SemVer、平台、稳定通道、发布时间、说明链接、下载 URL、大小和 SHA-256。 |

## 6. 更新协议与信任模型

### 6.1 版本来源

- `pom.xml` 是产品版本唯一真源，正式值为 `1.10.0`。
- Maven 在 JAR Manifest 中写入 `Implementation-Version`、构建提交和构建时间；开发环境取不到时明确显示“开发构建”，不伪装成正式版。
- 版本比较使用独立、覆盖测试的 SemVer 值对象；`1.10.0 > 1.9.9`，稳定通道忽略 `1.11.0-beta.1`。
- 安装类型在打包时写入 `installed` 或 `portable`，决定是否提供“启动安装器”。

### 6.2 签名信封

Cloud API 返回信封，不直接返回可被信任的松散字段：

```json
{
  "keyId": "release-2026-01",
  "payload": "BASE64_OF_EXACT_UTF8_JSON_BYTES",
  "signature": "BASE64_ED25519_SIGNATURE"
}
```

签名覆盖 `payload` 解码后的原始字节。客户端先按内置 `keyId -> publicKey` 密钥环验证签名，再解析载荷，避免 JSON 字段顺序和规范化差异。载荷至少包括：

- `schemaVersion`
- `product`、`channel`、`version`、`platform`、`architecture`
- `publishedAt`、`releaseNotesUrl`
- `installerUrl`、`installerSize`、`installerSha256`
- `portableUrl`、`portableSize`、`portableSha256`
- `minimumSupportedVersion`

未知 schema、未知 `keyId`、签名错误、产品/平台不匹配、非 HTTPS URL、超限大小或非白名单主机都按“不可信更新”处理，只显示可读错误，不提供安装按钮。

### 6.3 发布端

- Ed25519 私钥只保存在发布环境的受控 Secret 中，不写入仓库、构建日志、安装包或 Cloud 数据库。
- GitHub Actions 在测试和打包通过后读取实际产物，生成带精确大小与 SHA-256 的载荷并签名。
- 发布草稿先上传 EXE、ZIP、`SHA256SUMS.txt` 和签名清单；所有资产完成后才公开 Release 并原子更新 Cloud API 的稳定版指针。
- 客户端内置公钥环；轮换时先发布同时信任旧/新公钥的客户端，再用旧信任链发布新 `keyId`，最后停止旧密钥签名。
- 若清单发布失败，Release 可以存在但应用内不得宣称已可更新；重新发布清单不能改变同一版本产物的哈希。

### 6.4 客户端状态机

```text
IDLE
→ CHECKING
→ UP_TO_DATE | AVAILABLE | CHECK_FAILED
→ DOWNLOADING
→ VERIFYING
→ READY_TO_INSTALL | DOWNLOAD_FAILED | VERIFICATION_FAILED
→ INSTALL_LAUNCHED
```

- 所有网络、文件和哈希计算都在后台执行；JavaFX 线程只更新状态。
- 同一时刻最多一个检查或下载任务；重复点击不会创建并发下载。
- 临时文件使用随机名并只位于 `app-data/updates`；启动时清理过期、未校验的残留文件。
- 仅 `READY_TO_INSTALL` 状态允许启动安装器；进程启动成功后才请求应用退出。
- 已跳过版本只抑制该版本的自动提醒，手动检查仍显示；更高版本重新提醒。

## 7. 问题反馈与诊断数据边界

### 7.1 反馈类型

- `BUG`：功能错误、崩溃、卡死或数据异常。
- `UPDATE_PROBLEM`：检查、下载、校验、安装或升级后启动问题。
- `USABILITY`：界面、文案、键盘、缩放和可访问性问题。
- `SUGGESTION`：通用改进建议；v1.10 不承诺自动进入开发范围。
- `OTHER`：无法归类的问题。

严重程度由用户描述影响程度，不让用户决定维护优先级：无法启动/数据可能受损、主要流程受阻、部分功能异常、轻微问题。服务端最终优先级由维护者确认。

| 运行环境 | 否 | Windows 版本、架构、Java Runtime 版本；不上传用户名、主机名、IP 或精确硬件序列号。 |
| 错误摘要 | 否 | 崩溃编号、错误码、异常类型、已裁剪栈帧；不含 SQL、路径中的用户名和异常消息原文。 |
| 网络摘要 | 否 | Cloud/Ollama 的成功、超时或 HTTP 状态类别；不含 URL 查询参数、Token、请求/响应正文。 |
| 联系方式 | 否 | 用户主动填写；与账号邮箱分离，不自动带入。 |
| 原始日志/数据库/文档 | 永不默认 | P0 服务端提交不接受；诊断包也明确排除业务数据库、凭据和课程内容。 |

提交前必须显示最终 JSON 字段预览和勾选状态。用户取消提交时不发送网络请求。

### 7.3 本地诊断包

诊断包只由用户主动导出，建议结构：

```text
SQLTeacher-diagnostics-<timestamp>-<random>.zip
├─ manifest.json
├─ environment.json
├─ recent-errors.json
├─ update-state.json
└─ README.txt
```

- `manifest.json` 列出每个文件、生成时间、应用版本、内容类别和 SHA-256。
- 所有字符串经过统一脱敏、限长和控制字符清理；本机绝对路径只保留末级文件名或占位符。
- 不包含 `app.db`、`demo.db`、备份、课程文档、索引、Prompt、AI 响应、SQL、剪贴板、截图、环境变量、Token、密码或 AI Key。
- 诊断包生成后由用户自行决定保存和发送位置；应用不自动打开第三方上传页面。

### 7.4 服务端生命周期

反馈状态冻结为：

```text
RECEIVED → TRIAGED → IN_PROGRESS → RESOLVED | CLOSED
```

- 提交使用客户端生成的幂等键；同一键和同一提交主体重复请求返回原反馈编号。
- 匿名提交按 IP 的短期哈希与随机安装标识做限流；标识只用于反滥用，不跨重装恢复，不用于行为分析。
- 正文按纯文本保存和渲染；拒绝 HTML、脚本、可执行附件和超出限制的压缩内容。
- 每次状态变更记录操作者、时间和原因码；审计不复制反馈全文。
- 已关闭反馈 180 天后删除明细；未关闭反馈最长保留 365 天，届时转为不含正文的聚合记录或删除。
- 联系方式与诊断信息逻辑分区，运维查询默认不展示联系方式；生产备份遵循相同删除窗口。

## 8. 通用运行能力详细设计

### 8.1 启动、单实例与窗口恢复

- 以规范化数据目录为作用域获取单实例锁；不同测试数据目录可以并行，正式数据目录不允许两个写实例。
- 第二实例只通过本机 loopback 或受权限保护的锁文件通知第一实例激活窗口，不传输 SQL、凭据、文件内容或任意命令。
- 保存窗口尺寸、最大化状态和最后安全页面；恢复时按当前屏幕拓扑、DPI 和最小尺寸裁剪，移除显示器后不会把窗口恢复到屏幕外。
- 启动阶段记录 `STARTING → UI_READY → RUNNING → CLEAN_SHUTDOWN`。只有到达 `UI_READY` 后才允许启动更新检查和非关键后台任务。
- 连续两次未到达 `UI_READY` 即提供安全模式；安全模式不加载可选 AI、同步、索引、自动更新和上次页面，但保留备份、诊断、设置恢复和 SQL 安全边界。

### 8.2 安全退出与草稿

- 建立统一 `UnsavedWorkRegistry`，页面只登记“是否有未保存工作、说明、保存/放弃动作”，主窗口不读取具体业务内容。
- 退出顺序为：阻止新任务 → 收集未保存项 → 用户确认 → 请求可取消任务停止 → 限时等待 → 原子保存窗口/设置 → 写入干净退出标记。
- 不得无限等待不可控网络任务；超时后保留可重试状态并明确说明，不使用 `System.exit` 跳过清理作为正常退出路径。
- 可恢复草稿采用类型白名单、格式版本、大小上限和到期清理；SQL 草稿可以恢复文本，但永不恢复“已确认高风险”或“自动执行”状态。

### 8.3 设置、导入导出与重置

- 通用设置按外观、更新、网络、通知、帮助和支持分区，每区有 `formatVersion`、默认值、校验器和独立迁移。
- 写入使用同目录临时文件、刷新、原子移动和上一版本备份；不支持原子移动时采用可验证替换并保留恢复副本。
- 读取失败时不覆盖原损坏文件，而是隔离、显示可读原因并加载默认值；用户可导出损坏文件供本地诊断。
- 导入先解析到内存、校验版本和字段白名单、展示差异，再由用户分项应用；未知字段忽略并报告，未来版本文件拒绝降级导入。
- “恢复默认”按类别执行并支持撤销本次操作；“重置全部”不删除账号、凭据、数据库、知识文档、备份或反馈记录。

### 8.4 网络、代理与离线

- 网络策略由一个 Application Service 提供给 Cloud、更新、反馈和网络 AI；各模块可有不同超时，但不得各自读取未校验代理字符串。
- 支持直连、系统代理和手动 HTTP(S) 代理。代理主机、端口可持久化，用户名/密码进入现有 Windows DPAPI Secret Store；诊断只显示“已配置”。
- 手动连接测试依次区分 URI 配置、代理连接、DNS、TCP、TLS、HTTP、鉴权和服务健康，错误消息不回显凭据或响应正文。
- 离线状态只表示最近受控探针失败，不把一次失败永久缓存；各离线可用功能保持可用，恢复网络后由用户操作或退避计划重试。
- 更新下载和反馈提交使用独立超时、有限重定向、响应大小上限和取消；代理设置不能放宽 TLS、签名或主机白名单。

### 8.5 后台任务中心

通用任务状态统一为：

```text
QUEUED → RUNNING → SUCCEEDED
                 → FAILED → RETRYING
                 → CANCELLING → CANCELLED
```

- 任务快照包含任务 ID、类型、发起来源、简短标题、进度、可取消/可重试标记、开始/结束时间和稳定错误码，不包含 SQL、Prompt 或凭据。
- 同一资源的互斥任务要去重，例如同一更新不能并发下载，同一数据库不能同时备份和恢复。
- 任务完成后保留有限历史，默认最多 50 条或 30 天；清理历史不删除任务产生的用户文件。
- 应用退出时区分可安全取消、必须等待和可下次恢复的任务；安装更新只有在阻塞任务完成或用户明确放弃后才能交接。

### 8.6 通知中心

- 通知来源限定为更新、任务、备份、反馈、恢复和安全提示；教学业务通知继续使用既有业务模型，不在本次重写。
- 相同来源键和结果码在时间窗口内合并，成功通知自动降级，失败与安全通知保留直至用户处理或明确关闭。
- 通知只保存标题、原因码、时间、目标页面和读取状态，不复制异常栈、反馈正文或网络响应。
- 启动时不连续弹出历史通知；主窗口使用非模态摘要，用户主动打开通知中心查看详情。

### 8.7 存储、缓存与备份健康

- 分类统计 `database`、`knowledge`、`cache`、`logs`、`backups`、`updates`、`diagnostics` 和 `support-drafts`，计算失败时显示未知，不猜测大小。
- 允许直接清理的只有可重建缓存、过期未校验更新、过期诊断和超保留期日志；每个清理器固定根目录并再次验证目标在允许目录内。
- 业务数据库、知识原文、用户备份和导出的诊断包只能由用户选择精确对象后删除，并沿用现有数据维护确认边界。
- 剩余空间低于“当前操作预计空间 + 安全余量”时禁止下载、备份或索引重建；不得开始后再以删除用户文件腾空间。
- 备份健康展示最近成功、完整性检查、文件大小和保留位置；没有经过恢复验证的文件只称为“备份文件”，不宣称可恢复。

### 8.8 帮助、引导与快捷键

- 首次启动引导只介绍数据位置、SQL 安全、AI 草稿边界、更新与反馈入口；可跳过、可从帮助页重新打开，不强迫登录。
- 帮助内容随应用离线打包并与版本绑定；外部链接只指向固定 HTTPS 官方域名，打开前显示目标。
- 页面级帮助使用稳定主题 ID，不把控制器类名或磁盘路径暴露给用户；找不到主题时回到帮助首页。
- 全局快捷键至少覆盖帮助、设置、问题反馈、任务中心、通知中心和焦点导航；不得为执行 SQL、确认高风险或安装更新提供单键捷径。
- “新版本变化”读取随包发布的静态摘要或已验证更新载荷，禁止渲染远端 HTML。

### 8.9 可访问性与国际化基础

- 所有图标按钮有可读名称，表单控件有标签关联，错误信息能被焦点和助读技术发现；颜色之外必须有文字或图标状态。
- 100%、125%、150% 缩放及 1366×768 下核心操作可达；长中文、长英文占位文本和系统字体放大不截断确认按钮。
- 尊重减少动态效果偏好；进度动画不可成为唯一反馈，闪烁和自动滚动受到限制。
- 本次新增文案和主框架通用文案进入 UTF-8 ResourceBundle；测试检查缺失键、重复键、硬编码关键文案和格式参数数量。
- 日期、时区、文件大小、百分比和版本显示使用明确 Locale，协议与哈希计算始终使用 Locale-neutral 格式。

### 8.10 关于、隐私、许可证与供应链

- 关于页展示产品名、版本、提交、构建时间、安装类型、Java/JavaFX、数据目录入口、官网/Release/支持入口和复制诊断摘要按钮。
- 隐私页用数据类别说明本地存储、可选出站、用途、保留和删除方式；每次反馈提交保存所展示隐私文本的版本号。
- 构建阶段生成第三方组件与许可证清单，正式包内可离线查看；无许可证信息或许可证不兼容的新增依赖不能进入发布包。
- 生成 CycloneDX JSON SBOM 并作为构建/Release 资产；SBOM 不包含本机路径、私有仓库凭据或用户数据。
- 更新清单 Ed25519 签名与 Windows Authenticode 是不同信任层。若尚未取得代码签名证书，必须在发布记录中明确安装包发布者状态，不得把 SHA-256 或清单签名宣传为 Windows 代码签名。
- 代码签名证书一旦具备，EXE 签名和时间戳验证进入 P0 发布门禁；私钥使用硬件/托管签名或受控 Secret，不导出到仓库和构建产物。

### 8.11 性能与兼容性预算

- 阶段 1 在同一参考 Windows 环境记录 v1.9 的冷启动、热启动、首页可交互、空闲内存、设置页打开和正常关闭基线。
- v1.10 目标为冷启动到可交互不高于 5 秒，通用功能相对 v1.9 同环境 p95 回退不超过 15%，正常关闭不高于 3 秒。
- JavaFX 线程上单次通用操作目标低于 100 ms，严禁网络、磁盘扫描、压缩、哈希、备份和进程等待；超过 500 ms 的工作进入任务中心。
- 更新下载使用固定缓冲区，不把整个安装包读入内存；目录统计可取消、限并发并避免跟随符号链接或扫描工作区外未知路径。
- 正式兼容矩阵至少覆盖 Windows 10 22H2、Windows 11 当前受支持版本、已安装版/便携版、普通用户权限和中文用户名路径。

### 8.12 账号、会话与身份切换

- 账号页只展示必要资料、当前角色、会话状态和账号操作；不得显示 Access/Refresh Token、密码哈希、内部权限声明或其他账号信息。
- 修改密码必须验证当前密码或完成等价重新认证，采用服务端密码策略并撤销旧 Refresh Token；错误响应不能用于枚举账号。
- Access Token 到期时先暂停需要云端权限的动作并保留本地草稿；刷新失败再进入重认证，成功后重新读取当前权限而不是复用旧授权快照。
- 退出和身份切换顺序为：停止该账号任务 → 清空内存 Token/凭据 → 清理账号隔离的临时数据 → 切换 Owner → 再加载目标账号缓存。
- 访客本地练习、数据库连接和知识资料不因云端退出被删除；账号缓存只按明确的数据所有权规则清理。
- 密码重置、其他会话撤销和账号注销需要额外身份通道，因此列为 P1，未完成时界面必须诚实说明而不是提供失效入口。

### 8.13 个人数据控制

- 数据中心按“本机仅存、可选上传、账号云端、运维审计”展示类别、用途、位置、保留和删除方式，不用一键笼统同意代替分类说明。
- 导出按用户选择生成带 schema、版本、时间和 SHA-256 清单的数据包；默认不包含密码、Token、AI Key、其他账号缓存、安装包或可重建索引。
- 清理动作分为可重建缓存、个人草稿、反馈/诊断、账号缓存和业务事实；最后一类沿用现有维护权限、备份和二次确认。
- 云端账号数据导出/注销在 P1 实现前提供明确请求说明；任何本地按钮不得声称已经删除服务端数据。
- 数据请求、导出和删除操作记录最小审计元数据与结果码，不复制导出正文或删除内容。

### 8.14 统一错误、表单与撤销

- 通用错误对象至少包含 `code`、用户说明、数据影响、是否可重试、建议动作、关联 ID 和可选脱敏详情；错误码一经公开不随意复用。
- 错误中心最多保存 50 条或 30 天，只保存类别和脱敏摘要；同类错误合并计数，成功恢复后记录结果但不自动删除证据。
- 表单校验分为输入即时校验、提交前完整校验和服务端权威校验；网络未完成时不把“正在校验”显示为成功。
- 自动草稿只用于明确列出的长文本/设置编辑，采用去抖、原子写入、大小和过期限制；密码、Token、确认框和一次性验证码不得保存草稿。
- 撤销只用于能可靠逆转的本地动作并显示截止时间；删除账号、恢复数据库、启动安装器和高风险 SQL 不伪装成可撤销。

### 8.15 外部链接、文件、压缩包与剪贴板

- 外部链接使用固定 `https` 主机白名单并在打开前显示主机；反馈正文、更新清单和帮助内容不能构造任意 `file:`、`javascript:` 或自定义协议。
- 文件对话框限制扩展名只是便利，真正导入还需验证文件头、大小、schema、路径和内容；拒绝设备路径、UNC（未明确支持时）和重解析点越界。
- 所有 ZIP 读取拒绝绝对路径、`..`、盘符、符号链接、重复目标、异常压缩比、超文件数和解压后超总量，写入前验证目标仍位于临时根目录。
- 复制诊断或账号摘要只复制预览中的脱敏文本；复制潜在敏感配置时明确提示，应用不读取与当前操作无关的剪贴板内容。
- 通过 `Desktop`/`ProcessBuilder` 打开浏览器、目录和安装器时使用固定可执行对象与参数，不拼接 Shell 命令。

### 8.16 API 兼容、维护与时间

- `/health` 保持最小公开状态；受控能力端点返回 `apiVersion`、兼容客户端范围、可用能力、维护状态和服务器时间，不返回内部拓扑或 Secret。
- 客户端不只依赖版本字符串：未知能力默认关闭，缺少新能力时回到旧路径；服务端不得因客户端多发未知字段而静默误解释。
- HTTP 401/403、409、413、429、503 和网络失败分别映射；尊重受限的 `Retry-After`，超过上限转为用户手动重试，避免重试风暴。
- 检测到明显时钟偏差时提示用户校准系统时间，并以服务器时间处理服务端截止/会话判断；不得擅自修改系统时钟。
- 维护模式只暂停相关云端写操作并保留草稿/Outbox，不阻断离线 SQL、知识阅读、备份、诊断和设置。

### 8.17 休眠、唤醒与环境变化

- 休眠前不保证收到通知，因此所有重要写入必须持续原子化；唤醒后丢弃过期连接、重新探测网络并按任务幂等规则恢复。
- 唤醒、网络切换或代理改变后不自动重放提交反馈、恢复数据库、发布任务、安装更新或高风险 SQL；只恢复安全只读探针和显式可重试任务。
- 系统时区/时钟改变后重新格式化显示并刷新相对时间；已经持久化的事实时间保持 UTC/明确 Offset，不批量改写历史。
- 显示器、DPI、系统主题和字体变化触发布局/主题重算，窗口仍需保持可见；编辑草稿和焦点语义不丢失。
- 关机/注销请求复用安全退出协调，但在操作系统时限内停止；无法完成的备份或下载留下可恢复状态，不阻塞到系统强杀。

### 8.18 日志与支持模式

- 正式日志默认 INFO，按大小和日期轮转，压缩旧日志并受总量/天数双上限控制；日志目录不可写时降级但不让应用无限报错。
- 建立统一敏感模式测试：Bearer/Refresh Token、密码、AI Key、代理凭据、数据库 URL 凭据、SQL/Prompt/反馈正文和用户目录不得进入通用日志。
- 用户可在本机查看按时间/级别/错误码过滤的脱敏日志摘要；打开原日志目录属于显式系统动作，不等于自动上传。
- 支持模式最多持续 30 分钟或到应用退出，开启前展示范围和风险，仍不记录禁止类别；到期自动恢复 INFO 并生成本地提示。
- 日志清理与诊断导出都通过同一保留和脱敏边界，不能因“技术支持需要”绕过预览与用户确认。

### 8.19 资源、电源与调度

- 每类 Executor 有明确 Bean/Owner、线程命名、并发上限、队列上限和关闭责任；禁止控制器临时创建无界线程池。
- 更新下载、索引、备份、目录统计和诊断压缩设置并发/缓冲预算；内存压力时先暂停可重建/可重试任务，不牺牲数据库事务完整性。
- 低磁盘、低电量和按流量计费网络检测失败时按未知处理；P0 默认只警告和保护高空间操作，P1 再提供用户策略。
- 后台失败使用有上限指数退避和抖动；退出、账号切换、网络策略变化会取消旧计划，不产生永久自唤醒循环。
- 任务指标只记录类型、耗时、结果码和资源数量，不形成用户行为遥测或上传本机性能样本。

### 8.20 通用 UI 状态与维护手册

- 本次页面使用同一组加载骨架、空状态、错误条、只读提示、成功摘要和部分失败明细；状态文案回答原因和下一步，不只显示红色图标。
- 禁用控件必须说明原因；尚未实现的 P1 不出现在正式导航，不能用点击后“敬请期待”冒充交付。
- 长任务允许离开页面并在任务中心继续观察；返回时从服务状态恢复 UI，不依赖控制器内瞬时布尔值。
- 运维手册覆盖更新清单发布/撤回、反馈滥用、保留清理、Cloud 维护、密钥轮换、证书、备份恢复、容量和事故分级。
- 发布支持策略明确当前稳定版、上一稳定版的支持窗口、最低云端兼容版本、停止支持提示和安全问题联系入口；不得无公告突然停用离线能力。
- 每个维护开关有作用域、默认值、审计、过期和回滚；不得提供能关闭客户端签名、SQL 安全、权限或隐私校验的远程开关。

## 11. 测试矩阵

### 11.1 更新协议

- SemVer：`1.9.9 < 1.10.0 < 1.10.1`，稳定版与 `alpha/beta/rc`，非法版本、前导零和超长输入。
- 信封：正确签名、单字节篡改、未知 key、错误 Base64、重复字段、未知 schema、错误产品/平台/架构。
- URL：HTTP、用户信息、非白名单主机、跨主机重定向、重定向循环、超长 URL、查询参数泄露。
- 清单：当前版、旧版、新版、跳过版、更高版、未来发布时间、超限大小、缺少哈希和重复请求。

### 11.2 下载与安装

- 正常下载、慢速网络、无 Content-Length、超时、断网、取消、磁盘不足、目标目录只读和进程退出。
- 文件截断、大小不符、SHA-256 不符、下载后替换、重复点击、并发检查、过期临时文件和杀进程恢复。
- 已安装版升级、便携版提示、安装器启动失败、用户取消 UAC/安装、应用未退出和安装后首次启动。
- v1.9.0 的数据库、外观、连接配置和本地知识在 v1.10.0 可用；回装 v1.9.0 不因 `support/` 独立状态失败。

### 11.3 反馈与隐私

- 空字段、边界长度、控制字符、Unicode、换行、HTML/脚本、压缩炸弹标记和重复幂等键。
- 登录、Token 过期、访客、限流、服务端 4xx/5xx、超时、重试、草稿恢复和成功回执。
- 密码、Bearer Token、API Key、邮箱、Windows 用户目录、SQL 字符串和数据库样本的固定脱敏夹具。
- 取消同意、取消提交、仅必填字段、逐类勾选诊断、联系方式分离和关闭后保留清理。
- 运维查询权限、状态迁移、越权读取、反馈编号枚举和审计正文泄露。

### 11.4 崩溃与恢复

- JavaFX 事件异常、后台线程异常、启动早期异常、OutOfMemory 类异常降级、崩溃记录写入失败。
- 正常退出不显示恢复提示；连续崩溃进入安全恢复提示而不是重复加载问题页面。
- 栈摘要限长、路径脱敏、重复异常合并、本地删除和诊断包 SHA-256 清单。
- 生成诊断 ZIP 后扫描禁止文件名、SQLite 文件头、常见凭据模式、SQL/Prompt 固定敏感样例。

### 11.5 UI 与可访问性

- 1366×768、125%/150% 缩放、长版本说明、长错误消息和下载中窗口缩放。
- 键盘可达、焦点顺序、按钮禁用状态、进度文本、取消操作、屏幕阅读标签和颜色不作为唯一状态信息。
- 启动检查不抢焦点；失败不弹窗轰炸；可用更新只显示一次非阻断提醒。

### 11.6 生命周期与设置

- 同一/不同数据目录双启动、陈旧锁、第一实例无响应、loopback 消息伪造、窗口最小化/多屏/DPI 变化和显示器移除。
- `STARTING`、`UI_READY` 前后崩溃、连续崩溃、安全模式、干净退出、强制结束进程和系统关机请求。
- 多页面未保存项、保存失败、用户取消退出、后台任务超时和安装更新前退出协调。
- 设置正常写入、写到一半断电模拟、临时文件残留、损坏 JSON、旧/未来格式、未知字段、默认值和分类迁移。
- 导入预览、部分应用、撤销重置，以及密码、Token、数据库凭据、AI Key 和账号会话永不导出的固定夹具。

### 11.7 网络、任务、通知与空间

- 直连、系统代理、手动代理、代理鉴权、DNS、TLS、连接/读取超时、取消、离线恢复和凭据脱敏。
- 任务排队、互斥、重复请求、进度乱序、取消竞争、失败重试、应用退出和历史保留上限。
- 通知去重、未读计数、目标失效、历史降噪、敏感正文排除和启动时不批量弹出。
- 目录不可读、符号链接/重解析点、超大目录、统计取消、低磁盘、清理失败和清理目标越界拒绝。
- 备份存在但完整性失败、恢复探针失败、保留数量、升级恢复点不足空间以及业务数据不被自动清理。

### 11.8 帮助、资源与许可证

- 首次引导完成/跳过/重开、离线帮助搜索、失效主题、外部链接白名单和无网络状态。
- 快捷键冲突、文本编辑焦点、中文输入法、屏幕阅读名称、Tab 顺序、减少动态效果和高对比度。
- ResourceBundle 缺失/重复键、格式占位符不匹配、UTF-8、长文本、Locale 切换后的日期/大小稳定性。
- 正式运行时依赖与许可证清单一一对应；SBOM 可解析、版本匹配且不含本机绝对路径或 Secret。
- 关于页版本、提交、安装类型、链接和隐私文本版本与正式构建一致。

### 11.9 性能、兼容与安装生命周期

- 同一参考机至少 3 次预热、10 次测量冷/热启动、首页可交互、设置页、空闲内存和关闭耗时，记录 p50/p95/max。
- JavaFX 线程阻塞探针覆盖网络、目录扫描、ZIP、哈希、备份、代理测试和进程等待；超过预算即失败。
- Windows 10/11、普通用户、中文用户名、带空格目录、只读安装目录、已安装版/便携版和多显示器矩阵。
- 首装、覆盖升级、连续升级、重装、取消安装、卸载程序、卸载后重装；程序文件清理但 `app-data` 不被静默删除。
- EXE/ZIP/SBOM/许可证/清单/签名资产对应，Authenticode 有证书时验证签名与时间戳，无证书时验证发布说明未虚假声明。

### 11.10 账号、会话与个人数据

- Access Token 到期、Refresh 成功/失败/撤销、密码修改、错误当前密码、重复请求、账号枚举和重新认证后权限变化。
- 退出、强制退出、身份切换、切换中任务完成、旧账号缓存、访客数据和内存 Secret 可达性。
- 本地数据分类、导出白名单、哈希清单、部分清理、取消删除、备份建议、未来 schema 和其他账号数据混入拒绝。
- 云端数据请求未实现时的诚实提示，以及 P1 实现后的重新认证、异步完成、取消窗口、保留例外和审计最小化。

### 11.11 错误、表单、外部动作与文件安全

- 每个公开错误码的说明、影响、恢复动作、可重试性和脱敏复制；未知异常回退、错误合并和历史上限。
- 即时/提交/服务端校验竞争，离开脏表单、自动草稿写入失败、过期清理、撤销截止和不可逆动作禁止撤销。
- 外链 HTTP/非白名单/用户信息/自定义协议、Shell 元字符、浏览器/资源管理器/安装器启动失败。
- ZIP Slip、绝对路径、盘符、`..`、重解析点、重复目标、文件数/压缩比/总量炸弹、文件头与扩展名不符。
- 剪贴板只写入预览内容，不读取无关内容；错误/账号/诊断摘要不包含 Token、路径用户名和业务正文。

### 11.12 API 兼容、维护与系统变化

- API 旧/当前/未来版本、缺失/未知能力、最低客户端、部分降级、维护开始/结束和服务时间偏差。
- 401、403、409、413、429、503、非法/超大 `Retry-After`、重试上限、抖动和多客户端重试风暴夹具。
- 休眠发生在下载/反馈/备份/同步各阶段，唤醒后连接失效、网络/代理切换、重复回执和高风险写操作不自动重放。
- 时区/时钟前后跳、DST、服务器时间、显示器移除、DPI/系统主题改变以及关机/注销时限。

### 11.13 日志、资源与安全基线

- 日志轮转、压缩、天数/总量上限、目录只读、磁盘写满、支持模式开启/到期/退出和并发写入。
- 固定 Secret、SQL、Prompt、反馈、数据库 URL 和用户路径夹具扫描所有日志、错误中心、任务、通知、诊断和操作历史。
- Executor 命名、队列上限、拒绝策略、取消、关闭、线程泄漏；内存/CPU/磁盘压力下非关键任务暂停和核心事务完整。
- 路径遍历、临时文件权限、反序列化未知类型、超长输入、Unicode 控制字符、URL 混淆和 Secret 清零/释放边界。
- Maven 依赖漏洞、许可证、SBOM 与正式运行时对齐；高危漏洞有修复、不可利用证据或明确阻断发布。

### 11.14 交互状态与运维演练

- 加载、空、错误、只读、禁用、成功、部分失败、过期和无权限状态具有可读说明、键盘焦点和下一步动作。

- 更新清单撤回、反馈滥用、Cloud 维护、证书/签名密钥轮换、保留任务失败、容量告警和备份恢复桌面演练。

- 单实例、配置损坏恢复、安全模式、未保存内容、任务退出协调和低磁盘场景通过真实桌面验收。
- 设置导出、诊断 ZIP、反馈请求、日志和通知历史通过固定敏感数据扫描。
- 会话到期、修改密码、退出/切换身份、个人数据导出/清理和旧账号缓存隔离通过端到端验证。
- API 版本/能力、维护、限流、时钟偏差、休眠唤醒和网络切换场景不会重复提交或误判离线。
- 通用错误码、表单草稿、外部链接、剪贴板、文件头、ZIP Slip、路径越界和临时文件权限安全测试通过。
- 日志轮转/保留/支持模式、Executor 关闭、线程泄漏、资源压力和低磁盘降级通过门禁。
- 冷/热启动、UI 响应、空闲资源和退出结果不超过性能预算；所有阻塞 I/O 均不在 JavaFX 线程。
- 离线帮助、快捷键、ResourceBundle、隐私文本、第三方许可证和 CycloneDX SBOM 与正式包内容一致。
- 首装、v1.9 升级、v1.10 重装、卸载和回装验证程序/用户数据边界；卸载不得静默删除 `app-data`。
- 已配置代码签名证书时验证 EXE Authenticode 签名、时间戳和发布者；未配置时发布记录必须明确外部条件与风险。
- 更新、反馈、账号、维护、保留、备份、密钥轮换和事故回退运行手册完成一次桌面演练并记录证据。
- 固定输出目录最终只含当前版本 EXE/ZIP 与两条对应校验记录，不混入旧版本产物。
- ZIP/EXE/app-image 不含 `.env`、`.secrets`、`app-data`、数据库、日志、反馈草稿或已下载更新。

### 12.2 发布顺序

1. 冻结 `main`，运行完整测试、性能/兼容矩阵、许可证/SBOM 和打包预检。
2. 部署兼容旧客户端的 Cloud 反馈/清单 API，完成备份恢复和公网 HTTPS 探针。
3. 构建 v1.10.0 EXE/ZIP，生成 SHA-256、许可证、SBOM 和签名清单，在隔离环境完成首装、v1.9→v1.10 升级、重装和卸载边界演练。
4. 创建并核验 `v1.10.0` 标签与 GitHub Release 资产。
5. 原子切换稳定版更新清单，使旧客户端看到 v1.10.0。
6. 使用 v1.10.0 正式包执行应用内检查、下载、校验、安装、首次启动和反馈回执端到端验收。

### 12.3 回退

- 清单或下载故障：立即把稳定版指针回退到最后一个已验证信封；客户端保留手动检查但不启动未验证文件。
- 客户端严重故障：撤下 v1.10.0 稳定版提示并发布说明；保留 v1.9.0 正式资产供手动回装。
- Cloud 反馈故障：关闭反馈写接口或降级为本地导出，不影响更新检查和 SQLTeacher 离线功能。
- Cloud migration 失败：停止切换、恢复迁移前备份并验证 loopback/API/HTTPS；不以丢弃反馈或学习数据换取上线。
- 回退只处理程序文件，不删除 `app-data`；独立 `support/` 数据由旧版本忽略。
- 设置或生命周期故障：隔离 v1.10 通用设置并使用安全默认值启动，保留损坏文件；不得通过删除整个用户数据目录恢复。
- 帮助、通知、任务中心等非核心通用界面故障：关闭对应入口并保留更新、备份、诊断和 SQL 安全主路径，不远程下发补丁代码。

## 13. 风险与裁剪顺序

| 风险 | 控制措施 | 不得采用的捷径 |
|---|---|---|
| 更新源被篡改 | Ed25519 信封、HTTPS、主机白名单、大小和 SHA-256 双检。 | 只信任版本字符串、只校验 HTTPS 或提供“忽略校验”。 |
| 安装中断或数据受损 | 安装前提示保存、固定升级 UUID、真实旧版升级测试、`app-data` 与程序目录分离。 | 更新前清空数据目录或覆盖未知路径。 |
| 反馈泄露敏感数据 | 字段白名单、发送前预览、默认最少、结构化脱敏、诊断包扫描。 | 默认上传完整日志、数据库或截图。 |
| 匿名接口被滥用 | 请求大小、速率、幂等、纯文本、最小安装标识和运维告警。 | 强制收集设备指纹或开放任意附件。 |
| 更新失败打扰用户 | 后台非阻断、24 小时节流、一次提醒、明确重试和离线降级。 | 每次启动弹模态错误框。 |
| 崩溃处理自身崩溃 | 极小写入路径、限长、失败静默降级、连续崩溃安全模式。 | 在异常处理器中启动复杂网络或数据库操作。 |
| 私钥泄露 | 仅发布 Secret、日志屏蔽、权限最小化、轮换演练。 | 把私钥放进客户端或仓库。 |
| 设置损坏导致无法启动 | 分区版本、原子写入、旧值备份、损坏隔离和安全默认值。 | 捕获异常后覆盖原文件或删除全部配置。 |
| 双实例并发写坏数据 | 数据目录级单实例锁、陈旧锁恢复和第二实例只激活窗口。 | 仅凭进程名判断或开放任意本机控制端口。 |
| 清理功能误删用户数据 | 类别白名单、固定根目录、目标复核、预览和业务数据二次确认。 | 递归删除计算路径、跟随重解析点或“清理全部”。 |
| 代理/诊断泄露凭据 | DPAPI、统一网络策略、错误分类和响应正文禁止记录。 | 把代理密码放设置 JSON、命令行或诊断包。 |
| 通用能力过多拖垮交付 | 先地基后纵向闭环、阶段门禁、P0/P1 分层和性能预算。 | 同时改造全部旧页面或借机重写架构。 |
| 帮助与实际功能不一致 | 帮助随版本打包、主题 ID 测试、发布前功能/文档逐项核对。 | 在线加载可随时变化的远端 HTML 代替版本化帮助。 |
| 新后台任务影响响应 | 统一任务中心、限并发、可取消、低磁盘保护和 UI 线程探针。 | 每个页面自行创建无限线程或静默重试。 |
| 会话过期导致丢稿或越权 | 本地草稿先保存、重新认证、重新读取权限、账号任务和缓存隔离。 | 自动无限刷新 Token 或复用切换前授权。 |
| 个人数据中心造成误删 | 分类清单、精确对象、影响预览、备份建议、重新认证和异步状态。 | “清空全部”、混淆本地/云端删除或虚假宣称已删除。 |
| 错误中心泄露内部信息 | 稳定错误码、字段白名单、栈与用户文案分离、保留上限。 | 把异常 `message`/栈直接复制到 UI、日志或反馈。 |
| 导入包或路径攻击 | 文件头/大小/schema、ZIP Slip/炸弹、固定临时根和重解析点拒绝。 | 只检查扩展名或直接向用户目录解压。 |
| 维护/限流形成重试风暴 | 状态分类、`Retry-After` 上限、指数退避/抖动和全局并发控制。 | 把 429/503 当断网并立即循环重试。 |
| 休眠唤醒重复写操作 | 幂等键、过期连接丢弃、系统事件重校验和写操作不自动重放。 | 唤醒后无条件恢复所有 Future/请求。 |
| 支持模式扩大日志风险 | 明示范围、严格禁止类别、30 分钟自动到期和出包前二次扫描。 | DEBUG 等于记录请求/响应/SQL/Prompt 全文。 |
| 远程维护开关越权 | 最小作用域、权限、审计、到期和客户端不可绕过安全规则。 | 远程关闭签名、TLS、SQL 风险、权限或隐私校验。 |

若工期不足，先裁剪全部 P1，顺序为：完整英文界面 → Windows 原生通知 → 命令面板 → 截图/高级支持包 → 分阶段发布 → 下载断点续传 → 反馈状态/撤回 → 更新镜像 → 自动备份计划 → 账号注销/密码重置 → 增强系统集成 → 启动后升级确认。

P0 内允许缩减视觉装饰和帮助文章数量，但每个覆盖领域至少保留一个完整、诚实、可测试的纵向路径。签名验证、哈希/大小校验、用户确认、离线降级、反馈预览、敏感数据排除、崩溃不自动上传、服务端限流/幂等、单实例、设置原子写入/损坏恢复、清理白名单、安全退出、账号/会话隔离、个人数据影响预览、统一错误脱敏、ZIP/路径防护、API 兼容、休眠后写操作不重放、日志禁记敏感内容、资源并发上限、代理凭据保护、离线帮助、安全模式、SBOM/许可证、真实升级测试和回退门禁不可裁剪。

## 14. 完成定义

v1.10.0 只有同时满足以下条件才可宣布完成：

- 用户能在设置页确认当前版本，并手动检查更新。
- v1.9.0 正式安装版能发现、下载、验证并在用户确认后启动 v1.10.0 安装器。
- 伪造清单、篡改安装包、错误主机和哈希不符均无法进入安装状态。
- 启动自动检查不阻塞、不抢焦点，网络失败不影响任何现有教学或 SQL 功能。
- 用户能在不登录时提交最小问题反馈或导出诊断包；成功提交获得反馈编号。
- 发送前能看到并取消每类诊断信息；固定敏感数据夹具证明禁止内容没有出站。
- 未处理异常不会造成无限启动循环，也不会未经同意自动上传。
- Cloud 反馈 API 的越权、限流、幂等、保留清理、迁移和备份恢复通过。
- 重复启动不会产生两个正式写实例；窗口在显示器/DPI 变化后仍能恢复到可见区域。
- 未保存草稿、关键任务、正常退出和异常退出均有确定行为；安全模式能启动且不放宽 SQL 安全。
- 设置可原子保存、迁移、按类别重置和脱敏导入导出；损坏设置不会阻止应用启动。
- 用户能判断 Cloud/Ollama/代理/离线状态，代理凭据不出 DPAPI 且不会出现在诊断信息中。
- 更新、反馈、备份、同步、索引和清理在任务中心具有进度与结束状态；通知去重且不复制敏感正文。
- 存储页能安全清理可重建内容并阻止低磁盘高风险操作，固定越界夹具证明不会误删用户数据。
- 首次引导、离线帮助、快捷键、关于、隐私、第三方许可证和 SBOM 均随正式包可用。
- 会话过期可重新认证且不丢本地草稿；修改密码、退出和身份切换清理 Secret、任务和账号缓存而不删除访客数据。
- 个人数据中心准确区分本地/云端数据，导出与清理具备白名单、预览、备份建议和不可逆确认。
- 通用错误中心不显示原始栈，错误码、影响、恢复建议和安全复制内容通过契约测试。
- 表单校验、脏状态、草稿和撤销边界一致；未实现入口不出现在正式界面。
- 外部链接、剪贴板、文件导入、ZIP、临时目录和系统进程动作通过路径/内容/参数安全门禁。
- API 兼容、维护、限流、鉴权和时钟偏差能被区分；休眠/唤醒与网络变化不会自动重放写操作。
- 日志轮转、保留、支持模式和敏感扫描通过；所有 Executor 可关闭且没有无界队列和测试可见线程泄漏。
- 加载、空、错误、只读、禁用、成功、部分失败和过期状态在主框架与本次页面保持一致。
- 低分辨率、缩放、键盘和长文本场景可用。
- 冷/热启动、关键界面响应和退出性能不超过已冻结预算，JavaFX 线程阻塞探针通过。
- 首装、升级、重装、卸载和回装路径经过真实 Windows 验证，卸载不静默删除用户数据。
- 全量测试、EXE/ZIP、SHA-256、签名清单、包内容扫描、Cloud HTTPS、GitHub Actions 和公开 Release 全部通过。
- `main`、`v1.10.0` 标签、Maven 版本、更新清单和公开 Release 指向同一已验证提交与产物。
