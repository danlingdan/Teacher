## 1. 背景与结论

2026-09-09 对 `3.1.0` 主分支做了一次全库只读审计（SQL 执行安全链 / AI 与云客户端 /
领域与学习业务 / 云服务端 / 前端 / 持久化与桥接，6 个方向）。总体结论：执行架构与
安全分层设计健全（参数化 100%、IPC 白名单三方一致且有测试钉死、凭据全程 `char[]`、
错误脱敏一致），但确认了 **3 个 P0**、约 20 个 P1。三个 P0 均经主审会话逐行复核：

| 编号 | 级别 | 问题 | 位置 |
| --- | --- | --- | --- |
| A1 | P0 | MySQL 可执行注释 `/*! ... */` 绕过风险分析：分析基于去注释文本、执行用原文，`SELECT ... /*!40001 INTO OUTFILE ... */` 判 LOW 直接执行；GENERIC 方言叠加 `allowMultiQueries` 双杀 | `DefaultSqlRiskAnalysisService.java:28,292-310`、`JdbcSqlExecutionService.java:140` |
| A2 | P0 | 主 AI 路径未钉扎 HTTP/1.1：明文 `http://localhost:11434` 带 body POST 正是已复现的 h2c 死锁形态，2026-09-04 修复（commit `9563f5d`）漏掉了流量最大的生成路径与桌面端 embedding | `OllamaAiModelProvider.java:32-34,58-62`、`OllamaEmbeddingProvider.java:26` |
| A3 | P0 | 云端认证端点无限速无锁定：login/register/refresh 公网可达，每次尝试 310k 次 PBKDF2（CPU 放大）并写一行 `admin_audit`；注册 409 泄露邮箱注册状态；Nginx 示例无 `limit_req` | `SqlTeacherCloudServer.java:158-199`、`packaging/cloud/sqlteacher.conf.example` |

P1 级问题按域归组（详情见各工作项引用）：

- SQL 链：H2/DuckDB 文件读取函数未设防（A4）；UI 路径拒绝/确认/取消不产生审计事件（A5）；
  CTE 与括号复合查询被误判 FORBIDDEN，学生交不了 CTE 答案（A6）；亚秒 timeout 归零为
  无超时 + RuntimeException 绕过审计（A7）。
- 网络：云会话 401/403 判定靠 `message.contains("HTTP 401")`，服务端 JSON 消息使其失效，
  失效会话不登出（A8）；每次网络 AI 调用 new 一个 HttpClient + ObjectMapper（A9）。
- 服务端：`/sync/events` 与 `/bank/publish` 绕过 64KB 请求体上限无界解析、payload 无长度
  校验（A10）；匿名报表限流可绕过（不读 X-Forwarded-For + installId 自报）（A11）；绑定邮箱
  从不更新 `users.email`、验证邮件无限速可轰炸（A12）。
- 本地数据：备份恢复不清理 `-wal`/`-shm`，旧 WAL 重放可致静默损坏，Lucene 索引不失效（A13）；
  干预 `stableId` 把 attempts/lastSubmittedAt 计入哈希，状态失联、已处理项反复重现（A14，
  即 v3 遗留"干预状态机不一致"的根因）；练习进度统计与会话无 owner 隔离（A15）；干预脏状态
  `valueOf` 炸整个教师刷新（A16）；队列单个 outbox 失败整体降级且零日志（A17）。
- 前端：Monaco `onMount` 冻结闭包，CODE 活动 Ctrl+Enter 提交挂载时旧代码并计入学习记录（A18）；
  CloudPage 班级任务加载竞态（A19）；KnowledgePage/SettingsPage/TeachingPage 三态缺失、
  约 10 个 mutation 失败静默（A20）；RunnerFlow 探测失败永久"正在探测"（A21）。

同时，工作树已有两项已完成并通过行为测试的改进（本计划随 3.2.0 一并发布，见 W5.4）：

1. **CloudPage 云端操作反馈补全**：刷新班级、同步、班级/作业分析、反馈、掌握度、课程/章节/
   知识点操作等约 15 个 mutation 补齐 onSuccess/onError toast（`PlatformPages.tsx`）。
2. **创建班级后自动选中**：`cloud.class.create` 成功后 `setClassroomId` 自动选中新班级并提示，
   含 `.plain-list li.selected` 选中样式（`App.css`）与 `CloudPage.test.tsx` 行为测试。

计划制定当天另做了一次**安全合理性评审**（措施强度 vs 威胁模型），确认本地桌面教学产品的
真实边界只有三个：不可信内容进入执行路径（AI 草稿、导入包、检索文档）、应用自身完整性
（更新/导出/备份/app-data）、公网云端。评审发现"SQL 开发者模式"在 UI 路径是**无效开关**
（桥接层 `sqlAnalyze`/`sqlExecute` 使用原始分析结果，`DeveloperSqlExecutionPolicy` 的松绑
与 DROP 放行均不可达），且 DROP/TRUNCATE/GRANT/REVOKE/DROP DATABASE 的绝对禁止超出了
"学生操作自己的本地教学库"的威胁模型（学生本可直接用 mysql CLI 执行这些语句）。维护者
据此决策（D1–D6），落入 W1.2/W1.6/W2.4：D1 修活开发者模式并把默认值改为教学模式（明示
选择，替换静默 fail-open）；D2/D3 上述五类语句降为确认制；D4 文件函数按读/写分级；
D5 AI 每日配额整体移除（本地免费模型与云端 AI 一致不设日配额）；D6 本地 UI 错误信息放开
细节、日志与云端维持脱敏。相应地，`AGENTS.md`"非协商安全"一节中 "Block DROP DATABASE,
GRANT, and REVOKE" 的红线表述随本计划实施同步修订为确认制语义（与代码同批提交）。

## 2. 目标与非目标

### 2.1 目标

- 消除全部 3 个 P0：`/*!` 与 GENERIC 多语句不可再绕过风险分析；全部明文 HTTP 客户端统一
  钉扎 HTTP/1.1；认证端点具备失败锁定与网关限速。
- 安全模型按输入来源与风险重校（合理性评审 D1–D6）：开发者模式开关真正生效（默认教学
  模式、配置缺失/损坏 fail-closed、首次明示选择），DROP/TRUNCATE/GRANT/REVOKE/DROP
  DATABASE 降为确认制，文件函数按读/写分级，本地 UI 错误信息放开细节，AI 每日配额移除
  ——使措施强度与"本地教学库"威胁模型匹配，同时不可信输入边界（AI 草稿、导入包）的
  防御强度不降。
- 修复 SQL 教学产品的确定性功能缺陷：CTE/复合查询可正常作答；H2/DuckDB/GENERIC 方言的
  文件读取函数设防；SQL 拒绝/确认/取消全程可审计。
- 消除本地数据损坏与串扰风险：备份恢复清理 WAL 并阻塞并发访问；干预状态按自然键稳定匹配；
  练习进度与会话按 owner 隔离。
- 前端：快捷键提交/提示读取当前编辑内容；数据加载三态齐备；操作失败可见；班级任务不再串台。
- 两项已完成改进随版本正式发布。
- 服务端加固随 3.2.0 分阶段部署生产，桌面端与服务端可独立回退。

### 2.2 非目标

- **队列 N+1 批量端点**（A14 相邻的教师端 N+1 同理）：需要云端 API 扩展与跨端兼容设计，
  移入 v3.3 候选（见第 7 节）。
- Monaco 模块级动态拆分（当前路由级 lazy 已拆，首访页面仍整体加载）。
- 组件安装异步化（winget 弹窗与 30 秒超时）、Rust 退出 kill 窗口放宽、DPAPI 瞬时故障删文件
  策略、CSV 导出公式中和与路径校验、AI 历史全收藏误删、模型 unload 阻断选模等 P2 项。
- 不改变任何 IPC 方法集、判分内核语义、数据库 schema 兼容性（新增列/事件类型均为增量）。
- 不重构任何架构分层（审计确认无架构违规）。

## 4. 工作项拆解

### W1 SQL 执行链安全与正确性（A1、A4—A7，最高优先级）

- **W1.1 可执行注释分析对齐（A1）**：`removeComments` 增加方言感知的 `/*!` 处理——MySQL
  家族方言与 `GENERIC`（服务器家族未知，保守处理）在分析文本中**保留** `/*! ... */` 的内容
  （仅剥掉 `/*!` 与 `*/` 定界符），其余方言按普通注释照旧剥离；执行始终用原文。这样既有的
  `MYSQL_FILE_OUTPUT`、危险函数、多语句、管理语句检查看到的就是 MySQL 服务器实际会执行的
  内容，从根上闭合"分析与执行不一致"的缺陷，而 `SELECT /*! 教学注释 */ ...` 等合法写法
  照常按 SELECT 放行。GENERIC 不做连接级拒绝：多语句由分析层继续拦截，内置 MySQL/MariaDB
  连接维持既有 `allowMultiQueries(false)` 硬编码不变。测试：`/*!40001 INTO OUTFILE */`、
  `SELECT /*! SLEEP(60) */ 1` 被既有检查拦截；`SELECT 1 /*!; DROP TABLE t */` 按多语句
  拦截；字符串字面量内的 `/*!` 不受影响；良性 `/*!` 注释在 MySQL 放行、在其他方言剥离。
- **W1.2 文件函数分级设防（A4，D4 决策）**：为 H2（`FILE_READ`/`CSVREAD`）、DUCKDB
  （`read_text`/`read_csv`/`read_json`/`read_parquet`）、POSTGRESQL（`pg_read_file`/
  `pg_read_binary_file`）与 GENERIC 增加文件函数识别（大小写与空白不敏感，延续现有
  `MYSQL_FILE_OUTPUT` 实现方式），并按读/写分级：**读取类**（含 MySQL `LOAD_FILE`——
  本地库读的是用户自己机器上的文件，确认知情即可）降为 HIGH+确认后可执行；**写入类**
  （`INTO OUTFILE`/`DUMPFILE`、`COPY ... TO PROGRAM|FILE`——向任意路径写文件超出查询
  语义且不可预览）维持 FORBIDDEN。测试覆盖读取类确认后可执行、写入类拒绝、各方言别名。
- **W1.3 CTE 与复合查询放行（A6）**：`firstKeyword` 识别 `WITH` 与前导 `(`——跳过 CTE 头与
  括号前缀后提取主语句类型；`WITH ... SELECT` 判定为 SELECT（LOW）、`WITH ... INSERT/UPDATE`
  判定对应写风险。练习/评测入口的 SELECT-only 校验同步适配（`WITH ... SELECT` 可作答）。
  测试：CTE 查询、嵌套 CTE、`(SELECT 1) UNION (SELECT 2)`、`WITH ... INSERT`（仍拦）。
- **W1.4（可选，已降级）审计事件补全（A5）**：合理性评审认定 SQL"审计"事件的实际消费者
  是学情分析而非安全审计，本项降级为时间允许才做：桥接层拒绝处调用 `LearningEventService`
  记事件、`LearningEventType` 增加 `SQL_CONFIRMED`/`SQL_CONFIRMATION_CANCELLED`（沿用现有
  命名风格）；实现前先核实学习事件云同步路径对新事件类型的兼容性（服务端是否校验类型枚举）。
- **W1.5 执行层收尾（A7）**：timeout 校验要求 ≥1 秒（`Duration.toMillis() >= 1000`），
  `setQueryTimeout` 前 clamp 到 `[1, Integer.MAX_VALUE]`；`execute` 增补
  `catch (RuntimeException)` 统一记审计失败事件并转换为 `SqlTeacherException`。
- **W1.6 安全模型重校（合理性评审 D1/D2/D3/D6 落地）**：
  - **D1 开发者模式接线修复**：`DefaultLocalAppApi.sqlAnalyze/sqlExecute` 改用
    `DeveloperSqlExecutionPolicy.apply(...)` 后的分析结果（两层使用同一策略，消除
    "开关无效"与"两层判定不一致"两个缺陷）；`FileSqlSafetyModeService` 默认值从静默
    fail-open 改为教学模式（配置文件缺失/损坏均 fail-closed）；首次进入 SQL 工作台明示
    选择"教学模式（写操作需确认）/开发者模式（INSERT/CREATE 免确认）"，设置页开关文案
    与实际行为对齐。
  - **D2/D3 语句分级**：`DROP`/`TRUNCATE` 从一律禁止降为 HIGH+确认（复用
    `DeveloperSqlExecutionPolicy` 既有设计并经 D1 接通 UI 路径）；`GRANT`/`REVOKE` 从禁止
    降为 HIGH+确认；`DROP DATABASE` 从禁止降为 HIGH+确认并附备份强提示（确认弹窗文案
    明示"将删除整个数据库且不可恢复，请确认已有备份"）。多语句拦截与写入类文件操作
    （W1.2）不受模式影响，始终生效；不可信输入路径（AI 草稿进入工作台后）与手动输入
    同规则，由确认弹窗兜底。
  - **D6 错误信息分级**：本地 UI 透出分类后的错误细节（连接失败具体原因、驱动错误分类
    ——用户对本机与自有连接拥有信息所有权，过度脱敏伤害自查能力）；日志与云端错误路径
    维持既有脱敏不变。
  - 测试：开发者模式开/关在 analyze 与 execute 两层语义一致；五类语句在两种模式下的判定
    矩阵；配置文件缺失/损坏默认教学模式；首次选择流程写入正确模式；本地错误细节呈现
    且日志不含凭据。

### W2 网络与 AI 客户端加固（A2、A8、A9）

- **W2.2 云会话失效判定类型化（A8）**：`PersistentCloudSessionService` 与

### W3 云服务端加固（A3、A10—A12，随 3.2.0 部署生产）

- **W3.1 认证限速与锁定（A3）**：login/register/refresh/request-password-reset 按账号 +
  来源维度做失败计数与递增锁定（如 5 次失败锁 15 分钟，仅成功登录清零）；登录路径对不存在
  的邮箱执行一次哑 PBKDF2 拉平时序差；Nginx 配置增加 `limit_req` 作用于 `/api/v1/auth/`
  （示例配置与生产同步更新）。注册 409 改为与成功一致的统一外观响应（先核实 3.1.0 客户端
  对注册冲突错误码的依赖，保持客户端可理解的错误通道）。审计写入改为独立轻量表或异步化，
  不再逐次登录写 `admin_audit`。
- **W3.2 请求体上限统一（A10）**：`/sync/events` 与 `/bank/publish` 改走
  `requestBytes`/`objectRequest`；`upload()` 对 `payloadJson` 增加逐条长度上限。**取值先在

## 6. 风险与回退

- **安全模型重校的行为变化（用户可感知）**：全新安装默认从（静默）开发者模式改为教学模式，
  从未触碰开关的存量用户升级后将开始收到写操作确认弹窗（首次进入工作台有模式选择引导，
  切到开发者模式即恢复无打扰）；DROP/TRUNCATE/GRANT/REVOKE/DROP DATABASE 从一律拒绝变为
  可确认执行。发布说明的兼容性条目必须明示；模式开关即回退路径，无需版本回滚。
- **分级放宽与不可信输入边界的相互作用**：AI 草稿进入工作台后与手动输入同规则，确认
  弹窗成为不可信输入的最终闸门——弹窗文案需完整呈现语句与风险理由，不允许在草稿场景
  弱化提示；多语句与写入类文件操作不随模式放宽，测试矩阵固化。
- **可执行注释分析对齐的影响面**：MySQL 家族与 GENERIC 的分析文本开始包含 `/*!` 内容，
  行为只向更保守方向变化（良性用法不新增拒绝）；个别非 MySQL 服务器把 `/*!` 当普通注释
  使用时，只有注释内容本身命中危险模式才会被拦（理论误报面极小，可接受 fail-closed）；
  发布说明注明"注释中隐藏的负载将按其执行语义参与风险分析"。
- **限速误伤**：学校 NAT 出口共享 IP，锁定以账号维度为主、来源维度从宽；Nginx `limit_req`
  阈值需结合现网流量观测设定，先部署观察再收紧。
- **请求体上限误伤旧客户端**：W3.2 上限取值前必须测量 3.1.0 客户端实际 payload 分布；
  宁宽勿断，超限响应携带明确错误码供后续客户端提示。
- **干预状态一次性重现**：自然键化后旧状态行失效，已确认/已忽略项会在升级后首次刷新时
  重现一次，属已知迁移成本，发布说明与教师手册明示。
- **恢复门闸死锁风险**：全局排他闸必须带超时与失败释放，恢复失败走既有回滚分支；聚焦
  测试覆盖恢复中异常。
- **服务端部署回滚**：W3 全部为服务端独立变更，分阶段部署 + 部署前备份，出问题按运维流程
  回滚上一版 jar 与 Nginx 配置；桌面端 3.2.0 对服务端 3.1.x 保持兼容（未改 API 契约）。
- **审计事件新增的同步兼容**：W1.4 实现前核实云同步对未知事件类型的处理（服务端应为存储
  透传；若校验枚举则同步放行白名单）。
