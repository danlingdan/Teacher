## 1. 背景与结论

SQLTeacher 2.3 已经形成稳定的 Java 21 应用、领域、基础设施和云端能力，但桌面 UI 在持续扩展后出现以下结构性问题：

1. 页面数量和控制器体积持续增长，导航、状态、异步任务及依赖装配集中在 JavaFX 控制器内。
2. 课程、练习、实验、知识、班级和设置的用户路径被拆成过多页面，角色差异主要靠页面内控制，而不是信息架构本身。
3. 代码编辑器、Markdown/公式/Callout、虚拟列表、渐进渲染和现代无障碍支持在现有 JavaFX 体系内继续补齐的成本较高。
4. 页面性能缺少贯穿启动、交互、IPC、渲染和内存的统一基线，现有验证更偏向 Java 服务和确定性业务性能。

本计划选择以下总体路线：

> 使用 **Tauri 2 + React + TypeScript + Vite** 重建桌面界面；使用 **Monaco Editor** 提供代码编辑；使用 **unified/remark/rehype + KaTeX** 建立独立知识内容兼容层；把现有 Java 应用、领域和基础设施代码升级到 **Java 25 LTS** 后作为本地核心进程，通过有类型、可取消、受权限约束的本地 IPC 连接。

选择 Tauri 的主要原因是其使用系统 WebView、支持外部二进制 Sidecar 和细粒度 Capability 权限，适合把既有 Java 核心作为随应用分发的本地进程；Windows 端需要把 WebView2 的在线、离线和固定运行时分发方式纳入验证。[Tauri 概览](https://v2.tauri.app/start/)、[Sidecar](https://v2.tauri.app/develop/sidecar/)、[Capabilities](https://v2.tauri.app/security/capabilities/)、[Windows 安装器](https://v2.tauri.app/distribute/windows-installer/)

Electron 不作为首选。它内置 Chromium 和 Node.js，官方安全指南也要求对远程内容、上下文隔离、导航和新窗口等能力进行持续加固；在当前 2.3 Windows 包已约 200 MB 的情况下，它会增加安装体积和安全维护面。[Electron 进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)、[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

Compose Desktop 作为 Alpha.1 的备选退路，而不是并行开发路线。它可降低 JVM/IPC 迁移成本，但无法直接利用 Monaco 和成熟的 Web Markdown 插件生态，容易把编辑器、公式和 Obsidian 兼容工作重新变成自研控件工程。[Compose Desktop API](https://kotlinlang.org/docs/multiplatform/compose-desktop-components.html)

## 2. 目标与非目标

### 2.1 目标

1. 将 23 个 JavaFX 页面重新组织为不超过 7 个面向任务的工作区，减少重复入口和页面内说明文字。
2. 所有存在明确先后关系的操作使用分步流程、状态反馈和可恢复操作，不靠长段文字解释流程。
3. 为 SQL、Java、Python、C/C++ 等编辑场景提供语法高亮、补全、诊断、格式化入口和可扩展语言服务。
4. 原生兼容课程知识中的 Markdown、公式、Callout、Wiki 链接、嵌入、Mermaid 和代码块，并对不支持的语法提供可理解的降级显示。
5. 保留现有确定性学习、SQL 安全、权限、云端、数据库和本地 Runner 规则，UI 不拥有权威业务决策。
6. 建立可重复的性能基线、预算、跟踪与回归门禁，使启动、响应、渲染、内存和包体积都可测量。
7. 支持 Windows 10/11、离线核心学习、正常升级和 2.3 数据兼容。
8. 将编译、测试、运行时镜像和发布流水线统一升级到 Java 25 LTS，避免 3.0 发布后短期内再次迁移 Java 基线。

### 2.2 非目标

1. 3.0 不重写 Java 领域层、应用层、SQLite 数据或云端服务。
2. 不为 Java 升级而回写已发布的 2.3 安装包；2.3 维护线继续使用 Java 21，安全修复按原发布流程交付。
3. 3.0 不同时更换现有 Ed25519 更新信任链、生产 API 或账号体系。
4. 不把浏览器/PWA 作为唯一运行形态；本地编译器探测、文件、数据库、进程和离线能力仍需桌面容器。
5. 不在首个 Alpha 中执行 Dataview JavaScript、任意 HTML、TikZ 或其他不受信内容。
6. 不按现有 FXML 页面一比一翻译为 React 页面。
7. 不在 3.0 首轮引入 GraalVM Native Image；Spring、JDBC、Lucene、PDF 等反射和资源配置会显著扩大迁移风险。

```text

  ├─ Capability 权限白名单
  └─ Java Sidecar 生命周期

           ▼

  ├─ 有类型应用 API
  ├─ 事件、取消、进度与错误映射
  └─ 现有 Spring 装配
           │
           ▼
application -> domain
infrastructure -> application/domain
  ├─ SQLite / JDBC
  ├─ Runner / 环境探测
  ├─ 知识索引 / 文件
  ├─ Ollama / AI
  └─ Cloud API
```

### 4.1 IPC 契约

首选标准输入/输出 JSON-RPC，不开放固定的本机 HTTP 端口。Tauri/Rust 负责启动、监控和关闭 Java Sidecar；Java 暴露显式用例，不暴露 Spring Bean、JDBC Connection 或文件系统任意访问。

每个请求必须包含：

- `requestId`、`method`、`params`、`contractVersion`；
- 明确的响应或结构化错误；
- 对长任务的进度事件和取消令牌；
- 最大载荷、超时和并发限制；
- UI 可显示、日志可分类但不泄密的错误码。

UI 不得绕过 Java 中的 SQL 风险分析、只读限制、确认门、结果上限、权限判断、确定性评分或审计记录。

### 4.2 Java 25 LTS 基线

3.0 的 Java 编译和运行基线升级为 Java 25 LTS，发布构建默认采用 Eclipse Temurin 25。Java 21 仍是受支持的 LTS，并非在 2026 年立即停止维护；需要提前处理的是 Oracle JDK 21 在 NFTC 许可下的更新窗口计划于 2026 年 9 月结束，而 Java 25 是当前最新 LTS。Oracle 的商业支持路线列出 Java 25 Premier Support 至至少 2030 年 9 月、Extended Support 至至少 2033 年 9 月；Adoptium 对 Temurin 25 的可用性计划至少延续到 2031 年 9 月。[Oracle Java SE 支持路线](https://www.oracle.com/java/technologies/java-se-support-roadmap.html)、[Eclipse Temurin 支持路线](https://adoptium.net/support/)

升级必须作为独立兼容门禁完成：

- 将 Maven 编译基线、Toolchains、CI 和发布脚本统一为 Java 25，禁止开发机隐式使用不同 JDK；
- 在修改业务代码前运行完整 Java 21 基线测试，再在 Java 25 上运行相同测试集并保存差异；
- 验证 Spring、SQLite/JDBC、Lucene、Jackson、PDF、HTTP、加密、Runner、jlink/jpackage 和现有迁移脚本；
- Alpha 阶段仍需验证 JavaFX 回退入口能在 Java 25 运行，或为回退包明确保留独立 Java 21 runtime；
- 生成 Java 25 精简运行时镜像并作为 Tauri Sidecar 资源分发，用户不需要预装系统 JDK；
- 固定 Temurin 发行版、架构和补丁版本，季度安全更新必须通过完整测试和打包门禁后进入发布；
- 不为了使用新语法而批量改写现有 Java 代码；先完成无行为变化升级，再单独采用经过收益证明的新特性。

## 5. 新信息架构与交互原则

旧页面不逐页复刻，3.0 合并为以下工作区：

| 工作区 | 主要内容 | 角色 |
| --- | --- | --- |
| 今天 | 下一步学习、最近课程、诊断状态、明确反馈 | 全部 |
| 课程与知识 | 课程树、章节、知识阅读、搜索、导入 | 全部；管理操作按权限显示 |
| 练习与实验 | 选题预览、确认、作答、反馈；项目和模拟活动 | 全部 |
| 数据与 SQL | 数据库连接、结构、SQL 工作台、安全确认 | 全部；高级操作按权限显示 |
| 教学工作台 | 题库、内容、发布、学情与反馈 | 教师/管理员 |
| 班级与云端 | 班级、成员、任务、同步与账号状态 | 按角色 |
| 设置与数据 | 外观、环境、连接、安全、备份、更新、高级设置 | 全部；危险项按权限显示 |

交互遵循以下规则：

1. 明确流程使用步骤状态暗示：选择 → 预览 → 确认 → 操作 → 反馈。
2. 未进入作答前不展示编辑器；未选择对象前不展示不可操作的大型空白面板。
3. 每个异步动作必须有加载、成功、空结果、失败和重试状态。
4. 学生界面不渲染教师发布、成员管理或管理型知识操作；后端仍独立鉴权。
5. 常用设置提供推荐默认值；高级设置折叠，展示影响范围、恢复默认和验证结果。
6. 长列表按课程、类型、难度和状态分组并支持搜索，不再把不同课程活动混排在一个滚动列表。
7. 文案只解释不可从界面推断的规则，不承担导航和流程提示的主要职责。

## 6. 知识内容兼容层

知识层分为导入/索引和显示两个边界：Java 负责读取、权限、路径解析、稳定内容 ID、附件登记、增量索引与持久化；TypeScript `knowledge-renderer` 只接收受限内容模型并渲染。

### 6.1 首批支持

- YAML frontmatter 与普通 Markdown；
- GFM 表格、任务列表、脚注和代码块；
- `$...$`、`$$...$$` 与 KaTeX；
- Obsidian Callout，包括类型、标题、折叠 `+/-` 和嵌套；
- `[[Wiki 链接]]`、标题链接、块链接、别名与 `![[嵌入]]`；
- Mermaid，隔离渲染并设置节点/文本上限；
- 图片、PDF 和本地附件的受控预览；
- 不支持语法的原文降级卡片和诊断信息。

Obsidian Callout 的语法和折叠规则以官方说明为兼容基准。[Obsidian Callouts](https://obsidian.md/help/callouts)

Markdown 管线采用 AST 插件方式，避免字符串替换堆叠。`remark-rehype` 官方文档明确指出原始 HTML 处理存在 XSS 风险；默认不执行原始 HTML，确需启用时必须经过 `rehype-sanitize`。公式渲染遵守 KaTeX 的 `trust`、`maxSize` 和 `maxExpand` 安全限制。[remark](https://github.com/remarkjs/remark)、[remark-rehype 安全说明](https://github.com/remarkjs/remark-rehype)、[remark-math](https://github.com/remarkjs/remark-math)、[KaTeX 安全说明](https://katex.org/docs/security)

### 6.2 延后支持

- Dataview 首先显示查询源码和“不执行动态查询”的说明，Beta 前再决定只读子集；
- TikZ 首先显示源码、已有导出图片或离线预渲染结果，不在 WebView 中执行任意 TeX；
- 第三方 Obsidian 插件不直接加载；
- 外部网络资源默认阻止，用户明确允许后才获取。

## 7. 性能工程计划

性能优化不是“全部完成后再调优”，而是每个 Alpha 都必须提交基线、预算和回归结果。

### 7.1 测量方法

1. 固定一台参考 Windows 11 机器，并记录 CPU、内存、磁盘、电源模式、JDK、WebView2 和构建号。
2. 每项基准至少预热 3 次、正式测量 10 次，记录 p50、p95、最大值和标准差；不以最快一次作为结论。
3. 把启动拆为 Tauri 启动、WebView 创建、Java 进程启动、Spring 初始化、数据库就绪、首次 IPC、首个可交互视图。
4. UI 使用 Long Task、React Profiler 和性能标记；Java 使用 JFR/结构化计时；进程层采集 CPU、私有工作集、句柄和退出时间。
5. CI 运行短基准并阻止明显回退；完整数据集、冷启动和长稳态测试在发布门禁运行。
6. 每次预算调整必须保存原始结果、原因和批准记录，不允许通过放宽阈值掩盖回退。

### 7.2 Alpha.1 初始预算

下表是 3.0 的初始验收目标，不是已经达到的结果。Alpha.1 完成同机 2.3 对照后允许校准一次，此后冻结至 Beta。

| 指标 | Alpha.1/Beta 预算 |
| --- | --- |
| 冷启动到可交互 p95 | 不高于 4.0 s，且不劣于同机 2.3 基线 10% |
| 温启动到可交互 p95 | 不高于 2.0 s |
| 缓存页面切换 p95 | 不高于 150 ms |
| 本地数据页面骨架反馈 | 100 ms 内出现 |
| 常规本地数据页面完成 p95 | 不高于 800 ms |
| 普通输入/键入主线程任务 | p95 小于 50 ms，正常输入不得出现超过 100 ms 的长任务 |
| 无 I/O IPC 往返 p95 | 不高于 20 ms |
| 2,000 项列表 | 滚动和筛选无全量 DOM 渲染，使用虚拟化 |
| 200 KB 典型知识笔记首次渲染 p95 | 不高于 300 ms |
| 2 MB 大型知识笔记首次可读 p95 | 不高于 1.5 s，使用 Worker/分段渲染 |
| Monaco 打开 1 MB 文件 p95 | 不高于 1.0 s；键入保持上述输入预算 |
| 空闲 CPU 中位数 | 小于 1%，禁止轮询维持状态 |
| 正常退出 p95 | 不高于 2.0 s，不遗留 Java 子进程 |
| 空闲私有工作集 | 先以 350 MB 为预警线；Alpha.1 同机对照后冻结硬门槛 |
| 常见工作流峰值私有工作集 | 先以 600 MB 为预警线；无持续增长 |
| Windows 包体积 | 在线 WebView2 方案不超过 2.3 的 120%；离线 WebView2 单独记录 |

既有业务性能预算继续作为硬门槛，不因 UI 迁移放宽。对知识库新增 2,140 文件真实样本导入、10,000 文件合成样本、公式/Callout 密集笔记和失效附件样本。

### 7.3 优化策略

#### 启动

- Tauri 首窗与 Java Sidecar 并行启动，首页只等待必要的身份和下一步学习摘要；
- Spring Bean、知识索引、环境探测和云端同步按需延迟；
- 持久化可验证缓存，不在启动时重复扫描工具链和完整知识库；
- 避免首屏加载 Monaco、Mermaid、KaTeX 和教师模块，按路由拆包。

#### 交互与渲染

- 大列表和树使用虚拟化、稳定键和增量加载；
- 搜索、过滤、补全和 Markdown 解析使用 Worker 或可取消后台任务；
- React 状态按功能切分，避免全局状态变化触发整页重渲染；
- Monaco 模型按文档复用并设置数量/大小上限，离开页面及时释放；
- 图片、PDF、Mermaid 和复杂公式使用可见区加载及占位尺寸，避免布局抖动。

#### Java 与 IPC

- IPC 返回专用 DTO 和分页游标，不序列化完整领域对象图；
- 大结果按页或事件流传输，设置最大行数、字节数和取消点；
- 消除 UI 轮询，统一使用服务事件；合并高频进度事件；
- 环境探测和知识索引建立指纹缓存，文件变化时增量更新；
- 保留现有数据库索引、SQL 上限和确定性计算路径，并用 JFR 定位真实热点。

#### 内存与稳定性

- 分别记录 Tauri、WebView2、Java 进程的内存，不用总量掩盖单进程泄漏；
- 建立 2 小时课程阅读/编辑/运行循环，检查堆、DOM 节点、Monaco Model、监听器和子进程；
- 所有 Runner、导入、检索和 AI 流都支持取消、超时、资源上限和关闭清理。

## 10. 安全与隐私门禁

1. Tauri Capability 只授权当前窗口和命令需要的能力，不使用宽泛全局权限。
2. 所有 IPC 方法采用显式白名单和 DTO 校验；路径必须归一化并限制到用户授权范围。
3. Markdown、导入内容、模型输出和 Mermaid 均视为不可信；默认禁用原始 HTML、脚本、外部资源和插件执行。
4. 访问令牌仍只保存在当前程序内存或现有安全存储边界，不进入 Web 存储、日志或崩溃报告。
5. 学生、教师、管理员权限由 Java/服务端再次验证，隐藏按钮不等同于授权。
6. SQL、Runner、AI 和导入维持超时、取消、并发、大小和结果上限。
7. 发布包校验 Sidecar 哈希、SBOM、许可证、更新签名和依赖漏洞。

## 11. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| Java、TypeScript、Rust 三栈增加维护成本 | Rust 仅保留容器和权限；业务规则不进入 Rust；共享契约自动生成 |
| IPC DTO 膨胀或版本漂移 | schema-first、契约版本、兼容测试、分页和弃用周期 |
| WebView2 缺失或版本差异 | Alpha.1 验证 bootstrap/offline/fixed-runtime 三种模式并形成安装矩阵 |
| Web 技术带来 XSS 和资源耗尽 | 禁止原始 HTML/插件执行，净化 AST，限制节点、深度、公式、图表和资源大小 |
| 包体积因 Java runtime 与 WebView 增长 | 保留 jlink 精简运行时；分别记录在线与离线安装包；设 120% 预算 |
| 性能问题从 JavaFX 转移到 DOM/JS | 虚拟化、Worker、路由拆包、Long Task 门禁和真实知识库样本 |
| 一次性重写导致长期不可用 | 按工作区垂直切片；Alpha 保留 JavaFX 回退；Beta 前不删除旧界面 |
| 数据或升级不兼容 | 不改现有 schema 语义；历史数据矩阵、升级备份、失败自动回退 |

## 13. 版本门禁

- 顶层架构、信息架构和 IPC 主契约冻结；
- 2.3 核心功能已对齐，角色权限正确；
- 冻结性能预算全部通过；
- 历史数据、安装升级、离线和安全门禁通过；

### RC 准入

- 无阻断或高风险缺陷；
- 不再接受架构和大范围交互变更；
- 全量测试、长稳态、包体积、SBOM、签名和回退证据完整；
- JavaFX 移除与否基于回退证据决定，不以版本日期强行删除。

### 3.0 GA 完成定义

1. 用户无需理解底层架构即可完成选课、学习、练习、实验、反馈和同步。

5. 启动、交互、IPC、渲染、检索、内存、退出和包体积均有可复现证据且达到门禁。
