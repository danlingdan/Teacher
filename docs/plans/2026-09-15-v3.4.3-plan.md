## 1. 目标与范围

v3.4.3 定位为**知识与数据体验版本**：三块用户可见重做，一条新分发链路。不改 SQL 安全边界；IPC 合同保持 additive-within-v1（只加方法与字段，不删不改语义）。

现状盘点（调研结论，均以基线为准）：

- **检索课程知识无空库判断**：`KnowledgePage.tsx` 的搜索框（:195-228）、课程树、知识助教（:342-388）全部无条件渲染，仅文章列表处有空态文案（:269-273）。空库时输入≥2 字符显示「无匹配结果。」，用户无从知道是"库里没文档"。
- **知识与活动数据同源**：两页共用 `courseWorkspaceQuery`（`app/queries.ts:26`），后端 `HomeApiSection.courseWorkspace`（:73-82）把 courses（含 sections.activities）与 articles 混在一个 payload；KnowledgePage 靠前端自觉忽略 activities（KNW-1 注释 :234-236），数据层未切开。
- **连接表单全量铺开**：`DataSqlPage.tsx` ConnectionManager（:289-680）14 种方言字段平铺，GENERIC 的 JDBC URL/驱动类/驱动 JAR 与普通字段同级，5 个操作按钮；必填校验（:275-287）与「测试通过才能保存」（:325-348）的安全闸保留。
- **表结构无整体折叠、无索引**：SchemaPanel（:682-747）只有「标题+计数+筛选」→ 每表 `<details>` → 列平铺；后端 `JdbcDatabaseMetadataService.java`（:33-90）只读 getTables/getColumns/getPrimaryKeys，不读索引。
- **本地 RAG 管道现成**：markdown 导入 → SQLite 存储 + 800 字符切块（`SqliteKnowledgeService.java`）→ FTS5 + Ollama embedding（embeddinggemma）写本地 Lucene（`SqliteKnowledgeIndexService.java`）；Ollama 不可用时 FTS5 独立可用。导入入口仅教师手动（Obsidian 目录 / 单篇）。
- **云端有静态清单先例**：`GET /api/v1/app/update-manifest`（`SqlTeacherCloudServer.java:1001-1035`，env 指向签名 envelope 文件）；桌面调云走 `HttpCloudApiClient`（仅 HTTPS/loopback，默认 `https://api.sqlteacher.tech`）。
- **随包资源有先例**：`tauri.conf.json` resources 含 `sidecar/**/*`、`legal/**/*`；打包脚本构建期复制 legal 三件套。
- **迁移现状**：本地 `SqliteSchemaMigrator` 至 version 23；v20 的 `exercise_bank_state`（bank_version 字段）是"外部内容包状态表"的现成先例。

### 明确不做

- 不做分步向导式连接表单（用户已选单页智能默认）；不改「测试通过才能保存」安全闸与凭据内存暂存机制（`DatabaseCredentialSession`）。
- 不新增数据库方言、不改 14 种方言的 URL 构造与连接语义。
- bundle 不含预建向量：本地 embedding 模型（Ollama embeddinggemma）与云端（bge-small-zh，512 维）不同源，预建向量绑死模型；导入后走本地既有索引管道，Ollama 缺失时 fail-safe 降级 FTS5。
- 不做多知识库市场/订阅机制：v1 只支持单一官方 bundle（manifest 以 `bundleId` 字段预留扩展，不做多包管理 UI）。
- bundle 内容不进 Git（22 MiB 二进制 + 教材衍生内容）：仓库只存构建脚本、manifest 格式规范与文档；内容源在用户本机目录，构建期打 zip（参照 legal 的构建期复制先例）。
- 云端部署（上传 bundle、配置 env、Nginx）属生产操作，实施完成后另经用户授权按 `sqlteacher-cloud-operations` 技能执行，不在本计划的代码验收内。
- 不改课程活动（EditorPage/ActivityFlow）任何行为。
- 不删除既有 `knowledge.*` IPC 方法（additive-within-v1）。

### C. 官方课程知识库（OKB-1…7）——对应要求 3

- **OKB-1（P1）bundle 格式与构建脚本**：
  - 格式：zip = `manifest.json` + `docs/**` + `attachments/**`（图片，按文档相对路径组织）。manifest 字段：`bundleId`（v1 固定 `official-db-concepts`）、`version`（内容语义版本，首版 `1.0.0`）、`generatedAt`、`title`、`documents[]`（`id`（稳定 slug，更新时据此替换）、`path`、`title`、`sha256`、`attachments[]`（相对路径 + sha256））、`archiveSha256`（外层自校验）。文档格式 v1 仅 markdown，图片仅 png/jpg。图片处置口径已确认：**带图**（第 7 节确认记录 1）。
  - 构建脚本 `packaging/build-knowledge-bundle.ps1`：输入用户内容目录（参数化，默认指向用户 Obsidian 目录），输出 `target/knowledge/<bundleId>-<version>.zip` + 校验和；`docs/` 内 id 由脚本按目录结构生成稳定 slug（重跑同内容同 id）。产物不进 Git。
- **OKB-2（P1）Migration 24 与 bundle 状态**：本地 SQLite 新增 `knowledge_bundle_state`（bundle_id PK、version、source：builtin/cloud/manual、imported_at、archive_sha256），参照 v20 `exercise_bank_state` 先例；`course_knowledge_articles` additive 加 `bundle_id`、`bundle_doc_id` 两列（官方文档标记，用户文档为 NULL）——更新替换只认 `bundle_id` 匹配的文档，用户自有文档永不触碰。覆盖空库、v23 升级、重复启动、失败回滚、未来版本拒绝五类迁移测试。
- **OKB-3（P1）bundle 导入服务**：`application` 层新增导入契约（校验 manifest 与 zip 内每篇 sha256、拒绝超 20 MiB 单篇与非 md 格式、按 `bundle_doc_id` upsert——新版本对同 id 文档走既有 `revise` 语义、写入/更新 `knowledge_bundle_state`、触发既有 `rebuildPending` 索引管道）；`infrastructure` 实现解压与文件读取（zip slip 防护：条目路径规范化后必须落在解包根内）。导入为后台异步任务，UI 呈现加载/成功/失败三态；失败不落半状态（单事务或先校验后写入）。
  - 测试：导入成功、sha256 不符拒绝、zip slip 拒绝、更新替换官方文档且保留用户文档、Ollama 缺失降级 FTS5 不阻塞导入。
- **OKB-7（P1）图片存储与渲染链路**（口径 A 带图，第 7 节确认记录 1）：

  - 渲染：`KnowledgeRenderer.tsx` 解析 markdown 图片引用，经桥端点（additive，如 `knowledge.article.asset`，返回本地资产绝对路径或 base64，实施时按 Tauri asset 协议可用性定）解析为可显示 src；图片缺失/读取失败显示占位说明，不出现破图，不影响正文。
  - 资产端点做路径校验：仅允许返回 `knowledge-assets` 根内文件（防目录穿越），拒绝任意路径读取。
  - 测试：导入落盘、渲染解析、缺失占位、路径穿越拒绝；`KnowledgeRenderer` 图片用例。
- **OKB-4（P1）云端 manifest 与下载端点 + 桌面更新链路**：

  - 测试：首启导入、二次启动跳过、builtin 版本低于已装 cloud 版本时不回退（比较 version）、资源缺失静默跳过。
