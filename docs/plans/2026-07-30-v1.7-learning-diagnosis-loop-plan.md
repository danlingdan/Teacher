# SQLTeacher v1.7 学习诊断与个性化练习闭环计划

> 制定日期：2026-07-30
> 发布基线：`v1.6.1`
> 目标版本：`v1.7.0`
> 实施方式：单人、五阶段串行交付
> 版本定位：让题目、任务、学情、反馈与 AI 解释形成可追溯的教学闭环

## 1. 规划结论

v1.6.1 已具备题库、确定性评测、学习事件、学情统计、云端班级与任务、课程知识检索，以及统一的本地/网络 AI 工作区。当前主要缺口不是继续增加同级页面，而是这些能力之间缺少稳定、可解释的闭环：学生看到薄弱项后不能直接形成有顺序的练习队列，教师看到统计后也缺少“谁需要干预、为什么、下一步做什么”的工作入口。

v1.7.0 定位为“学习诊断与个性化练习闭环”。系统先由 Java 确定性规则计算知识点掌握快照和推荐原因，再将未完成任务、薄弱知识点、最近失败题目和教师反馈组合为学生学习队列；教师侧提供有权限边界的干预队列，可从证据进入学生记录、反馈草稿或任务操作。AI 只能解释已确定的事实、润色待审核反馈或提供提示草稿，不得决定分数、掌握度、推荐对象或自动发布操作。

当前 GitHub 仓库没有未关闭 Issue。本计划以 `v1.6.1` 的代码、300 项自动化测试和已发布能力为基线；后续新缺陷按 P0/P1 分级纳入，不在阶段中途无边界扩张范围。

## 2. 成功标准

| 指标 | v1.7.0 目标 |
|---|---|
| 诊断可复现 | 相同题目、尝试、任务与反馈数据生成相同掌握快照和原因码，不依赖 AI 随机输出。 |
| 学生学习队列 | 首页可展示 3～7 个按优先级排序的下一步行动，并可直接继续任务、重练题目或查看反馈。 |
| 教师干预队列 | 教师可按班级查看需要干预的学生/知识点、证据和建议动作，只能访问已授权班级。 |
| 解释透明 | 每条推荐展示来源、原因、更新时间和解除条件；用户可暂时忽略，但不能篡改原始评测事实。 |
| AI 可选 | Ollama、网络 Provider 均不可用时，诊断、排序、练习、评测和教师操作仍完整可用。 |
| 离线与同步 | 本地事件可离线形成个人诊断；云端数据恢复后可幂等同步，不重复制造推荐或干预项。 |
| 性能 | 5,000 条尝试、500 名学生的固定夹具中，单个学生诊断低于 500 ms，班级干预页低于 2 s。 |
| 隐私 | 推荐与诊断不新增明文凭据、完整 Prompt、数据库样本行或越权学生数据出站。 |

### 3.3 明确不纳入 v1.7

- AI 自动评分、自动调整确定性掌握度、自动选择受干预学生或自动发布反馈。
- 自治 Agent 自动执行 SQL、修改题库、创建正式任务或调用教师权限操作。
- 排行榜、竞赛、学生间比较、惩罚性预警或不可解释的黑盒风险分数。
- 基于敏感属性、身份标签或外部画像进行推荐。
- 新建独立 Web/移动端、短信/邮件推送、学校级多租户或第三方插件市场。
- 向量数据库、大规模 RAG、联网搜索或把完整学生记录发送给网络 AI。
- 新数据库方言、复杂考试监控、摄像头/屏幕监考或行为画像。

## 4. 核心设计原则

- **事实先于建议**：评测事实、任务状态和权限先确定，再生成推荐；AI 不参与事实计算。
- **原因码优先**：排序规则必须产生稳定原因码和证据引用，不能只输出无法解释的综合分。
- **少而可行动**：学生队列最多展示 7 项，优先给出可以立即执行的动作，避免制造信息焦虑。
- **教师在环**：干预项只是待处理工作，不是对学生的最终判断；反馈和任务发布始终人工确认。
- **权限随数据走**：教师只能查询当前授权课程/班级；学生只能看到自己的诊断、任务和反馈。
- **离线优先**：个人诊断从本地稳定事件生成；云端不可用不阻断练习、评测和本地刷新。
- **可重算而非神秘缓存**：派生诊断允许从事实表重建，缓存损坏不得破坏原始尝试和任务记录。
- **不增加 AI 信任**：无限模式、Provider 类型或教师身份都不能让 AI 自动执行或改变确定性结果。

## 5. 建议领域与应用契约

| 概念 | 职责 |
|---|---|
| `MasterySnapshot` | 某学生在一个知识点上的确定性掌握快照、证据窗口、版本和更新时间。 |
| `MasteryEvidence` | 引用题目、尝试、任务、错误类型或反馈状态，不保存无关敏感正文。 |
| `DiagnosisReasonCode` | 稳定原因码，例如 `REPEATED_FAILURE`、`HINT_DEPENDENCY`、`OVERDUE_TASK`、`STALE_PROGRESS`。 |
| `LearningAction` | 学生下一步动作：继续任务、重练题目、查看反馈、复习知识点或完成目标。 |
| `LearningQueueService` | 合并、排序、去重并限长学生行动队列。 |
| `InterventionCandidate` | 教师干预候选、证据摘要、优先级、处理状态和授权范围。 |
| `InterventionService` | 生成班级干预队列、标记状态并进入反馈/任务工作流。 |
| `DiagnosisPolicy` | 冻结时间窗口、最小证据量、权重、阈值和版本；可测试、不可由 AI 修改。 |

依赖方向继续保持：

```text
desktop -> application -> domain
infrastructure -> application/domain
```

诊断与队列服务不得依赖 JavaFX、HTTP 或具体 AI Provider。AI 解释只能消费已经脱敏、限长的诊断摘要。

## 6. 诊断与排序口径

### 6.1 掌握快照

首版采用透明的确定性规则，不引入机器学习模型：

- 证据窗口默认取最近 30 天和最近 20 次相关尝试，较近证据权重更高。
- 通过率、连续失败、错误类型重复、提示依赖、完成时间和任务逾期分别产生独立指标。
- 少于 3 次有效尝试时状态为 `INSUFFICIENT_EVIDENCE`，不生成“薄弱”结论。
- 掌握等级只使用 `UNKNOWN`、`NEEDS_PRACTICE`、`DEVELOPING`、`MASTERED` 四档。
- 题目或评测规则版本变化后，旧证据保留来源版本；必要时触发新策略版本重算。

### 6.2 学生队列优先顺序

1. 已发布且即将到期/逾期的任务。
2. 教师已发布但学生未查看的反馈。
3. 有足够证据的重复失败知识点。
4. 最近中断但未完成的练习。
5. 学习目标中的下一道合适题目。

同一任务或题目只出现一次；优先项完成、撤回、过期或证据不足后自动解除。排序必须稳定，分数相同时使用动作类型、更新时间和稳定 ID 作为次级顺序。

### 6.3 教师干预优先顺序

- 任务逾期且无有效提交。
- 同一知识点连续失败达到阈值。
- 多次使用提示仍未通过。
- 长时间无进展且存在未完成任务。
- 已提交但反馈尚未处理。

干预状态采用 `OPEN`、`ACKNOWLEDGED`、`RESOLVED`、`DISMISSED`；状态变化需记录操作者、时间和原因码。新证据可重新打开已解决项，但必须生成新的稳定周期 ID，不能静默覆盖历史。

## 7. 数据与隐私策略

- 原始事实继续使用现有尝试、学习事件、任务快照、提交和反馈记录。
- `mastery_snapshot` 只保存派生值、策略版本、证据摘要哈希和更新时间；可删除并重算。
- `learning_action_state` 保存用户忽略、开始和完成状态，不复制完整题目或 SQL。
- `intervention_state` 保存班级、学生、原因码、处理状态和审计字段，不保存 AI Prompt。
- 网络 AI 仅可接收知识点名称、原因码、聚合指标、授权反馈风格和限长证据摘要。
- 学生邮箱、令牌、连接凭据、数据库样本行、完整 SQL 历史和其他学生数据默认禁止进入 Prompt。
- CSV 导出采用字段白名单，教师必须先选择授权班级；导出行为写入审计。

## 8. 五阶段单人串行计划

| 阶段 | 唯一主目标 | 主要工作 | 阶段门禁 |
|---|---|---|---|
| 阶段 1 | 冻结诊断契约 | 固定指标、原因码、证据、策略版本、权限矩阵、数据迁移和性能夹具；不改 UI。 | 同一夹具结果可复现；权限与隐私威胁模型完成；现有 300 项测试继续通过。 |
| 阶段 2 | 交付个人诊断 | 实现快照计算、重算、缓存恢复、学生学习队列和服务级测试。 | 无 AI/无网络可运行；数据不足不误判；5,000 次尝试性能达标。 |
| 阶段 3 | 完成学生闭环 | 在首页/进度页接入队列、继续任务/题目/反馈入口和完成后刷新。 | 关键动作不超过 2 次主要操作；重复点击、页面切换和旧异步结果不污染状态。 |
| 阶段 4 | 完成教师闭环 | 实现授权班级干预队列、证据详情、处理状态、反馈草稿和任务草稿联动。 | 越权访问被拒绝；AI 不改变事实；发布仍需确认；离线/重试幂等。 |
| 阶段 5 | 收敛与发布 | 完成 P1 取舍、性能/隐私/恢复测试、主题与键盘资源检查、安装包、手册和 Release。 | P0 缺陷为 0；全部门禁通过后才创建 `v1.7.0` 标签。 |

每次只推进一个纵向闭环。修改诊断口径、迁移、权限或同步逻辑时先运行聚焦测试；完成一个阶段或累计高风险变更后运行完整 `mvn test`。

## 9. 必测场景

| 场景 | 正常路径 | 必测边界 |
|---|---|---|
| 掌握诊断 | 多次尝试形成稳定快照和原因码。 | 数据不足、重复事件、乱序时间、题目版本变化、提示后通过、时区边界。 |
| 学习队列 | 合并任务、薄弱项、反馈并稳定排序。 | 同题多来源、撤回任务、过期任务、已忽略项、全部完成、快速连续刷新。 |
| 继续学习 | 从队列进入目标并在完成后刷新。 | 页面缓存、任务被撤回、题目停用、会话中断、数据库恢复、离线。 |
| 教师干预 | 按授权班级查看证据并处理。 | 越权班级、学生转班、重复处理、新证据重开、并发版本冲突。 |
| AI 解释 | 基于确定性摘要生成待审核文本。 | Provider 离线、坏 JSON、Prompt 注入、AI 改分、泄露他人数据、取消与超时。 |
| 同步 | 本地事件上传后云端诊断一致。 | 重复上传、部分失败、乱序、网络恢复、旧设备事件、快照重建。 |
| 导出 | 教师导出授权范围的诊断摘要。 | 大班级、CSV 注入、敏感字段、空结果、导出取消和审计失败。 |

## 10. 自动化与性能测试策略

### 10.1 必增测试

- 诊断策略：四档状态、最小证据量、时间衰减、原因码和稳定排序。
- 幂等：重复/乱序事件、重复同步、重复任务和重算结果一致。
- 权限：学生只读本人；教师只读授权班级；管理员能力不隐式下放。
- 学生队列：限长、去重、解除条件、忽略状态和继续学习路由。
- 教师队列：筛选、处理状态、新证据重开、反馈/任务草稿联动。
- AI 边界：确定性事实不可修改，网络上下文字段白名单，离线模板降级。
- 迁移与恢复：从 v1.6.1 升级、重复迁移、失败回滚、派生表删除重建。
- 性能：5,000 次尝试、500 名学生、100 道题、30 个知识点固定夹具。
- CSV：公式注入转义、字段白名单、稳定列序和 UTF-8。
- UI 逻辑：加载/空态/失败/过期/刷新、页面离开和旧异步结果丢弃。

### 10.2 验证节奏

```powershell
mvn test
.\packaging\package-stage1.ps1
```

- 诊断策略和 schema 完成后运行完整回归。
- 学生闭环完成后运行完整回归与性能夹具。
- 教师权限、同步或批量操作变更后运行完整回归。
- 发布候选先完成真实 Ollama/网络 AI 的可选解释测试，再打包。
- JavaFX 人工视觉和流程验收继续由发布负责人使用 `target/installer` 中的正式候选包完成。

## 11. 发布门禁

- P0 工作项全部完成，P0 缺陷为 0；P1 裁剪有明确记录。
- 从 v1.6.1 用户数据升级成功，失败可回滚，原始尝试、任务、反馈和凭据不丢失。
- 同一事实夹具在重复计算、重启、离线和同步后得到相同诊断结论。
- 学生与教师权限测试覆盖本人、授权班级、越权和角色切换。
- Ollama/网络 AI 不可用时，确定性诊断和完整教学闭环仍通过。
- 日志、诊断表、CSV、备份、ZIP、EXE 和 app-image 不含明文凭据、完整 Prompt 或越权学生数据。
- 性能夹具达到既定阈值，未出现无界查询、无界缓存或 JavaFX 线程阻塞。
- 亮色/深色、低分辨率、125%/150% 缩放和键盘主路径由发布负责人完成安装包人工验收。
- `target/installer` 只保留 v1.7.0 EXE、ZIP、app-image 和当前双条目 `SHA256SUMS.txt`。
- `main`、`v1.7.0` 标签、GitHub Actions 和公开 Release 三项资产状态一致。

## 12. 风险与裁剪顺序

| 风险 | 应对 | 工期不足时的裁剪 |
|---|---|---|
| 诊断规则被误解为学生标签 | 展示证据、数据量、更新时间和解除条件；使用“需要练习”而非能力定性。 | 裁剪综合分，不裁剪原因码和证据。 |
| 学生/班级数据越权 | 服务端与本地应用层双重授权，查询按稳定 ID 和当前成员关系限制。 | 裁剪批量操作，不裁剪权限验证。 |
| 推荐过多造成焦虑 | 队列限长、可忽略、优先行动而非告警；数据不足不下结论。 | 裁剪学习目标，不裁剪限长和解除条件。 |
| AI 改写确定性事实 | 将事实与草稿分区，Prompt 固定事实，保存前再次比对。 | 裁剪 AI 解释，不裁剪规则模板。 |
| 云端同步使结果不稳定 | 原始事实幂等、策略版本化、派生数据可重算。 | 裁剪跨设备队列状态，不裁剪事实同步幂等。 |
| 大班级性能退化 | 批量聚合、索引、分页、限长队列和固定性能夹具。 | 裁剪复杂筛选，不裁剪分页与上限。 |

裁剪顺序：批量反馈 → 诊断 CSV → 学习目标 → AI 个性化措辞 → 跨设备忽略状态 → 高级筛选。确定性诊断、原因码、权限、学生队列、教师干预、离线降级、幂等、迁移恢复和发布安全门禁不可裁剪。
