## 1. 目标与范围

v3.7.0 定位为**教师端学情反馈版本**：把教师能看到的学生信息从"作业提交的布尔结果（通过/失败/哈希）"
升级为"学习过程记录"——学生执行了什么 SQL、哪题错在哪、AI 生成与提问、知识检索与阅读、掌握度变化、
每日活跃，全部结构化上报云端，教师在班级与云端页按班级、按学生逐条查看。教师从"只看结果"变为
"看到过程"，干预依据从状态码升级为证据。

安全与原则边界不动：排行榜/监考/行为画像继续排除；AI 只起草、教师在环；权限随数据走（教师只见
授权班级）；离线优先、本地学习不依赖网络、同步不隐式联网；明细读取全部落审计。

- 角色与班级模型完备：云端 `users`/`user_roles`（ADMIN/TEACHER/STUDENT，注册默认 STUDENT）、

### 明确不做（红线延续，历代计划一致）

- 实时推送（WebSocket/SSE）、课堂投影模式、教师实时协同视图、课堂统计大屏——v3.5.0 计划第 36 行
  已两次书面"另行立项"，本版仍不做；教师看到的数据以学生同步为准。
- 排行榜、班级排名、同伴比较、监考、键盘/屏幕监控、行为画像、AI 自动评分/自动发布——v1.7/v1.9
  确立的排除项不变；每日活跃只记天级累计分钟数，不记录操作级监控。
- 多教师协作、角色权限模型变更（v3.3 计划既定边界）；教师查看非本班学生的任何数据（服务端
  `requireTeacher` + 班级成员校验强制）。
- AI 助教**回答**全文上传（只上传提问摘要与元数据）；SQL 执行**结果集数据**上传（只传行数/列数
  元数据与截断文本）。
- 改变离线优先原则：本地学习流程继续完全不依赖网络；网络失败一律降级保留本地（既有
  `SyncStatus` 分类与作业离线队列沿用）。

2. **云端 `sync_events` 保留期默认值**：**已执行**——默认 180 天，服务端每日自动清理，

## 2. 任务清单

### A. 学生端数据与上传（TFB-D1…D4）——第一批

- **TFB-D1（P0）上传载荷白名单脱敏**：`DefaultCloudLearningSyncService` 上传前按事件类型维护
  attributes 白名单，剥离 `_desktop_owner_id`（`LearningEventOwnerProvider.OWNER_ATTRIBUTE`）等
  本地内部字段；服务端 `CloudClassroomStore.upload` 侧对入库 payload 做二次收敛（纵深防御）。
  白名单常量集中定义并写入隐私声明（TFB-C4）。
  - 测试：逐事件类型白名单过滤用例；未知字段剥离用例；服务端二次收敛用例。
- **TFB-D2（P0）既有事件证据丰富化（additive）**：
  - `SQL_EXECUTION`：attributes 增 `sql_text`（截断 4KB）、`duration_ms`、`row_count`、`dialect`。
  - `EXERCISE_PASSED/FAILED/ATTEMPT`：增 `exercise_id`、`score`、`error_code`、错误消息摘要、
    `sql_text` 摘要（截断）；`EXERCISE_HINT_USED` 增 `exercise_id`。
  - `AI_SQL_GENERATED`：增生成 SQL 文本摘要（截断）与 `generated_event_id` 关联标记，执行后的
    `SQL_EXECUTION` 携带同 ID 串联"AI 生成 → 是否执行 → 执行结果"。
  - `KNOWLEDGE_SEARCHED`：增命中课程/章节数元数据（不传检索词全文，仅摘要）。
  - 截断策略统一常量 + 单测；单事件逼近 16KB 上限时自动降级为仅元数据（事件不丢）。
  - 测试：各事件字段映射与截断用例；超限降级用例；桥契约 additive 一致性用例。
- **TFB-D3（P1）新事件类型**（`LearningEventType` additive 枚举 + 写入点）：
  - `MASTERY_CHANGED`：`JdbcLearningDiagnosisService` 写 `mastery_snapshot` 时同步记录
    （knowledge_point、level、mastery_percent、attempts、passes、failures）；教师端按每知识点
    最新事件重建掌握度状态，复用 `sync_events` 管道，不新增端点。
  - `DAILY_ACTIVE`：每日一条，attributes 含本地累计 `active_minutes`（前台定时 flush，非键盘/
    鼠标监控）；退出未 flush 时次日补记，崩溃丢失可接受（天级数据）。
  - `KNOWLEDGE_ARTICLE_READ`：阅读进度跨阈值（如 25/50/75/100%）时记录 `article_id + progress_percent`，
    每文章每版本限频，防刷屏。
  - `AI_ASSISTANT_ASKED`：`ai.knowledge.ask` 落事件（问题文本按决策点 1 处理 + 检索命中数 +
    结果码；不落回答全文）。
  - 测试：各写入点触发条件与限频用例；旧服务端收到新事件类型的兼容矩阵（云端先部署场景）。
- **TFB-D4（P2，可裁剪）`sql_history` 补 `owner` 列**：additive 迁移，旧行标 legacy 仅对当前
  账号可见，修复本机多账号执行历史串号；写入点带 owner。与上报主线无耦合。
  - 测试：迁移幂等用例；多账号隔离用例。

  CSV 导出的审计先例）。学生本人 `GET /sync/events` 语义不变（仅本人）。
  - 测试：越权矩阵（非教师/他班教师/非本班学生/管理员）用例；分页与过滤用例；审计落行用例。

## 3. 风险与边界

- **载荷上限**：单条 16KB、请求 1MB、Nginx `client_max_body_size 2m`——所有新增文本字段必须
  截断常量化并测试；超限降级为元数据保底，事件本身不丢。
- **云端先行**：新事件类型与新端点要求服务端先于（或同批）客户端部署；旧客户端 + 新服务端
  必须 additive 兼容（既有 `sync/events` 幂等与回拉语义不破坏）。
- **schema 迁移**：云端 `CloudSchemaMigrator` 新版本与本地 `SqliteSchemaMigrator` additive 迁移
  均沿用 fail-closed 校验与升级前自动备份；迁移失败保留旧路径可检索/可学习。
- **隐私与审计**：白名单是唯一上传边界，服务端二次收敛；教师明细读取与导出全部落
  `export_audit`；教师权限严格限定本班成员；学生侧有暂停开关与透明视图。
- **容量治理先行**：S4（频次配额、容量上限、retention 默认值）必须不晚于 D 批扩大上报的规模
  上线，避免 `sync_events` 被动膨胀。
- **桥契约**：`desktop.bridge` 全部 additive 演进，契约测试与前端类型同 change 提交；不改既有
  事件语义（旧事件字段只增不改）。
- **AI 边界不动**：AI 不碰 JDBC、生成 SQL 仍走 Java 强制路径；本版仅把既有安全事件的证据
  （拦截、确认、生成）带得更全，不新增任何 AI 决策权。
