## 1. 目标、边界与成功定义

用户用一段自然语言需求（如"设计一个学生选课系统，学生可选修多门课程，每门课程可被多名学生选修，记录成绩"）
生成一张**国内教材风格（陈氏记号）的 E-R 图**：矩形实体、椭圆属性（主码下划线）、菱形联系、连线上标注
1/1/n/m，可缩放、拖拽微调布局，并可导出 PNG/SVG 用于课件。

**决策变更声明**：[v3.5.0 计划](2026-09-16-v3.5.0-sql-teaching-experience-plan.md)曾裁定"不做 ER 图
编辑/建模工具，只做从外键元数据生成的只读简图"。本计划部分推翻该裁定：AI 生成使建模工具的教学价值/
成本比发生变化，本版交付"AI 生成 + 查看微调"，仍不做完整手工编辑器。v3.5.0 文档保持历史原样，数据页
只读关系简图（外键驱动）继续保留，与本功能互补。

边界：

- 不做手工增删改图元的编辑器；不做 ER→建表 SQL；不做 AI 概念模型与实际库 schema 的对比视图；
  不做局部 E-R 分步合并。
- 不新增云端端点：仅桌面端本地 AI 通道（与 NL2SQL 相同走 sidecar IPC），`com.sqlteacher.server` 不动。
- 不改 SQL 安全路径、风险分析、NL2SQL 行为与 AI 供应商切换语义（`SwitchableAiModelProvider` 的
  显式回落语义保持）。
- 不做本地确定性 E-R 兜底、网络 AI 失败不自动回落本地模型（与 v3.10.0 已声明口径一致）。
- 记号渲染集中在一个渲染模块中实现，便于后续按教材版本微调。

成功定义：输入教材典型需求样例（学生选课、图书借阅、供应者-项目-零件）能生成记号正确、布局可读的
E-R 图；AI 未配置/失败/输出不合规时给出明确中文提示与下一步引导；960×640 与深色模式可用；
全流程离线可用（AI 为本地 Ollama 时）。

## 3. 记号规范（陈氏记号，v3.11 全集）

| 概念 | 图形 | 模型字段 |
| --- | --- | --- |
| 实体 | 矩形 | `entities[]` |
| 弱实体 | 双线矩形 | `entity.weak = true` |
| 属性 | 椭圆 | `attributes[].name` |
| 主码属性 | 属性名加下划线 | `attribute.key = true` |
| 复合属性 | 椭圆 + 子属性子椭圆 | `attribute.composite[]` |
| 多值属性 | 双椭圆 | `attribute.multivalued = true` |
| 派生属性 | 虚线椭圆 | `attribute.derived = true` |
| 联系 | 菱形，连实体直线，线旁标 1/n/m | `relationships[]` + `members[].cardinality` |
| 依赖联系（弱） | 双菱形，弱实体侧双线 | `relationship.identifying = true` |
| 全参与约束 | 实体—联系双线 | `member.total = true` |
| 联系属性 | 椭圆挂菱形 | `relationship.attributes[]` |
| 多元联系 | 一菱形连 ≥2 实体 | `members` 数量 2–4 |
| 概括/特化 | 三角形（标 ISA 或自定义名），超类/子类直线 | `hierarchies[]` |

渲染风格：直线连线（教材风格，不用正交折线）、黑白为主淡色填充、中文字体继承应用、深色模式可读。
主码下划线用 SVG `<tspan text-decoration="underline">` 实现（canvas 方案无法做部分下划线，是弃用
Cytoscape 的原因之一）。

## 4. 中间契约（冻结，四端以此为准）

IPC 方法：`ai.modeling.er.generate`（contractVersion 不变，仍为 `3.0-v1`）。

请求参数：`{ "requirement": string }`——必填，trim 后非空，≤2000 字符（桥接层校验）。

响应：

```json
{
  "status": "OK | MODEL_UNAVAILABLE | PROVIDER_ERROR | PROMPT_ERROR | PARSE_ERROR | VALIDATION_FAILED",
  "model": "ollama:qwen2.5:7b",
  "promptVersion": "er-modeling-v1",
  "erModel": { "...见下，失败时为 null..." : null },
  "errors": ["校验失败原因列表，仅失败态非空"],
  "message": "面向用户的中文摘要（脱敏，不含原始需求全文）"
}
```

`erModel` 结构：

```json
{
  "title": "学生选课系统",
  "explanation": "≤300 字的建模思路说明",
  "entities": [
    { "id": "student", "name": "学生", "weak": false,
      "attributes": [
        { "name": "学号", "key": true,
          "composite": [], "multivalued": false, "derived": false },
        { "name": "住址", "composite": ["省", "市"] },
        { "name": "电话", "multivalued": true }
      ] }
  ],
  "relationships": [
    { "id": "elective", "name": "选修", "identifying": false,
      "members": [
        { "entity": "student", "cardinality": "1", "total": true },
        { "entity": "course", "cardinality": "n", "total": false }
      ],
      "attributes": [ { "name": "成绩" } ] }
  ],
  "hierarchies": [
    { "id": "h_person", "name": "ISA", "superclass": "person", "subclasses": ["undergraduate"] }
  ]
}
```

解析宽容、校验严格：缺省布尔字段按 false、缺省数组按空补齐；随后全部走确定性校验。

### 校验规则（Java 确定性执行，AI 输出一律不可信）

- 规模上限：实体 ≤16；每实体属性 ≤12；复合子属性 ≤4；联系 ≤24；联系成员 2–4；联系属性 ≤6；
  层级 ≤8；每层级子类 ≤6。
- `id`：`[a-z0-9_]{1,40}`，全局唯一；`name`：trim 后非空、≤20 字符，实体间唯一、联系间唯一，
  属性在所属实体/联系内唯一；剥离控制字符。
- `cardinality` 白名单 `{1, n, m}`（小写）。
- 引用完整性：`members[].entity`、`hierarchies.superclass/subclasses` 必须引用已声明实体 id。
- `identifying = true` 的联系必须恰好 2 个成员，其一为弱实体，另一成员（拥有者）`cardinality = "1"`；
  `weak = true` 的实体必须参与至少一个 identifying 联系。
- 联系属性不得声明 `key = true`。
- 层级：`subclasses` ≥1；同一实体至多作为一个层级的子类（教材 ISA 为树形）。
- 失败聚合返回全部错误（不首错即断），供修复重试与用户提示。

### Fail-safe 与重试

- 状态语义对齐 NL2SQL：模型未启用 → `MODEL_UNAVAILABLE`（不调 Provider）；Provider 异常/超时 →
  `PROVIDER_ERROR`；提示词准备失败 → `PROMPT_ERROR`；JSON 解析失败 → `PARSE_ERROR`；校验失败 →
  `VALIDATION_FAILED`（附 errors）。任何失败不抛异常穿透到 UI。
- `PARSE_ERROR` 与 `VALIDATION_FAILED` 允许**一次**修复重试（把错误列表回灌提示词），重试仍失败则
  返回失败态；重试次数计入事件明细。
- 事件记录沿用 `LearningEventService` 既有模式（分类、状态、耗时、错误码，不记录需求原文）。

## 6. 安全与隐私

- AI 输出不可信：Java 侧聚合校验后才出桥；前端纯映射渲染，文本走 React 转义，禁 raw HTML 注入。
- 需求文本属用户输入：≤2000 字符硬上限、控制字符剥离；提示词中显式抗注入声明；日志与学习事件
  不记录需求原文与模型输出全文（仅状态、错误码、耗时）。
- 密钥与连接信息零接触（本功能不读数据库凭据）；导出图像仅写用户选择的位置。
- 全程无 SQL 执行、无 JDBC 面；不引入遥测与外部服务。

## 8. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| elk 对"属性环绕实体"布局质量不稳 | 算法可切换（layered/force/stress），退化为属性极坐标摆放松绑到 owner |

| AI 输出不稳定 | JSON mode + 低温 + 一次修复重试 + 聚合错误回灌 |
