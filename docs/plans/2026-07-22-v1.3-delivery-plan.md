>

> 版本定位：教学任务闭环与运维自动化版

## 1. 迭代目标

v1.3 不扩大为完整在线考试或学校管理平台，而是在 v1.2 已具备账号、班级、任务、同步和统计能力的基础上，补齐“教师布置任务 → 学生提交 → 服务端确认 → 教师按任务分析 → 管理员可运维”的真实教学闭环。

本版本完成后，任务不再只是班级公告，而是能够关联题目、学生提交和确定性判题结果；教师可按任务、学生和时间查看完成情况；管理员可在不接触密码、令牌和 API Key 的前提下处理账号、审计、数据保留与服务状态；证书续期、备份、恢复和故障告警形成可重复的自动化流程。

### 明确不纳入 v1.3

- 完整在线考试、监考、防作弊、排行榜、竞赛、聊天和通知推送平台。
- 多学校计费、多租户自助开通、复杂组织架构、采购流程和单点登录。
- PostgreSQL、SQL Server、Oracle 等新数据库及其完整方言支持。
- AI 自动执行 SQL、AI 决定最终判题、自治 Agent 或让模型直接访问 JDBC。
- 云端托管用户数据库密码、网络 AI API Key、本地数据库文件或未经授权的课程原文。
- 移动端、Web 学生端和安装器代码签名采购；有明确需求后单独立项。

## 3. 关键设计原则

- **确定性判题是唯一成绩依据**：AI 可解释错误或生成草案，但提交结果必须来自 Java 侧规则、隔离数据集和确定性结果比较。
- **服务端时间与状态为准**：提交资格、截止时间、任务状态和权限由服务端判定；客户端时间只作为诊断元数据。
- **幂等优先**：每次提交携带稳定操作 ID；网络重试、应用重启和重复点击只能产生一条逻辑提交。
- **业务逻辑不进入 JavaFX 控制器**：任务提交、冲突处理、统计筛选和管理员操作通过 application 服务编排，UI 只负责输入、状态和展示。
- **账号禁用立即生效**：禁用账号必须同时撤销其访问令牌和刷新令牌；本地数据保留，重新授权前不能访问云端资源。
- **导出与审计最小化**：导出仅含当前教师被授权班级的必要教学字段，继续防止 CSV 公式注入；审计不记录密码、令牌、API Key 或完整原始 SQL。
- **运维自动化可验证**：续期、备份、清理、迁移和回滚都必须有 dry-run 或隔离演练，不依赖仅存在于个人电脑的手工步骤。
- **本地优先不变**：云端中断时，自由 SQL、隔离练习、确定性判题、本地统计和知识检索继续可用；待提交数据进入本地队列。

## 5. 功能验收矩阵

| 功能 | 正常场景 | 失败与边界 | 权限与安全 |
|---|---|---|---|
| 任务草稿与复制 | 教师保存草稿、复制、编辑并发布。 | 标题为空、截止时间无效、并发编辑和重复发布有明确反馈。 | 草稿仅本班教师/管理员可见，学生永远不可见。 |
| 学生提交 | 学生从所属任务提交确定性判题结果并查看最终状态。 | 断网、超时、重复点击、服务重启后不丢失且不重复。 | 服务端校验成员、任务状态、截止时间和操作 ID。 |
| 截止与撤回 | 截止前允许提交，截止后显示只读结果；撤回立即停止新提交。 | 客户端改时间、旧缓存和离线迟到提交不能绕过规则。 | 以服务端时间为准，拒绝结果可审计但不泄露其他资源。 |
| 学情筛选 | 教师按任务、状态和时间查看统计并导出。 | 空结果、无效范围、大数据分页和导出失败可理解。 | 查询和导出都强制当前教师班级范围，字段使用白名单。 |
| 账号禁用 | 管理员禁用账号后全部会话失效，恢复后需重新登录。 | 重复禁用/恢复幂等；不能禁用最后一个有效管理员。 | 只存操作者、目标账号、原因、时间和结果，不存凭据。 |
| 数据清理 | 管理员预览保留期影响范围，确认后执行并查看审计。 | 备份失败、范围过大或并发同步时停止清理。 | 默认软删除或可恢复窗口；不可恢复操作需明确二次确认。 |
| 证书与备份 | 定时续期、Nginx reload、每日备份和周期恢复演练。 | 续期/备份失败触发告警且不删除最后一份有效数据。 | DNS 凭据最小权限、受限文件保存，不进入 Git 和日志。 |

## 6. 数据与接口演进

### 6.1 建议数据模型

| 数据域 | 最小增量 | 关键约束 |
|---|---|---|
| `class_assignments` | `version`、`published_at`、复制来源、可选描述。 | 版本单调递增；状态转换和截止时间由服务端校验。 |
| `assignment_submissions` | 提交 ID、操作 ID、任务/用户、尝试号、判定摘要、提交时间、状态。 | `(user_id, operation_id)` 唯一；不保存数据库密码或完整连接信息。 |
| `admin_audit` | 操作者、动作、目标、结果、原因、关联 ID、时间。 | 不记录认证头、令牌、密码、API Key 或敏感请求体。 |
| `retention_jobs` | 数据类别、截止时间、预览数量、执行状态、审计 ID。 | 执行前必须有可用备份；失败可重试且不扩大范围。 |
| 本地待提交队列 | 操作 ID、任务 ID、最小判定摘要、重试状态、下次重试时间。 | 按账号隔离；登出不删除，其他账号不可读取或上传。 |

### 6.2 API 原则

- 修改任务必须提交当前 `version`；冲突返回稳定错误码及最新安全快照。
- 提交接口接收确定性判题摘要和稳定操作 ID，不接收任意可执行 SQL 指令供服务端执行。
- 统计与导出使用同一筛选 DTO 和服务端查询口径，避免页面数字与 CSV 不一致。
- 管理接口单独校验管理员角色，并对禁用、恢复、撤销和清理建立不可省略的审计记录。
- 分页接口限制页大小并提供稳定排序；导出采用后台生成或流式响应，避免占满服务器内存。
- 错误响应只返回稳定错误码、关联 ID 和面向用户的消息，不暴露数据库结构或堆栈。

## 9. 风险与裁剪顺序

| 风险 | 应对 | 工期不足时的裁剪 |
|---|---|---|
| DNS 凭据权限过大或续期仍失败 | 创建仅限目标域名解析记录的 RAM 用户，隔离凭据并演练轮换。 | 不裁剪；证书门禁未通过则不得发布。 |
| 提交模型与本地事件重复计数 | 将“练习事件”和“正式提交”分域，以操作 ID 和任务 ID 建立唯一约束。 | 保留正式提交与幂等；裁剪多次提交历史展示。 |
| 多教师并发覆盖任务 | 使用版本号和冲突响应，不采用最后写入获胜。 | 不裁剪并发保护；裁剪批量编辑。 |
| 大班级统计拖慢服务 | 服务端分页、索引、限定范围和流式导出，建立性能基线。 | 保留任务级统计；裁剪复杂组合维度和图表美化。 |
| 管理员误禁用或误清理 | 最后管理员保护、影响预览、二次确认、审计和可恢复窗口。 | 保留账号禁用与会话撤销；裁剪桌面审计高级筛选。 |
| AI Provider 差异扩大工作量 | 维持 OpenAI-compatible 边界并用预检适配差异。 | 首先裁剪 Provider 预设数量，不影响提交和判题主流程。 |

裁剪顺序：应用内到期提示 → Provider 预设 → 图表美化 → 高级审计筛选 → 任务批量操作。证书续期、提交幂等、服务端截止规则、权限、备份恢复和数据最小化不可裁剪。
