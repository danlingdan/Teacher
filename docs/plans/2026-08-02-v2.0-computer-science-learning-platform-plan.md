# SQLTeacher v2.0 计算机专业学习平台总计划

> - 制定日期：2026-08-02
> - 发布基线：`v1.11.5` / `90cf8de`，当前 `main` 为 `1.11.5`
> - 目标版本：`v2.0.0`
> - 发布节奏：`Alpha → Beta → RC → GA`
> - 实施方式：单人、直接在 `main` 串行开发，以功能开关、数据库/API 能力协商和预发布标签隔离未完成能力
> - 版本定位：从安全、可验证的 SQL 教学软件升级为本地优先、可验证的计算机专业学习 IDE

## 1. 规划结论

v1.11.5 已形成 SQL 练习、确定性评测、学习事件、知识点诊断、学生学习队列、教师干预、课程知识库、RAG、班级任务、云端同步、账号治理和 Windows 正式发布能力。v2.0 不废弃这些资产，而是把其中可复用的“学习—练习—评价—诊断—反馈”闭环抽象为通用学习平台内核，使 SQL 成为数据管理课程中的一种学习活动。

v2.0 同时推进两条主线：

1. **产品升级**：引入计算机专业课程图谱、通用学习活动、编程与可视化实验、项目制学习、跨课程诊断、教师课程创作和学习成果档案。
2. **桌面重构**：保留 Java 21、JavaFX 21、FXML/CSS、Spring Context、Maven 和现有分层，重构应用壳、导航、页面模板、设计系统和复杂实验工作区。

本计划不再以“首发最小范围”裁剪功能。所有列出的工作都属于 v2.0 系列目标，通过多个 Alpha 持续扩展，通过多个 Beta 完成功能、内容和兼容性收敛，通过一个或多个 RC 完成正式发布门禁。若某项在 Beta 冻结前经安全、许可、可用性或工程验证证明不可行，必须在计划进度记录中写明证据和替代方案，不能静默消失。

计划采用里程碑驱动，不预先承诺固定发布日期。版本阶段只表示成熟度，不表示并行团队；仍按单人纵向闭环逐项完成。

## 2. 产品定位与成功标准

### 2.1 产品定位

> 2026-08-09 alpha.4 决策：原计划把产品限定为 IDE 与 LMS 之间的学习编排层；根据实际编程课程需求，
> 现调整为“计算机专业学习 IDE”。它提供真实本地编辑、工具链、终端和联网运行，同时保留课程、评价、
> 诊断和教师闭环；仍不追求替代所有通用 IDE、在线判题网站、LMS 或大学全部课程。

v2.0 的目标是把 IDE 工作流与可验证学习闭环组合起来：

```text
课程知识与学习成果
        ↓
可交互、可运行、可验证的学习活动
        ↓
确定性评价与结构化失败原因
        ↓
跨活动、跨课程的掌握证据和下一步行动
        ↓
教师反馈、任务、干预和项目评价
```

目标用户保持明确：

- 主要学习者：高校计算机类专业学生和自学者；
- 主要教学者：课程教师、实验教师和助教；
- 主要运行环境：Windows 10/11，本地优先，云端增强；
- 核心差异：离线可用、评价可复现、诊断可解释、AI 不掌握最终决定权、教学数据边界清晰。

### 2.2 v2.0 GA 成功标准

## 3. 课程与能力框架

v2.0 参考 ACM/IEEE-CS/AAAI CS2023 知识领域组织平台能力，但不把知识领域机械映射为软件页面。课程可以跨知识领域，知识点可以建立前置、关联和迁移关系。

### 3.1 内置学习路径

| 编号 | 学习路径 | 主要活动 |
| --- | --- | --- |
| CUR-01 | 数据管理 | 保留 SQL、关系模型、规范化、索引、事务、查询优化和数据库安全实验。 |
| CUR-02 | 程序设计基础 | Java、Python、C 的表达式、控制流、函数、数据结构、异常、文件和测试基础。 |
| CUR-03 | 数据结构与算法 | 复杂度、线性结构、树、堆、哈希、排序、搜索、图和经典算法的跟踪与可视化实验。 |
| CUR-04 | 计算机系统 | 数据表示、数字逻辑、简化 CPU、指令周期、汇编、存储层次、Cache 和虚拟内存。 |
| CUR-05 | 操作系统 | 进程/线程、调度、同步、死锁、内存管理、文件系统和 I/O 模拟。 |
| CUR-06 | 计算机网络 | 编址与子网、分层封装、交换、路由、TCP/UDP、DNS/HTTP 和受控报文流程模拟。 |
| CUR-07 | 软件工程 | Git、测试、构建、调试、需求、设计、代码审查、CI、项目协作和维护。 |
| CUR-08 | 程序设计语言与编译 | 范式、类型、作用域、运行时、有限自动机、词法、语法树、解释和简单代码生成。 |
| CUR-09 | 离散数学与理论基础 | 集合、逻辑、关系、组合、图、证明、自动机和可计算性入门。 |
| CUR-10 | AI 与数据基础 | 搜索、分类、聚类、评价指标、过拟合、数据偏差、Prompt 边界和负责任 AI。 |
| CUR-11 | 计算机安全基础 | 输入验证、权限、密码学概念、安全编码、威胁建模和隔离式防御实验。 |
| CUR-12 | 综合项目 | 跨课程项目、里程碑、自动测试、教师量规、反思记录和成果档案。 |

每条路径至少包含课程地图、学习成果、前置知识、知识内容、分层练习、一个综合实验、确定性评价证据和教师任务模板。内置内容必须记录来源、许可、版本和作者信息；不得把未经授权的教材或题库打包进发行物。

### 3.2 跨课程连接

- B+ 树：数据结构 ↔ 数据库索引 ↔ 存储性能；
- 图与最短路径：算法 ↔ 网络路由 ↔ AI 搜索；
- 并发：程序设计 ↔ 操作系统同步 ↔ 数据库事务 ↔ 分布式系统；
- 自动机：离散数学 ↔ 编译原理 ↔ 正则表达式；
- 数据表示：离散数学 ↔ 体系结构 ↔ 网络协议 ↔ 安全；
- 测试与可验证性：程序设计 ↔ 软件工程 ↔ 数据库 ↔ 安全；
- 隐私与伦理：AI、数据管理、安全、软件工程和专业实践的共同能力。

## 4. 通用学习活动内核

### 4.1 领域模型

引入通用 `LearningActivityDefinition`，通过 Java 21 sealed hierarchy 或等价的显式类型模型表达活动规格，避免单个 record 堆积 SQL、代码、测验和模拟的可空字段。

建议核心概念：

| 概念 | 职责 |
| --- | --- |
| `CourseDefinition` | 课程、版本、可见性、语言、许可、维护者和学习成果。 |
| `CourseSection` | 章节、顺序、解锁策略和学习成果聚合。 |
| `KnowledgePointDefinition` | 稳定知识点、前置/关联关系、CS2023 映射和替代名称。 |
| `LearningOutcome` | 可观察、可评价的学习成果和期望能力级别。 |
| `LearningActivityDefinition` | 活动公共元数据、知识点、难度、预计时间、版本和活动专用规格。 |
| `ActivitySession` | 一次学习会话、上下文、草稿、开始/暂停/恢复/关闭状态。 |
| `ActivityArtifact` | SQL、代码、操作序列、答案、实验记录或项目产物的类型化引用。 |
| `ActivityEvaluator` | 对一种活动规格和产物执行确定性评价。 |
| `ActivityEvaluationResult` | 总状态、逐项标准、原因码、证据摘要、资源使用和评价器版本。 |
| `MasteryEvidence` | 将活动评价转为可重算掌握证据，不复制不必要的敏感正文。 |
| `ActivityRunner` | 需要运行环境的活动执行入口；SQL、代码和模拟分别使用独立适配器。 |

### 4.2 活动类型

| 类型 | 核心能力 | 评价策略 |
| --- | --- | --- |
| `SQL` | 当前安全 SQL 工作区和数据库题目。 | 现有 SQL 解析、风险、确认、执行和结果规则。 |
| `QUIZ` | 单选、多选、填空、排序、匹配、短答。 | 答案、规范化文本、集合/顺序和教师量规。 |
| `TRACE` | 代码、递归、指针、算法、汇编和协议状态跟踪。 | 期望状态序列、关键检查点和错误步骤原因码。 |
| `SIMULATION` | 数据结构、CPU、调度、内存、网络和自动机操作。 | 初态、允许操作、目标不变量、路径质量和最终状态。 |
| `CODE` | Java/Python/C/C++ 编译运行、单测和输入输出。 | 编译、公开/隐藏测试、静态检查、资源限制和可选量规。 |
| `LAB` | 多步骤实验、观测、截图/日志摘要和结论。 | 检查点、结构化观测、允许范围和教师复核。 |
| `PROJECT` | 多文件项目、里程碑、测试、提交和反思。 | 自动门禁、量规、同行/教师反馈和版本化成果。 |
| `READING` | 带来源课程内容和主动回忆。 | 阅读状态、嵌入问题和后续检索练习；阅读本身不等于掌握。 |

所有活动统一支持草稿、开始、运行/检查、提交、重试、分级提示、暂停恢复、版本变化提示、撤回/停用、离线缓存、学习事件和无障碍状态。

### 4.3 课程包与创作格式

定义版本化、声明式课程包，包含：

- `manifest`：格式版本、课程 ID、版本、语言、许可、作者和内容哈希；
- 章节、知识点、学习成果和关系图；
- Markdown/图片等白名单内容资源；
- 活动规格、测试数据、提示、评价规则和量规；
- 允许的运行时、依赖、资源上限和网络策略；
- 发布状态、兼容版本和迁移说明。

课程包一律视为不可信输入：限制压缩包大小、条目数量、路径深度、解压总量、MIME、文件名和链接协议；阻止 Zip Slip、符号链接逃逸、脚本自动执行、外部实体、远程类加载和隐式网络请求。声明式课程包不得携带任意 Java 插件或本地可执行文件。

## 5. 学习功能

### 5.1 学生工作台

- 基于身份和课程的任务中心，替代宣传式首页；
- 当前课程、学习目标、待完成任务、需要复习、未读反馈和最近项目；
- 课程地图、前置关系、已掌握/发展中/需要练习/证据不足状态；
- 日/周学习计划、连续学习记录和可解释提醒，不做惩罚性排行榜；
- 全局搜索和 `Ctrl+K` 命令面板覆盖课程、知识点、活动和固定安全命令；
- 活动草稿自动保存、本机恢复和跨设备受控同步；
- 学习历史、评价差异、提示使用、错误类型和改善趋势；
- 成果档案：项目、实验、通过证据、教师反馈和学生反思，可选择导出；
- 中英文界面与课程内容语言独立，不因界面语言改变活动事实。

### 5.2 通用诊断与推荐

保留确定性、可重算、离线可用原则，同时从 SQL 尝试扩展为多种证据：

- 记录活动类型、难度、评价器版本、成功、原因码、提示等级、重试、耗时和是否独立完成；
- 不同活动类型使用版本化 `EvidencePolicy`，不得直接用同一固定权重比较测验、模拟和项目；
- 继续保留最小证据量和 `INSUFFICIENT_EVIDENCE`，不因一次失败给学生贴标签；
- 掌握快照引用证据稳定 ID 和策略版本，派生表可删除重算；
- 推荐展示来源、原因、更新时间、解除条件和下一步行动；
- 支持前置知识回退、间隔复习、错因聚类、替代练习和跨课程迁移提示；
- 学生可以暂时忽略建议，但不能修改原始评价事实；
- 教师可以调整课程策略版本，不能手工伪造学生原始证据。

### 5.3 AI 学习助手

- 基于授权课程内容的带引用解释；
- 苏格拉底式提问、分层提示、错误解释、相似例题和复习摘要；
- 根据知识点和教师模板起草测验、活动、量规和反馈；
- 比较学生两个版本的思路，提示变化而不直接代写完整答案；
- 支持本地 Ollama和用户配置的 OpenAI-compatible Provider；
- 显示 Provider、是否联网、使用了哪些来源和哪些字段可能出站；
- 教师可配置“禁止直接答案”“至少尝试后提示”“考试模式禁用 AI”等策略；
- AI 不执行 SQL、不运行代码、不发布任务、不评分、不改变掌握度、不自动选择干预学生；
- Provider 失败、超时、坏 JSON、Prompt 注入或无引用时回退规则模板，不阻断核心学习。

## 6. 专业实验工作区

### 6.1 数据结构与算法实验室

- 结构可视化：数组、链表、栈、队列、树、堆、哈希和图；
- 逐步执行、撤销、重置、速度控制、状态历史和不变量提示；
- 排序、搜索、遍历、最短路径、最小生成树和动态规划跟踪；
- 时间/空间复杂度对比与输入规模实验；
- 代码跟踪与可视化状态联动；
- “预测下一步 → 操作 → 解释 → 验证”的活动模板；
- 确定性识别访问顺序错误、不变量破坏、边界遗漏和复杂度误判。

### 6.2 编程实验室

- Java、Python、C/C++ 课程工具链探测和明确安装状态；
- 多标签编辑器、行号、语法高亮、括号匹配、格式化、搜索和诊断标记；
- 单文件、多文件、标准输入输出、公开测试、隐藏测试和单元测试；
- 编译错误、运行错误、超时、内存超限、输出超限和测试失败的稳定错误码；
- 测试驱动练习、代码阅读、调试任务、缺陷修复和重构任务；
- 代码版本差异、运行历史、草稿恢复和选择性源码提交；
- 禁止将模型生成代码自动运行；用户必须预览并主动运行；
- 不把完整源码、编译输出或本机路径默认上传云端或网络 AI。

### 6.3 计算机系统、操作系统与网络实验室

- 数字逻辑组件、数据通路和简化指令集模拟；
- 汇编单步执行、寄存器/内存观察和断点；
- Cache、页表、TLB、页面置换和存储性能实验；
- 进程调度、信号量、互斥、生产者消费者和死锁检测模拟；
- 文件分配、磁盘调度和 I/O 路径实验；
- 子网划分、分层封装、交换/路由、TCP 状态和 DNS/HTTP 流程模拟；
- 网络实验默认使用内置模拟数据，不执行端口扫描、凭据尝试、流量劫持或对公网目标的攻击性操作。

### 6.4 软件工程、语言与理论实验室

- Git 仓库初始化、提交、分支、合并、冲突和历史可视化；
- 单元、集成、契约和回归测试任务；
- 需求—设计—实现—测试—发布的项目里程碑；
- 代码审查量规、教师反馈和同伴反馈草稿；
- 正则表达式、有限自动机、词法标记、语法树和解释器实验；
- 类型、作用域、参数传递、闭包和不同编程范式对比；
- 命题逻辑、集合、关系、组合和图论交互练习；
- 证明题以结构化步骤和量规辅助评价，不让 AI 直接判定数学证明正确性。

## 7. 教师、课程与协作功能

### 7.1 教师课程工作台

- 课程、章节、知识点、学习成果和前置关系编辑；
- 活动模板、题目版本、测试、提示、量规、资源上限和发布预览；
- 课程包导入、差异预览、许可确认、版本发布、停用和回滚；
- 班级、成员、分组、任务、截止时间、补交和个别化安排；
- 学生提交、自动评价、教师复核、反馈、重交和申诉记录；
- 知识点、活动、课程和班级学情分析；
- 授权范围内的干预队列、证据详情和反馈/任务草稿；
- CSV/JSON/PDF 导出采用字段白名单、公式转义、稳定列和审计；
- 大班级分页、筛选、后台加载和取消，JavaFX 线程不得执行网络、文件、数据库或 AI 阻塞工作。

### 7.2 项目制与成果评价

- 个人/小组项目、角色、里程碑、模板仓库和交付清单；
- 自动门禁与教师量规组合，不把测试通过等同于完整能力；
- 版本化提交、构建结果、测试摘要、反馈和反思；
- GitHub Classroom 风格的模板和自动测试可作为可选集成，不要求学生必须公开仓库；
- 团队成员只访问授权项目，不通过成果档案暴露其他班级或私人仓库；
- 学生可导出本人作品集，公开分享必须由本人明确选择。

### 7.3 云端与多设备

- Cloud API 升级到 `2.0` 能力协商，旧客户端在最低兼容窗口内获得稳定降级；
- 同步课程版本、任务快照、最小评价摘要、学习事件、反馈和项目元数据；
- 大型课程资源和运行产物使用哈希、分块、续传、上限和保留策略；
- 冲突采用稳定版本、幂等 operation ID 和显式冲突状态，不静默覆盖；
- 教师只能访问当前授权班级；学生只能访问本人和所在小组授权内容；
- 离线期间生成的事实可幂等上传，云端部分失败时本地继续工作且不展示不完整班级结论。

## 8. 桌面 UI 2.0 重构

### 8.1 应用壳

- 左侧导航从“页面列表”改为“学习、课程、实验、教学、系统”工作区；
- 顶部上下文栏显示当前课程、班级、运行环境、数据库或项目；
- 首页按学生、教师、管理员展示不同任务中心；
- 低频入口进入用户菜单或设置，避免侧栏继续无限增长；
- 路由、页面工厂、页面缓存、能力可见性和命令注册从 `MainWindowController` 拆分；
- 页面加载失败、权限变化、身份切换和异步过期结果统一处理。

### 8.2 通用实验工作区

```text
左侧：课程/文件/结构/实验步骤
中间：编辑器、可视化画布或主要任务
右侧：要求、提示、诊断、知识解释
底部：结果、测试、日志摘要、评价标准
```

各区域支持折叠、拖动、键盘切换和合理的最小尺寸；低分辨率下按优先级折叠为抽屉或标签，不使用简单缩小字体解决布局问题。

### 8.3 设计系统

- 采用面向 Windows 生产力工具的 Fluent-inspired 视觉语言，不复制受限品牌资产；
- 统一 8px 间距体系、字号层级、表面、边框、焦点、状态和数据可视化色；
- CSS 固定为 tokens → foundations → components → layouts/pages 四层；
- 逐页淘汰旧 `app.css` 覆盖和原始颜色，不在 FXML 内堆叠内联样式；
- 保留浅色、深色、跟随系统、字体、密度、减少动态效果和高对比度；
- 图标使用项目内可审计矢量资源，提供 accessible text、tooltip 和非颜色状态；
- 建立首页、课程地图、实验工作区、教师表格和设置页的视觉回归截图基线。

## 9. 运行隔离、安全与隐私

### 9.1 代码 Runner

学生代码不得在 SQLTeacher 主 JVM 或 Cloud API 主进程中执行。代码始终使用独立子进程/服务，并分为：

- **本地 IDE Runner**：所有 CODE 活动可直接使用本地工具链、项目文件、环境变量、终端和网络；学生对主动运行的代码负责，应用持续显示该权限状态并保留取消、超时和输出上限；
- **安全评价 Runner**：课程需要受限可复现证据时使用一次性工作目录、默认禁网、工具链白名单，并限制 CPU、内存、墙钟、输出、文件、磁盘和子进程；不继承数据库密码、Token、AI Key、代理凭据、用户目录或应用数据路径；
- 终止时清理完整进程树，超时/取消/应用退出均有恢复测试；
- 标准输出和错误保持有界 UTF-8 解析；安全评价不展示宿主绝对路径，本地 IDE 控制台可显示真实项目路径；
- 本地 IDE Runner 明确不是安全沙箱；高风险、教师导入代码或正式评价优先使用安全评价/受控远端 Runner；
- Java `SecurityManager` 不作为方案，Runner 威胁模型必须在 Alpha 阶段冻结。

### 9.2 SQL 与 AI 安全继承

- 现有 SQL 继续经过结构化解析、验证、构建、风险分析、预览、确认、有界执行和审计；
- 多语句默认禁止；`DROP DATABASE`、`GRANT`、`REVOKE` 继续阻止；
- AI 和课程内容不能持有 JDBC `Connection`、Runner 句柄或直接执行能力；
- 检索内容、课程包、测试输出和模型输出均为不可信输入，不能覆盖系统安全策略；
- AI 生成 SQL/代码必须标记来源并由用户预览，不能由提示词或教师身份绕过执行门；
- 评价事实与 AI 草稿分区保存，发布反馈、任务和量规必须人工确认。

### 9.3 隐私和学术诚信

- 默认本地保存源码和实验草稿；云端提交策略由任务明确声明；
- 学习分析只使用完成教学所需的最小字段，不建立硬件、网络地址、行为或敏感属性画像；
- 不引入摄像头、麦克风、屏幕监考、键盘记录或惩罚性风险评分；
- 提示、完整答案和 AI 可用性由课程策略控制，所有 AI 辅助保留可见标记；
- 日志、诊断包、CSV、备份和错误信息不得包含凭据、完整私有课程、无限长源码或越权学生数据；
- 课程内容、图片、代码模板和测试数据必须有许可清单与来源记录。

## 10. 数据、迁移与兼容

### 10.1 本地数据

- 使用追加式 schema 迁移，保留最旧支持版本升级、重复启动、失败回滚和未来版本拒绝测试；
- 现有 SQL `ExerciseDefinition` 映射为 `SQL` 活动，稳定 ID、版本和尝试历史不变；
- 现有学习事件保留原类型，同时新增通用活动类型、活动 ID、评价器版本和证据字段；
- 掌握快照、学习队列和干预状态继续是可重算派生数据；
- 迁移前自动创建安全快照，失败时不删除旧事实，不把半迁移数据库当成功；
- 新旧客户端并行窗口内，旧客户端看不到新活动但不能破坏课程或通用事件。

### 10.2 云端兼容

- Cloud API 使用能力协商而不是仅比较版本字符串；
- 新活动、课程包、项目和 Runner 结果使用独立端点和稳定错误码；
- 服务端拒绝未知活动规格、超限内容、非法状态迁移和越权评价；
- 提交默认只包含结果哈希、稳定错误码和必要摘要；上传源码、项目或实验附件必须由任务策略和用户动作共同授权；
- 生产 API 继续通过 `https://api.sqlteacher.tech` 的 Nginx HTTPS，Java API 保持 loopback 绑定，除非另行批准架构变化。

### 10.3 品牌与安装兼容

2.0 需要在 Beta 冻结前决定产品公开名称。无论是否更名：

- 不在 Alpha 初期重命名 Java package、数据目录、Cloud 表或 installer Upgrade UUID；
- 保持 v1.x 安装升级和用户数据识别；
- 若采用新品牌，提供“原 SQLTeacher”迁移说明和应用内一次性提示；
- SQLTeacher 名称可保留为数据管理课程模块或历史产品标识；
- 更名不能造成并存安装误删数据、更新通道分叉或旧签名失效。

## 11. Alpha、Beta、RC 与 GA 流程

### 11.1 版本规则

- Maven/应用版本使用 `2.0.0-alpha.N`、`2.0.0-beta.N`、`2.0.0-rc.N`、`2.0.0`；
- 在第一个 Alpha 前验证 Maven、jpackage、WiX、更新清单和 GitHub Release 对预发布版本的合法映射，不假定 SemVer 标签可直接作为 MSI ProductVersion；
- Alpha/Beta/RC 的 GitHub Release 标记为 prerelease，GA 才是正式 Latest；
- 每个预发布标签只指向通过对应门禁的 `main` 提交，不为单人项目引入 PR 流程；
- 预发布默认使用独立更新通道，稳定版用户不会自动收到 Alpha/Beta/RC；
- 数据库和课程格式一旦进入 Beta，只允许兼容性修复，不再破坏式重设计。

### 11.2 Alpha：能力建设与纵向闭环

| 里程碑 | 主要目标 | 退出门禁 |
| --- | --- | --- |
| `alpha.1` | 通用活动、课程图谱、事件、评价结果和迁移骨架；现有 SQL 作为首个活动适配器。 | v1.11.5 SQL 全流程无回归；旧数据可升级/重算；未知活动安全拒绝。 |
| `alpha.2` | UI 2.0 应用壳、身份任务中心、课程地图、通用实验工作区和设计系统。 | 首页、课程、SQL、设置主路径可用；亮/暗、低分辨率、键盘路径通过人工走查。 |
| `alpha.3` | 测验、代码跟踪、数据结构与算法可视化、跨活动诊断。 | 至少一个完整课程纵向闭环覆盖学习—评价—诊断—推荐—教师反馈。 |
| `alpha.4` | 独立代码 Runner、Java/Python/C/C++ 活动、编译/测试/资源限制和取消恢复。 | 威胁模型、进程树清理、无凭据继承、超时/内存/输出限制和恶意夹具通过。 |
| `alpha.5` | 计算机系统、操作系统和网络模拟实验。 | 每类活动具备确定性检查点、原因码、课程内容和离线运行路径。 |
| `alpha.6` | 软件工程、语言/编译、离散数学、AI 和安全基础实验。 | 各路径至少一个可发布课程单元；高风险操作无公网攻击或主机逃逸路径。 |
| `alpha.7` | 教师课程创作、课程包、项目制学习、成果档案、Cloud 2.0 和多设备同步。 | 课程包安全导入、授权、冲突、幂等、项目评价和隐私门禁通过。 |

Alpha 允许功能开关、数据重建和 UI 调整，但不允许降低 SQL/AI/权限/凭据安全边界。任何 Alpha 都必须可安装、可启动、可卸载、可从上一预发布升级；未完成能力必须明确标记实验性，不能以假数据冒充可用功能。

### 11.3 Beta：功能完整与系统收敛

| 里程碑 | 主要目标 | 退出门禁 |
| --- | --- | --- |
| `beta.1` | 功能完整：计划中的课程路径、活动类型、学生、教师、项目、AI、Runner、同步和 UI 入口全部接线。 | 不再新增顶层功能、活动类型、数据库体系或 Cloud 主端点；所有入口具有真实运行路径。 |
| `beta.2` | 教学内容与诊断校准：课程内容、活动质量、原因码、提示、量规和跨课程关系复核。 | 内容来源/许可完整；固定夹具可复现；教师审查无系统性误判。 |
| `beta.3` | 兼容、性能、无障碍与国际化：旧数据、弱网、大班级、大课程、高 DPI 和中英文。 | 性能预算、可访问性、键完整性、离线/恢复、500 人班级和大事件夹具通过。 |
| `beta.4` | 安全、隐私、运维与发布预演：Runner、课程包、AI、Cloud、更新和备份恢复。 | 威胁模型用例、敏感数据扫描、升级/回退演练、生产兼容探针和候选打包通过。 |

> 2026-08-09 实施决策：为加速单人串行开发，四组 Beta 门禁合并到 `2.0.0-beta.1` 一次执行，
> 不再分别创建 beta.2-beta.4 功能版本。功能、内容、兼容、性能、安全和发布预演范围均保留；
> 合并后的冻结契约与证据见 [一次性 Beta RFC](2026-08-09-v2-consolidated-beta-rfc.md)。

Beta 开始后进入功能冻结：只允许完成已列工作、修复缺陷、补内容、优化性能和兼容性，不接受新的顶层产品方向。若发现架构级缺陷必须退回 Alpha 编号，不用 Beta 标签掩盖重构。

### 11.4 RC：发布冻结

RC 只允许以下变化：阻断缺陷、数据/安全/兼容缺陷、错误文案、内容事实错误、许可缺口和发布配置修正。任何新功能、schema 重构、活动类型或 Cloud 契约变化都必须返回 Beta。

RC 门禁：

- P0/阻断、P1/高优先级缺陷均为 0；P2 仅允许有明确规避方式、影响范围和后续记录；
- 完整 `mvn test`、固定性能夹具、迁移矩阵、安全/隐私测试、课程包夹具和 Runner 恶意夹具通过；
- 从 v1.11.5、最后一个稳定 1.x 和上一 Beta 的升级通过，失败恢复不会丢失事实数据；
- EXE、ZIP、app-image、SHA-256、SBOM、第三方许可、更新清单和版本元数据一致；
- 正式候选包完成 Windows 10/11、100%/125%/150% 缩放、亮/暗、高对比度、离线、弱网和代理人工走查；
- Cloud 2.0 在预生产环境完成权限、限流、幂等、备份恢复、兼容和公开 HTTPS 验证；
- RC 期间发现问题继续发布 `rc.N+1`，不带已知阻断问题进入 GA。

### 11.5 GA：正式发布

- GA 使用最后一个通过 RC 的源提交，仅允许正式版本元数据和签名流程所需变化；
- 本地正式产物、GitHub Actions、标签、公开 Release 和更新清单指向同一提交；
- Release 非 draft、非 prerelease，资产完整，不混入旧版本安装包；
- 发布后按现有分阶段更新能力逐步开放，支持暂停但不能更换签名产物；
- 生产监控、证书、备份、恢复、Cloud 健康、错误率和更新下载状态通过；
- GA 后缺陷进入 `2.0.x`，新顶层功能进入后续版本计划，不回写本计划的历史假设。

## 12. 测试策略

- 派生诊断删除重建、课程版本变化、评价器版本变化和证据不足。

## 13. 性能、质量与发布指标

正式数值在 `alpha.1` 建立基线后冻结；在此之前使用相对回归门禁：

- 启动、首页可交互、课程切换和实验打开不得较 v1.11.5 基线出现无解释的显著退化；
- 个人诊断保持 5,000 事件固定夹具低于既有 500 ms 预算，并为多活动证据建立新夹具；
- 500 人班级看板和干预队列保持分页、有界查询和可取消加载；
- Runner 默认并发有界，不因一个恶意活动耗尽主应用线程、内存或文件句柄；
- 日志、缓存、课程资源、运行产物和更新临时文件均有大小/数量/保留上限；
- JavaFX Application Thread 不执行数据库、文件、网络、AI、编译或 Runner 等待；
- 正式候选无 P0/P1 缺陷、无未解释测试跳过、无敏感文件、无陈旧安装资产。

```text
  → RC 发布冻结
```

每次只选择一个可演示纵向闭环，完成领域、应用、基础设施、桌面、测试和文档后再进入下一个。不要分别堆积几个月的模型、数据库和 UI 后一次集成。

## 15. 不可妥协边界

以下内容不是“范围裁剪”，而是任何 2.0 阶段都不能引入的行为：

- AI、课程包或第三方脚本直接执行 SQL、代码、Git 或教师权限操作；
- 在主 JVM 内运行不可信学生代码，或用 Java `SecurityManager` 宣称已经隔离；
- 为了更多课程放宽 SQL 确认、Runner 隔离、权限、隐私或更新签名；
- 摄像头/麦克风/屏幕监考、键盘记录、隐蔽行为画像、惩罚性排行榜或黑盒学生风险分；
- 未经授权打包教材、题库、图片、代码、模型或私有课程资料；
- 任意 Java 插件、本地可执行插件、远程脚本市场或服务端下发代码；
- 将完整源码、Prompt、数据库样本、学生记录、Token、密码或连接信息写入日志、诊断包或网络 AI；
- 以 UI 隐藏替代应用服务、Runner 或 Cloud 的权限和安全 enforcement；
- 为追求功能数量保留占位入口、假数据、不可运行按钮或无验证的“已完成”状态。

## 16. 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| 功能面过大导致长期不可用 | 以多个可安装 Alpha 交付纵向闭环；每个里程碑都必须有真实活动和迁移/回归门禁。 |
| 领域模型被 SQL 历史限制 | 先抽象活动/评价/证据，SQL 作为适配器迁移，不在旧 record 上堆可空字段。 |
| 任意代码危害本机或云端 | 独立 Runner、默认禁网、资源限制、无凭据、恶意夹具和取消恢复；高风险运行转受控环境。 |
| 课程内容工作量失控 | 使用版本化课程包、模板和教师创作工具；内置内容按路径逐步完成并保留许可清单。 |
| 诊断跨活动后失真 | 按活动类型和评价器版本建立证据策略；数据不足不结论；教师复核固定夹具。 |
| UI 再次堆叠 | 先完成壳、路由、页面模板和设计系统，再迁移页面；禁止新页面自行定义视觉体系。 |
| Alpha 数据不可升级 | 从 alpha.1 起即测试相邻预发布升级；破坏式实验数据变化必须提供重建或明确删除边界。 |
| Cloud 2.0 扩大隐私面 | 最小摘要、显式源码策略、能力协商、授权查询、保留上限和公开 HTTPS 验证。 |
| 品牌更名破坏更新和数据 | Beta 前决策，保持 Upgrade UUID、数据目录和兼容入口，不在 Alpha 早期大范围重命名。 |
| 单人开发上下文切换 | 严格串行；一次只做一条课程/活动纵向闭环；阶段门禁后再切换领域。 |
