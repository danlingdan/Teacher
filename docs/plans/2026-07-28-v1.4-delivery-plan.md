# SQLTeacher v1.4 单人迭代计划

> 制定日期：2026-07-28
> 建议周期：2026-07-29 至 2026-09-08（6 周）
> 发布基线：`v1.3.0`（任务提交、任务学情、管理员运维、数据保留恢复和自动化运维已交付）
> 版本定位：课程内容协作与个性化反馈版

## 1. 版本目标

v1.4 在 v1.3 的“教师布置任务 → 学生提交 → 教师查看学情”闭环上继续向教学内容和反馈推进，但不扩展为正式在线考试平台。

本版本完成后，教师可以按课程、章节和知识点维护共享题库，从固定题目版本创建可复现的任务，针对学生提交给出结构化反馈；学生可以查看反馈、薄弱知识点和下一步练习建议；应用通过站内通知提示任务、截止时间和新反馈。AI 只用于生成可编辑的解释草稿，不能决定成绩或绕过 SQL 安全规则。

### 2.3 明确不纳入 v1.4

- 正式在线考试、监考、防作弊、排名和可作为官方成绩依据的高风险考试。
- 让 AI 自动判分、直接发布反馈、执行 SQL 或访问 JDBC 连接。
- 邮件、短信、系统推送和即时聊天；v1.4 仅提供应用内通知。
- 学校级多租户自助开通、计费、采购、复杂组织架构和单点登录。
- Web 学生端、移动端以及 Oracle、PostgreSQL、SQL Server 等新数据库适配。
- 云端保存用户数据库密码、网络 AI API Key、本地数据库文件或未经授权的课程全文。
- 安装器代码签名采购；如已有合法证书，可作为独立运维任务接入，不阻塞功能开发。

## 3. 核心设计原则

- **历史可复现**：已发布任务引用不可变内容快照；题目、数据集或评测规则更新只能影响新任务。
- **确定性结果为准**：薄弱点和推荐只使用 Java 侧确定性评测数据；AI 只能解释已有结论。
- **最小权限**：学生仅访问所属班级已发布内容及本人提交、反馈和通知；教师仅管理被授权课程与班级。
- **并发与幂等**：题目、反馈和目录修改使用版本号；同步操作携带稳定操作 ID，重试不得制造重复版本或通知。
- **本地优先**：网络不可用时，本地练习、评测、已缓存任务和反馈可读；待提交操作按账号隔离并可恢复。
- **隐私最小化**：分析与 AI 草稿只使用必要的错误码、知识点和脱敏摘要，不发送完整 SQL、学生身份或数据库结构。
- **控制器保持轻量**：业务规则位于 application/domain，JavaFX 控制器只处理输入、异步状态和展示。

## 5. 关键数据与接口演进

### 5.1 建议数据域

| 数据域 | 最小增量 | 关键约束 |
|---|---|---|
| 课程目录 | 课程、章节、知识点、排序、状态、版本 | 删除默认转为停用；历史任务引用不得悬空。 |
| 共享题库 | 逻辑题目 ID、发布版本、内容、数据集版本、评测规则、知识点 | 发布版本不可变；复制产生新逻辑题目；内容字段设大小上限。 |
| 任务快照 | 任务 ID、题目版本 ID、数据集/评测摘要、快照哈希 | 发布事务内冻结；服务端校验所有引用。 |
| 教师反馈 | 提交 ID、状态、评语、知识点标签、版本、操作者、时间 | 一个提交一条当前反馈并保留审计；禁止敏感内容进入日志。 |
| 掌握度摘要 | 用户、知识点、样本范围、通过/尝试计数、更新时间 | 可由原始确定性提交重建；不把 AI 输出写成事实。 |
| 站内通知 | 接收者、类型、关联资源、幂等键、已读时间、创建时间 | `(recipient, idempotency_key)` 唯一；读取时再次校验资源权限。 |

### 5.2 API 约束

- 所有写接口携带当前资源版本或稳定操作 ID；冲突返回稳定错误码和安全的最新摘要。
- 任务发布必须在同一事务中验证并冻结所有题目版本，不接受“始终取题库最新版”的引用。
- 反馈发布与读取均按提交、班级和角色重新授权，不能信任客户端传入的教师或学生 ID。
- 掌握度查询与导出共享同一筛选 DTO、时间边界和统计实现。
- 通知只保存最小展示字段和资源引用；资源失效或权限变化后不得继续泄露原内容。
- AI Provider 只接收脱敏、限长的结构化上下文；返回内容按未信任文本处理并经过教师确认。

## 6. 验收场景

| 场景 | 正常路径 | 必测边界 |
|---|---|---|
| 共享题库 | 教师创建题目、关联知识点、发布版本并用于任务。 | 并发编辑、重复发布、停用引用、跨课程越权和超长内容。 |
| 历史复现 | 学生完成任务后教师修改题库，新任务使用新版本。 | 旧任务、旧提交、统计和反馈仍指向原快照。 |
| 教师反馈 | 教师查看提交并发布结构化反馈，学生收到通知并查看。 | 旧版本覆盖、重复点击、撤销授权、禁用账号和他人提交。 |
| 薄弱点推荐 | 学生根据多次确定性结果获得知识点摘要和练习建议。 | 样本不足、题目停用、重复提交、空结果及相同分数的稳定排序。 |
| 离线恢复 | 学生断网查看缓存内容、完成练习，联网后提交并收取反馈。 | 账号切换、内容版本过期、重复重试、应用重启和服务端拒绝。 |
| 通知中心 | 任务、截止、提交和反馈各生成一条可跳转通知。 | 重复同步、资源删除、权限变化、分页和大量未读记录。 |

## 7. 测试策略

### 7.1 必增自动化测试

- 课程目录：排序、停用、循环/悬空引用、版本冲突和权限矩阵。
- 题目版本：发布不可变、复制、并发更新、过滤分页和数据大小限制。
- 任务快照：事务冻结、哈希一致性、历史复现、旧数据迁移和失败回滚。
- 教师反馈：版本冲突、跨班级拒绝、学生隔离、审计脱敏和幂等重试。
- 掌握度与推荐：固定样例、时间边界、重复提交、样本不足和稳定排序。
- 通知：幂等键、已读状态、权限失效、分页、账号隔离和离线同步。
- AI 草稿：结构化输入、输出限长、超时、非法内容、来源缺失及无 Provider 降级。
- 桌面逻辑：后台加载、取消、失败重试、空状态、键盘操作和低分辨率资源加载。

### 7.2 验证节奏

聚焦验证使用 Maven 的 `-Dtest` 指定相关测试类；以下节点运行全量回归：

```powershell
mvn test
```

- schema 或公共契约完成后。
- 题库到任务快照闭环完成后。
- 反馈、分析和通知累计完成后。
- 发布候选打包前。

发布候选还需运行：

```powershell
.\packaging\package-stage1.ps1
```

并完成 Windows 安装/升级/卸载、ECS 健康检查、备份与隔离恢复演练。

## 8. 发布门禁

- `mvn test` 全量通过，v1.3 的安全、提交、权限、离线队列和恢复测试无回归。
- 至少完成“教师发布题目版本 → 创建任务 → 学生离线练习并提交 → 教师反馈 → 学生查看通知与建议”的端到端演练。
- 旧任务可复现；题库更新不能改变历史任务、提交、统计或反馈口径。
- 重复、越权、过期版本、禁用账号和账号切换场景均被正确处理。
- v1.3 生产数据副本升级、重复 migration、失败回滚、备份和隔离恢复通过。
- AI 关闭、Ollama 不可用和网络 Provider 失败时，确定性评测、反馈和推荐主流程仍可用。
- EXE、ZIP、app-image 和 SHA-256 生成并核对；包内不含数据库、日志、凭据、课程原文或学生数据。
- 用户手册、教师手册、部署手册、隐私说明、已知限制和发布说明与实际行为一致。

## 9. 风险与裁剪顺序

| 风险 | 应对 | 工期不足时的裁剪 |
|---|---|---|
| 题目版本与任务快照混淆 | 使用逻辑题目和不可变发布版本两层模型，以集成测试固定历史行为。 | 不裁剪快照；先裁剪批量操作和高级筛选。 |
| 课程目录扩大为复杂教务系统 | 仅支持课程、章节、知识点三级目录和现有角色。 | 不增加院系、学期排课和组织继承。 |
| 推荐结果被误解为成绩 | 展示依据、样本量和建议性质，允许教师调整。 | 保留规则摘要；裁剪图表和个性化文案。 |
| AI 反馈泄露数据或产生错误结论 | 只提供脱敏错误码和授权知识片段，教师确认后发布。 | 首先裁剪网络 AI，保留模板化反馈。 |
| 通知数量膨胀 | 稳定幂等键、分页、保留期和按类型聚合。 | 保留任务与反馈通知；裁剪临近截止提醒。 |
| 单人跨桌面、服务端和迁移切换过多 | 每周只交付一个纵向闭环，接口和 UI 同步完成。 | 不并行启动 P1；先保证 P0 端到端可演示。 |

裁剪顺序：批量标签与导入映射 → AI 反馈草稿 → 临近截止通知 → 推荐图表美化 → 高级组合筛选。题目版本、任务快照、权限隔离、反馈审计、迁移回滚和数据最小化不可裁剪。
