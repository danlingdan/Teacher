## 1. 背景与结论

v3.2.0 把 SQL 执行安全模型校准为"按输入来源分级"后，练习（单条 SELECT）与工作台
（确认制全语句）之间的能力断层成为最突出的教学短板：学生无法在可判分、可重置的
环境里练习写操作，也没有脚本、事务、触发器、索引优化等进阶训练形态。维护者确定
v3.3 主题为**全面提升 SQL 教学能力与相关 UI**，并将原 v3.4 候选（脚本/事务、部分
给分与自适应、错题本、可视对比、题库分发生态等）全部并入本版本。

对现行链路的核实结论：

- 判分内核（`DeterministicSqlExerciseEvaluationService`）是"参考答案结果集 vs 学生
  结果集"的确定性比对，规则为 columns/rows/order/row_count/keywords 五类；提交语句在
  练习（`JdbcExercisePracticeService:238`）与评测（`:62`）两处硬编码为单条 SELECT。
- 练习会话具备现成的数据集重置能力（`JdbcExercisePracticeService.reset:127`）；会话库
  与评测库均为按题隔离的一次性 SQLite 文件，`query_only` 是只读边界的唯一开关——
  在这类"沙盒库"上放开写操作/多语句，与 v3.2.0 校准后的安全模型（隔离教学环境不套用
  不可信输入强度）一致。
- **SQLite 能力评估（触发器与存储过程）**：SQLite 完整支持 `CREATE TRIGGER`
  （行级 BEFORE/AFTER/INSTEAD OF，`FOR EACH ROW` 语义，无语句级触发器与
  `UPDATE OF 列` 之外的粒度控制）；**不支持存储过程**（仅触发器与视图）。结论：
  触发器练习纳入本次范围；存储过程教学需要引入第二评测引擎（H2/PostgreSQL），
  列入后续候选，本次不做。
- 题库分发（v3.1.0 W5）：服务端 `V31ExerciseBankStore` 单一单调 `bankVersion`，
  清单+分块只读接口与管理员发布接口已上线（当前为空清单）；客户端
  `practice.bank.check`/`practice.bank.update` 已接通，更新默认手动检查。
- `EXPLAIN`/`EXPLAIN QUERY PLAN` 当前被风险分析判为不支持语句（switch default
  FORBIDDEN），查询计划与索引实验教学需要先放行该语句族。
- `practice.catalog` 返回全量 `ExerciseSummary` 列表，无分页；题库规模增长后需要
  Java 侧分页与前端窗口化渲染。
- 其他 UI/平台事实同 v3.2.0 审计与遗留清单：教师学情 JSON dump、Monaco 全局补全
  互相污染、CSV 导出无公式中和、SQL 确认/取消审计事件缺失、学习队列云端 N+1、
  服务端令牌/备份目录无清理、组件安装同步阻塞、DPAPI 瞬时故障删密文、Rust 退出
  500ms 强杀。

## 2. 目标与非目标

### 2.1 目标

- **题型体系扩展**：在现有 QUERY 题之外新增三类确定性判分题型——写操作题
  （STATE：单条 `INSERT`/`UPDATE`/`DELETE`/`CREATE`，验证查询比对 + 影响行数）、
  脚本/事务题（SCRIPT：多语句脚本，终态比对 + 事务关键字约束）、触发器题
  （TRIGGER：`CREATE TRIGGER` 定义，触发场景查询比对）；做错可一键重置本题数据。
- **判分与个性化闭环**：分项部分给分（确定性加权展示，不改变"全对才通过"语义）、
  难度自适应推荐（确定性算法，基于作答历史）、错题本与个性化重练（AI 仅起草
  讲解，不决定任何学习状态）、失败后期望/实际结果并排可视对比（教师按题控制
  是否展示期望数据）。
- **查询教学与性能深化**：工作台执行计划查看、题面期望结果形状、索引实验题
  （以 `EXPLAIN QUERY PLAN` 输出为判分依据）、教师题库健康检查。
- **题库分发与内容生态**：S/P/J/SPJ 第二题库内容包、多题库频道与订阅、题库更新
  定时检查（opt-in）、题库目录分页与虚拟化渲染、服务端题库多版本保留与回滚。
- **UI 与平台质量**：教师学情结构化呈现、Monaco 补全隔离、CSV 导出加固、
  v3.2.0 遗留清偿（审计事件、N+1 批量端点、服务端清理、组件安装异步化、
  DPAPI 保护、Rust 退出排空）。

### 2.2 非目标

- 不引入 AI 判分、模糊比对或非确定性评分；一切判分、推荐、状态均由确定性代码
  拥有，AI 仅起草文本（讲解/提示），且经确定性过滤后展示。
- 不支持存储过程教学（SQLite 引擎不支持；第二评测引擎列入后续候选）。
- 不改变练习会话/评测库的隔离架构与单机存储模型；不做多语句评测的并发执行。
- 不改变题库 DSL 的存量语义：全部新字段可选，旧包零改动导入，旧服务端/客户端
  前向兼容。
- 教师端不做多人协作/权限模型变更（沿用既有教师角色）。

## 3. 已核实基线

- 练习链路：`practice.submit` → `JdbcExercisePracticeService`（SELECT 门禁 :238-241，
  友好提示已存在）→ 会话库（`query_only` :250、10s、500 行）→
  `DeterministicSqlExerciseEvaluationService.evaluate`：评测库由 setup SQL 初始化，
  先跑 `referenceSql` 生成期望（失败归因 `REFERENCE_SQL_FAILED`），再跑学生语句，
  `evaluateCriteria` 产出中文分项反馈；临时库删除时清理 `-wal`/`-shm`。
- 规则模型：`ExerciseEvaluationRule`（compareColumns/compareRows/rowOrderMatters/
  expectedRowCount/requiredSqlKeywords）；`ExerciseDefinition` 为防御性 record；
  题库文字 DSL（`===[DATASET]===`/`===[EXERCISE]===` 分块，TITLE/DATASET/SQL/RULE/
  HINTS 字段）与导入自测（真实建库、逐题试跑参考 SQL）v3.1.0 已上线。
- 会话能力：`reset(sessionId)` 重建数据集；会话按 owner 隔离（v3.2.0 W4.3）；
  风险分析（v3.2.0 后）CTE 放行、确认制分级、文件写操作禁止；`EXPLAIN` 落入
  default FORBIDDEN。
- 题库分发：`V31ExerciseBankStore` 单 `bankVersion`（`currentVersion+1` 发布，分块
  携带版本），`GET /bank/manifest`、`GET /bank/block/{type}/{id}` 公开只读，
  `POST /bank/publish` 管理员发布；客户端 `practice.bank.check/update` + `bankVersion`
  防降级已接通，默认手动检查。
- 目录：`practice.catalog` 返回全量 `ExerciseSummary`（含作答状态徽标字段，
  v3.1.0 W4 已上线），无分页参数。
- UI/平台事实：学情 JSON dump（`PlatformPages.tsx` 约 :1761）；Monaco 全局补全两处
  （`EditorPage.tsx:46`、`DataSqlPage.tsx:16`）；`SqlCsvExporter` 无公式中和；
  审计事件缺确认/取消类型；`DefaultStudentLearningQueueService.refresh` 每作业一次
  提交查询 + 每课程 3 次调用；服务端令牌表/`retention-backups/` 无清理；
  `WindowsManagedComponentService` 同步 `waitFor` 且无 `CREATE_NO_WINDOW`；
  `WindowsDpapiSecretStore.load` 任何异常即 `clear()`；Rust 退出 500ms 后 kill。
- 版本位置：`pom.xml`、`ui-web/package.json`、`ui-web/src-tauri/Cargo.toml`、
  `ui-web/src-tauri/tauri.conf.json` 均为 `3.2.0`。

## 4. 工作项拆解

### W1 练习题型体系扩展（STATE / SCRIPT / TRIGGER）

- **W1.1 题型模型与 DSL**：`ExerciseDefinition` 增加 `exerciseType`
  （`QUERY` 默认 / `STATE` / `SCRIPT` / `TRIGGER`）与对应可选字段：
  `verificationSql`（教师验证查询，导入校验为单条 SELECT）、`allowedStatementTypes`
  （STATE 默认 INSERT/UPDATE/DELETE，可含 CREATE/DROP）、`expectedAffectedRows`、
  `requiredTransactionKeywords`（SCRIPT：如 BEGIN/COMMIT/ROLLBACK）、
  `triggerProbeSql`（TRIGGER：触发场景语句）。DSL 增加对应可选字段
  （`TYPE:`/`VERIFY:`/`ALLOWED:`/`AFFECTED:`/`TXN:`/`PROBE:`），缺省等价旧行为。
- **W1.2 STATE 判分**：双临时库比对——库 A 跑参考写语句 + 验证查询得期望，库 B
  （同 setup）跑学生语句 + 同验证查询得实际；沿用五类规则；`expectedAffectedRows`
  声明时增加 affected_rows 分项。学生语句执行失败/验证失败按既有归因风格反馈。
- **W1.3 SCRIPT 判分**：评测库按顺序执行学生脚本语句（拆分器沿用
  `SqlScriptSplitter`，单语句仍受 FORBIDDEN 类拦截——写文件/用户角色管理在脚本内
  同样拒绝）；执行完成后跑验证查询做终态比对；`requiredTransactionKeywords` 作为
  结构关键字分项（复用 KEYWORDS 归一化匹配）。事务原子性不做故障注入验证
  （确定性边界），以终态 + 关键字评价并写明教学说明。同一套流程支持 TRIGGER 题：
  学生语句为 `CREATE TRIGGER`（分析放行该 DDL 于沙盒场景），`triggerProbeSql` 在
  触发后产生可比对状态。
- **W1.4 练习会话路径矩阵**：QUERY 题维持 `query_only` 不变；STATE/SCRIPT/TRIGGER
  题会话库放开只读并允许按题型执行单条/多语句（逐条执行、总超时不变）；
  FORBIDDEN 类在全部题型硬拦截；确认制在沙盒会话豁免（v3.2.0 安全模型）；
  `reset` 在非 QUERY 题常驻强化；owner 隔离覆盖全部新路径。
- **W1.5 导入自测扩展**：解析/导入对 STATE/SCRIPT/TRIGGER 题执行与运行时一致
  的自测（参考答案 + 验证查询/探针语句真实执行并满足自身规则、影响行数核对、
  事务关键字可满足）；setup 白名单本次不扩展（触发器题的触发器由学生创建，
  教师数据集仍限 CREATE TABLE/INDEX/INSERT）。
- **W1.6 作答 UI**：按题型呈现引导（STATE/SCRIPT/TRIGGER 显示"本题修改数据，可
  随时重置"与常驻重置按钮、SCRIPT 显示语句数与事务提示）、影响行数与验证分项
  反馈、沙盒豁免不弹工作台确认弹窗；QUERY 题界面不变。
- **W1.7 测试**：DSL 往返兼容；四题型判分矩阵（正确/类型越界/影响行数不符/
  语法错/表被破坏归因/事务关键字缺失）；会话可写矩阵与重置恢复；FORBIDDEN 在
  脚本内拦截；自测拒绝坏验证/坏探针。

### W2 判分与个性化学习闭环

- **W2.1 部分给分**：规则分项权重（DSL 可选 `WEIGHTS:`，缺省各分项均分），评测
  结果新增确定性得分（通过分项加权求和，0–100）；**"通过"语义不变**（全部分项
  通过才算通过），得分与分项得分仅用于反馈与学情展示；题目目录/作答界面显示
  得分与未通过分项。
- **W2.2 难度自适应推荐**：练习目录新增"推荐下一题"——确定性算法（按知识点
  正确率与题目难度层级的固定规则，基于本机作答历史即时重算，无随机、无 AI）；
  推荐理由在 UI 展示（如"查询正确率 60%，建议同难度再练一道"）。
- **W2.3 错题本与个性化重练**：本机聚合失败尝试（按题目/知识点，确定性统计）；
  新增"错题本"入口（目录内筛选 + 独立视图），支持一键重练（开新会话）；
  "AI 讲解"按钮按需起草错因讲解（走既有 AI 任务链：本地/云 provider、字符预算、
  无配额），AI 输出仅作为展示文本草稿，不写入任何学习状态、不影响判分与推荐。
- **W2.4 期望/实际可视对比**：评测失败时反馈区提供"对比视图"——期望/实际结果
  并排表格 + Java 侧计算的单元格级差异标记；期望数据是否展示由教师按题控制
  （DSL `REVEAL:` `never`/`on-fail`/`always`，缺省 `on-fail`）；提交前任何状态下
  不泄露期望数据行。数据在 IPC 中为结构化表（复用结果分页模型），diff 标记由
  Java 确定性计算。

### W3 查询教学与性能深化

- **W3.1 执行计划放行与展示**：风险分析放行 SQLite 方言 `EXPLAIN`/`EXPLAIN QUERY
  PLAN` 前缀语句（LOW 只读，行数/超时约束不变）；工作台结果面板"执行计划"操作
  （对当前语句自动包裹执行并以表格呈现）；练习作答不开放该入口。
- **W3.2 期望结果形状**：DSL 可选 `EXPECT_COLUMNS:`；作答界面题面下方展示期望
  列（仅列名），与失败反馈的期望列展示闭环。
- **W3.3 索引实验题**：以 W3.1 为基础的新题型能力——验证查询允许对
  `EXPLAIN QUERY PLAN` 输出做关键字断言（规则 `PLAN_KEYWORDS:`，如要求
  `USING INDEX idx_xxx`）；配套大容量演示数据集（内容，随题库包发布，见 W4.1）；
  工作台不做独立实验模式，全部以题目形态交付。
- **W3.4 教师题库健康检查**：教学工作台"题库体检"——对库内全部题目批量执行与
  导入自测同等校验（含新题型），产出题目级报告（题目、题面、失败原因、建议），
  支持导出文字报告；只读，无副作用。

### W4 题库分发与内容生态

- **W4.1 S/P/J/SPJ 第二题库内容包**：基于 v3.1.0 教材数据集（demo.db 的
  供应商-零件-工程项目 7 表）编写第二题库包（文字 DSL），覆盖入门查询到连接/
  子查询/聚合进阶，全部题目经导入自测验证；随应用内置包通道分发（复用 v3.1.0
  W3.1 版本化 upsert），并作为 W4.3 频道功能的第二个内置频道内容。
- **W4.2 多题库频道与订阅**：服务端题库接口扩展 channel 维度（清单接口支持
  按频道枚举/获取，channel 为独立 bankVersion 序列，沿用防降级语义）；客户端
  增加频道订阅设置与"检查更新"按频道执行；不订阅的频道不拉取、不上库。
- **W4.3 题库更新定时检查**：设置页 opt-in 开关（默认关），启用后由既有桌面端
  定时机制周期调用 `practice.bank.check`，有更新时仅通知不打断；离线/失败静默
  降级并记日志，绝不阻塞本地练习。
- **W4.4 目录分页与虚拟化**：`practice.catalog` 增加 `page`/`pageSize` 参数
  （Java 侧 SQLite 分页 + 总数返回），前端练习目录改为分页拉取 + 窗口化渲染；
  虚拟列表实现方式二选一（实施时定）：自研轻量窗口化组件（约百行，无新依赖，
  倾向方案）或引入 `@tanstack/react-virtual`（唯一允许的新前端依赖）。
- **W4.5 教师题库多版本**：服务端保留 bankVersion 历史清单快照（新表），管理员
  可发布新版本、回滚激活版本（对全体客户端即时生效，不做按比例灰度）；客户端
  清单请求带当前版本，服务端按激活版本返回目标版本。发布/回滚全程审计（沿用
  admin 鉴权与审计惯例）。

### W6 平台遗留清偿（v3.2.0 遗留 + 已知技术债）

  `LearningEventType` 增加 `SQL_CONFIRMED`/`SQL_CONFIRMATION_CANCELLED`；实现前

## 6. 风险与回退

- **范围风险（本版本最大风险）**：工作流按 W1→W2→W3→W4→W5/W6 分阶段交付，每个
  工作流独立可发布、可中止；任一工作流受阻不阻塞已完成工作流的发版（版本号只在
  最终发版时 bump，功能在 main 上按工作流累积）。
- **写/脚本路径安全边界**：沙盒豁免确认的依据是"一次性隔离库"；FORBIDDEN 类
  （多语句限制按题型放宽、写文件、用户/角色管理）在单条与脚本内均硬拦截，QUERY
  题行为与 v3.2 完全一致——测试矩阵固化，发布说明明示各题型边界。
- **判分语义**：部分给分只做展示层（通过仍需全部分项通过），避免"得分高即通过"
  的歧义；自适应推荐为确定性规则，算法与权重实现内聚在 Java 并可单测重算。
- **期望数据泄露**：对比视图与期望形状受教师按题 `REVEAL` 控制，缺省仅失败后
  展示；IPC 载荷层校验（never 时不含期望行），测试覆盖。
- **DSL 兼容**：新字段全部可选且缺省等价旧行为；旧服务端/客户端前向兼容；导入
  自测与运行时共用同一校验实现，避免双标。
- **题库多版本**：版本切换对全体客户端即时生效，回滚即切回历史清单快照；
  发布/回滚全程审计；如未来需要渐进放量，再评估引入灰度机制。
- **评测成本**：STATE 双库、SCRIPT 脚本重放增加评测耗时，沿用临时库清理纪律与
  行数/超时上限；目录分页降低大题库下的目录加载成本。
- **依赖纪律**：虚拟化优先自研；仅当自研方案不可行才引入
  `@tanstack/react-virtual` 并在实施记录说明理由。
- 回退方式：功能按工作流独立回退（前端/Java 侧开关或版本回退）；题库 DSL 新
  字段旧版本不读取；频道/清理任务均可独立停用；云端变更沿用版本目录 +
  备份 + 清单备份回滚点。
