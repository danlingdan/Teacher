# v2.0 alpha.6 专业基础课程单元 RFC

> 制定日期：2026-08-09
> 目标版本：`2.0.0-alpha.6`

## 目标

Alpha6 为软件工程、程序设计语言与编译、离散数学、AI 与数据基础、计算机安全基础五条路径各交付一个可发布课程单元。每个单元必须包含课程、章节、学习成果、知识点、真实交互、确定性评价和离线证据，而不是静态占位内容。

## 实现路线

五个单元复用 `SIMULATION` 有限状态活动，不新增顶层活动类型：

| 路径 | 单元 | 确定性任务 |
| --- | --- | --- |
| 软件工程 | 持续集成质量门禁 | 从验收标准映射测试，检查固定 CI 结果并评审发布证据 |
| 语言与编译 | 词法分析流水线 | 对固定源文本划分词素、分类 Token 并验收 Token 流 |
| 离散数学 | 数学归纳法 | 依次完成基础步、归纳假设、归纳步和结论 |
| AI 基础 | 分类结果评价 | 构造混淆矩阵、计算 precision/recall 并审计指标局限 |
| 安全基础 | 不可信输入防御链 | 完成结构约束、对象授权、上下文编码和受控处理 |

课程差异全部保存在 schema 15 的内置定义中。通用 Java 评价器重放动作序列，并用课程专用原因码标识首个未达到检查点。

## 安全与权威边界

- 软件工程实验不执行真实 Git、CI 或发布命令；
- 编译实验不调用本机编译器，仅处理固定字符与 Token 数据；
- 数学证明只评价固定结构化步骤，不让 AI 判断自由文本证明；
- AI 实验不训练、调用或下载模型，不处理个人数据，模型输出不决定权威学习状态；
- 安全实验只模拟防御门禁，不提供攻击载荷，不执行 Shell、网络扫描、凭据尝试或主机操作；
- SQL、AI、Cloud、权限、本地 Runner 和隐私 enforcement 保持不变。

## 数据与验收

schema 15 只追加五门内置课程及关联内容，不删除或覆盖已有数据。验收要求五条正确路径全部离线通过；空 artifact 分别返回 `SE_*`、`COMPILER_*`、`DISCRETE_*`、`AI_*`、`SEC_*` 稳定原因码；课程地图、活动评价与学习事件持久化路径贯通。
