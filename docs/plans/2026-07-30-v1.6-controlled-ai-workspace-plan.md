# SQLTeacher v1.6 可控 AI 教学工作区计划

> 制定日期：2026-07-30
> 发布基线：`v1.5.6`
> 建议周期：5 个单人串行阶段
> 版本定位：安全、可解释、可降级的统一 AI 教学工作区

## 1. 规划结论

v1.6 建议停止继续扩张同级管理页面，把重点放在 v1.5.6 已统一的本地/网络 AI 入口上，将目前“可生成草稿”的能力提升为可安全配置、可解释调用、可验证回归、可课堂使用的完整工作流。

本版本完成后，用户可以在一个 AI 助手中选择本地 Ollama 或受支持的 OpenAI-compatible Provider，安全保存设备级配置，明确看到即将发送的上下文范围，并使用统一的 NL2SQL、SQL 错误解释和教师反馈草稿能力。任何 AI 输出仍然只是待审查草稿，不得自动执行 SQL、自动判分或自动发布反馈。

当前 GitHub 没有未关闭 Issue，因此本计划以 `v1.5.6` 的已知边界、现有代码结构和发布记录为基线；后续新缺陷先分级进入本计划，不直接打断正在进行的阶段。

## 2. 成功标准

| 指标 | v1.6 目标 |
|---|---|
| Provider 配置 | 本地 Ollama 与网络 Provider 使用统一配置模型；网络密钥经 Windows DPAPI 加密保存，明文不落盘、不入日志。 |
| 能力探测 | 保存前可测试端点、认证、模型列表和基础响应；失败时提供可操作且脱敏的提示。 |
| AI 主流程 | NL2SQL、SQL 错误解释、教师反馈草稿共用 Provider、超时、取消、审计和降级机制。 |
| 上下文透明度 | 调用前展示将发送的数据类别、字数和来源；默认不发送学生身份、凭据、完整数据库内容或无关课程全文。 |
| 安全 | AI 不持有 JDBC 连接、不自动执行 SQL；无限模式不改变 AI 安全审查结果。 |
| 稳定性 | Provider 不可用、限流、超时、格式错误或应用重启时，本地 SQL、确定性评测和模板提示仍可使用。 |
| 回归 | 固定 Prompt/响应样例可重复运行；结构解析、安全拦截和降级路径均有自动化测试。 |

### 3.3 明确不纳入 v1.6

- AI 自动执行 SQL、自动确认高风险 SQL、直接访问 JDBC 连接或继承无限模式。
- AI 自动判分、自动发布教师反馈、自动修改题库或课程资料。
- 通用聊天机器人、联网搜索、网页浏览、Agent 工具调用和第三方插件市场。
- 云端托管用户 API Key、代付模型费用、计费、套餐和采购流程。
- 向量数据库或大规模 RAG 平台；v1.6 继续使用授权、限长的本地知识检索片段。
- Web/移动端、SSO、学校级多租户、新数据库方言和正式在线考试。
- 为追求兼容性而关闭 TLS 校验、允许公开 HTTP Provider 或记录完整 Prompt/响应。

## 4. 核心设计原则

- **统一入口，不统一信任**：本地和网络 Provider 共用应用层契约，但网络调用需要更严格的隐私预览、密钥保护和错误脱敏。
- **任务化而非聊天化**：每次调用具有明确任务类型、结构化输入、结构化输出和最大长度，避免无边界对话上下文。
- **确定性规则优先**：SQL 风险、成绩、权限、推荐事实和反馈状态由 Java 规则决定；AI 只能解释或生成草稿。
- **最少数据出站**：默认只发送完成任务所需字段；学生 ID、账号、令牌、密码、数据库样本行和无关文档不得进入网络 Prompt。
- **安全模式正交**：设备无限模式只影响用户手动 SQL 执行，不能放宽 AI 输出解析、安全审查或自动化权限。
- **可恢复降级**：网络失败不清空用户输入；可切回本地 Provider、模板解释或纯手写 SQL。
- **控制器轻量**：JavaFX 控制器只管理表单和异步状态，Provider、上下文、脱敏、审计与重试位于 application/infrastructure。

## 5. 建议架构增量

### 5.1 应用层契约

建议新增或收敛以下概念，命名以实施时的现有代码兼容性复核为准：

| 概念 | 职责 |
|---|---|
| `AiProviderProfileService` | 管理非敏感 Provider Profile，并通过密钥存储接口引用凭据。 |
| `AiProviderProbeService` | 测试端点、认证、模型列表和最小响应，不暴露原始异常。 |
| `AiTaskService` | 按任务类型编排请求、取消、超时、解析、审查、降级和审计。 |
| `AiContextPolicy` | 决定每类任务允许使用的数据类别、字段和长度。 |
| `AiContextPreview` | 向 UI 提供即将发送的数据类别、来源、字符数和删减说明。 |
| `AiTaskResult` | 返回结构化草稿、Provider/模型、状态、警告、来源和安全审查结果。 |

依赖方向保持：

```text
desktop -> application -> domain
infrastructure -> application/domain
```

Provider 实现不得依赖 JavaFX；application 不得依赖 HTTP、DPAPI 或具体模型 SDK。

### 5.2 本地存储

- Provider 非敏感配置写入 `app-data/ai-providers.json`，包含格式版本、名称、HTTPS 端点、模型和启用状态。
- API Key 单独写入 DPAPI 加密存储，Profile 只保存凭据引用，不保存明文或可逆日志片段。
- Prompt 继续位于版本化资源目录；运行时记录 Prompt 版本号，不记录完整敏感上下文。
- 配置迁移必须只追加且可重复执行；损坏配置按 Profile 隔离，不阻止 SQLite 主流程启动。

### 5.3 网络与 Provider 边界

- 默认只允许 HTTPS；`localhost`/`127.0.0.1` 可使用 HTTP 以支持本地服务。
- 重定向后重新检查协议和主机，禁止从 HTTPS 跳转到公开 HTTP。
- 设置连接、读取和总体超时；限制响应体、模型列表和错误正文大小。
- 认证、超时、限流、服务不可用、模型不存在和格式错误映射为稳定错误码。
- 日志只记录 Profile ID、Provider 类型、任务类型、模型、耗时和结果码。

## 7. 必测场景

| 场景 | 正常路径 | 必测边界 |
|---|---|---|
| Provider 配置 | 保存 HTTPS Profile、加密密钥、测试并选择模型。 | 公开 HTTP、重定向降级、坏证书、错误 Key、损坏配置、密钥删除和账号切换。 |
| NL2SQL | 使用 schema 生成结构化 SQL 草稿并展示风险。 | Prompt 注入、多语句、DROP、超长 SQL、方言错误、非 JSON、无限模式已启用。 |
| SQL 错误解释 | 使用脱敏错误码和 SQL 摘要给出修正建议。 | JDBC 原始异常含密码、SQL 过长、无 Provider、超时和模板降级。 |
| 教师反馈草稿 | 根据确定性结果和授权知识片段生成可编辑反馈。 | 他人学生数据、未授权课程、AI 改变成绩、空证据和重复发布。 |
| 草稿修订 | 用户提出修订要求，生成完整新草稿并再次审查。 | 上下文越积越大、修订要求绕过安全、取消、快速重复点击和旧响应晚到。 |
| 隐私预览 | 调用前展示数据类别、来源、规模和删减。 | 空上下文、超限截断、用户取消、Provider 切换和本地 Provider。 |
| 降级恢复 | 网络失败后保留输入并切换本地或模板结果。 | 应用重启、限流、服务恢复、模型被删除和半完成响应。 |

## 8. 自动化测试策略

### 8.1 必增测试

- DPAPI 凭据：密文不等于明文、当前用户可解密、删除、损坏和错误引用。
- Profile：格式版本、字段校验、HTTPS/回环规则、原子保存、损坏隔离和迁移幂等。
- Provider Probe：认证、模型发现、重定向、超时、限流、响应限长和错误脱敏。
- Task 编排：取消、重试上限、输出限长、结构解析、Provider 切换和确定性降级。
- 上下文策略：字段白名单、来源授权、字符预算、学生身份/凭据排除和预览一致性。
- Prompt 回归：SQLite/MySQL/MariaDB、中文、空 schema、恶意文本和各 SQL 风险等级。
- UI 逻辑：加载/成功/错误/取消状态、重复点击、页面离开、键盘焦点和禁用原因可读性。
- 回归：SQL 风险、无限模式边界、任务快照、反馈权限、通知幂等、云同步和备份恢复。

### 8.2 验证节奏

聚焦测试按当前工作项运行；以下节点运行完整回归：

```powershell
mvn test
```

- Provider Profile 与凭据存储完成后。
- 三类 AI 任务迁移完成后。
- 上下文策略或 Prompt 版本变更后。
- 发布候选打包前。

发布候选运行：

```powershell
.\packaging\package-stage1.ps1
```

UI 人工检查继续由发布负责人执行；自动门禁验证 FXML/CSS 资源、控制器状态和业务行为，不把像素截图比较作为唯一依据。

## 9. 发布门禁

- P0 全部完成，P0 缺陷为 0；P1 未完成项有明确裁剪记录。
- `mvn test` 全量通过，v1.5.6 的 SQL、权限、同步、迁移和主题资源测试无回归。
- 至少完成 Ollama 和一个 OpenAI-compatible 测试 Provider 的能力探测与三类任务演练。
- 仓库、日志、导出、备份、ZIP、EXE 和 app-image 均不含明文 API Key、令牌、数据库密码或运行数据。
- 网络出站样例证明禁止字段不会进入 Prompt；上下文预览与实际发送摘要一致。
- 无限模式开启时，AI 草稿仍经过解析、方言与风险检查，仍不能自动执行。
- 断网、超时、限流、无模型、坏 JSON 和 Provider 删除场景均可理解地降级。
- Windows 10/11、125%/150% 缩放的 AI 主流程由发布负责人完成安装包人工验收并记录结果。
- `target/installer` 生成 v1.6.0 EXE、ZIP、app-image 和只含当前版本的 `SHA256SUMS.txt`。
- `main`、`v1.6.0` 标签、GitHub Actions 和公开 Release 三项附件状态一致。

## 10. 风险与裁剪顺序

| 风险 | 应对 | 工期不足时的裁剪 |
|---|---|---|
| Provider 差异扩大适配成本 | 只冻结 OpenAI-compatible 最小契约和 Ollama；能力探测记录真实支持项。 | 裁剪 Provider 预设数量，不裁剪连接测试和错误脱敏。 |
| 密钥持久化引入泄露风险 | DPAPI 与非敏感 Profile 分离；禁止导出密钥；日志按字段白名单。 | 可退回会话级密钥，不得明文落盘。 |
| 上下文功能演变为大规模 RAG | 继续使用授权 FTS5 片段、明确字符预算和来源。 | 裁剪多文档选择，不裁剪隐私预览与字段白名单。 |
| 草稿修订形成无界对话 | 每轮提交结构化任务摘要，只保留有限轮次和总字符预算。 | 裁剪历史复用，保留单轮修订。 |
| AI 结果被误解为事实或成绩 | UI 明确“草稿”；确定性结果单独展示；发布动作保持人工确认。 | 裁剪语言润色，不裁剪事实/草稿区分。 |
| 单人同时修改 UI、网络和安全导致回归 | 严格按五阶段串行；先契约和测试，再接 UI。 | 裁剪 P1 和视觉细节，不并行新增业务页面。 |

裁剪顺序：历史收藏 → 教师表达模板 → 每日用量提醒 → 多 Provider 预设 → 多轮草稿修订 → AI 页面视觉精修。DPAPI/会话级安全替代、连接测试、上下文最小化、隐私预览、结构化输出、安全审查、确定性降级和完整回归不可裁剪。
