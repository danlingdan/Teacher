# SQLTeacher v1.9 可验证教学编排与自适应学习计划

> 制定日期：2026-08-01
> 发布基线：`v1.8.6` / `0b474ab`
> 目标版本：`v1.9.0`
> 实施方式：单人、七阶段串行交付
> 核心方向：课程目标图谱、确定性学习计划、带引用的辅导会话、教师教学编排和跨设备闭环

## 1. 规划结论

v1.8.6 已经具备题库、任务、确定性评测、学习诊断、课程知识、混合 RAG、联网来源、云端共享知识和生产 Qdrant。下一步的主要问题不再是“能否找到资料”，而是这些能力仍以页面和服务为单位存在：课程目标没有统一进度口径，学生的练习、反馈、知识阅读和 RAG 提问没有形成连续计划，教师也不能围绕一个教学目标完成发布、观察、干预和复盘。

v1.9.0 定位为“可验证的个性化教学编排版本”：

- 教师把课程章节、知识点、先修关系、题目和资料组织成可版本化的课程目标图。
- Java 确定性策略依据授权事实生成短周期学习计划，不让 AI 决定掌握度、优先级或正式任务。
- 学生从统一学习工作台执行“复习知识 → 完成练习 → 查看反馈 → 必要时提问”的连续动作。
- RAG 辅导只在授权资料和稳定引用内解释，不能改分、代答正式任务或扩大检索权限。
- 教师围绕教学目标查看班级证据、创建干预草稿、发布复习任务并观察后续变化。
- 本地离线仍可完成练习、诊断和个人计划；云端只同步必要事实、发布状态和动作状态。

目标闭环：

```text
教师定义课程目标与先修关系
→ 关联知识文章、题目版本和任务模板
→ 学生完成练习 / 阅读 / 任务并产生事实证据
→ 确定性策略生成掌握快照与 7 天学习计划
→ 学生按计划复习、练习、查看反馈或发起有引用的辅导
→ 新证据触发增量重算，展示计划变化原因
→ 教师按目标查看班级分布与干预候选
→ 教师审核并发布复习任务或反馈
→ 记录干预前后变化，进入下一轮课程复盘
```

## 2. 发布基线与现实约束

### 2.1 已有能力

| 能力 | v1.8.6 基线 |
|---|---|
| 本地事实与诊断 | app schema 9；SQL 练习、确定性评测、学习事件、四档掌握诊断、学生队列和教师干预队列。 |
| 教学协作 | 账号、班级、课程、章节、知识点、题目版本、任务快照、提交、反馈、通知和离线同步。 |
| 课程知识 | Markdown/TXT/PDF/DOCX 导入、不可变修订、发布边界、阅读状态和知识点关联。 |
| 本地检索 | SQLite FTS5 + Lucene HNSW + Ollama Embedding + RRF，模型不可用时回退 FTS5。 |
| 云端检索 | Cloud schema 4、事务 Outbox、FastEmbed 512 维向量、Qdrant、课程/可见性过滤和返回后二次授权。 |
| AI 边界 | 本地/网络 Provider、发送前预览、上下文白名单、引用校验、确定性降级和 SQL 草稿安全复核。 |
| 发布基线 | 326 项自动化测试；Windows EXE/ZIP、GitHub Actions、生产 HTTPS、备份和恢复门禁已建立。 |

### 2.2 必须正视的缺口

- 知识点主要是目录项，没有课程目标、先修边和可验证完成条件。
- 当前学生队列是“下一步建议”，不是可保存、可完成、可重算并解释变化的短周期计划。
- 诊断、知识阅读、RAG 提问、任务和教师反馈之间缺少统一证据引用和稳定关联 ID。
- 教师干预以候选列表为主，缺少按课程目标组织的课前准备、课中观察和课后复盘工作流。
- AI 辅导结果虽有引用边界，但缺少会话级目标、学习者动作、帮助反馈和“是否回到练习”的闭环指标。
- 本地与云端目前同步事实和部分内容，计划动作状态、目标版本失效和多设备冲突尚未冻结。
- v1.8.6 生产知识集合当前为空；已有 2 Point 隔离端到端证据，但不能据此宣称真实大规模课程负载已经验证。
- 当前代码仍是单 Maven 模块和单节点 Cloud 服务，v1.9 不宜同时启动微服务拆分、多节点部署或新客户端。

## 3. 成功标准

| 维度 | v1.9.0 发布目标 |
|---|---|
| 课程目标 | 教师可定义目标、先修关系、完成条件和关联资源；环路、跨课程引用和失效版本被拒绝。 |
| 学习计划 | 每名学生生成 3～7 个未来 7 天动作；相同事实与策略版本产生相同计划、顺序和原因。 |

| 证据可追溯 | 每个计划动作和干预候选都能定位到掌握快照、任务、反馈、阅读或练习事实。 |
| 辅导可靠性 | RAG 辅导实质结论引用覆盖率 ≥ 0.95，未知引用接受率为 0，无依据问题正确拒答率 ≥ 0.95。 |
| 教师效率 | 教师可按目标筛选班级状态，批量形成草稿；任何正式任务和反馈仍需人工确认。 |
| 权限安全 | 本人、班级、课程、PRIVATE/PUBLISHED、退课、停用、换号和旧缓存越权泄露为 0。 |
| 离线与冲突 | 断网时个人计划、练习和知识浏览可用；恢复后重复事件不重复计数，冲突有明确处理结果。 |
| 性能 | 10,000 条个人事件重算计划 p95 ≤ 750 ms；500 名学生班级目标汇总 p95 ≤ 2 s。 |
| 云端负载 | 脱敏夹具 100 门课程、100,000 知识片段、10,000 计划动作、并发 30 只读请求通过门禁。 |
| 可恢复性 | 派生计划、目标汇总和向量索引均可重建；事实数据库升级、备份和恢复不丢数据。 |

所有性能数字使用固定夹具、固定硬件和至少 3 次预热、10 次测量记录 p50/p95/max。不得通过取消授权复核、缩短事实窗口或降低引用校验来换取指标。

## 4. 核心设计原则

- **课程目标是结构，不是 AI 标签**：目标、先修边、完成条件和关联资源由教师定义或审核。
- **事实先于计划**：计划只消费评测、任务、反馈、阅读和同步事实；AI 不参与排序和完成判定。
- **计划可重算**：计划是带策略版本的派生状态，损坏或过期后可从事实重新生成。
- **变化必须可解释**：新增、上移、下移、完成、过期和解除都产生稳定原因码。
- **少而可执行**：默认 7 天、3～7 项；不生成无限清单、焦虑性警告或惩罚排名。
- **辅导必须回到学习动作**：AI 回答的终点是引用、原文、示例或关联练习，不是持续闲聊。
- **教师始终在环**：批量能力只能生成草稿或选择集，正式发布必须预览、确认并审计。
- **权限前后双检**：候选进入计划/辅导前过滤，返回或执行动作前再按当前成员关系复核。
- **本地优先、云端增强**：断网不阻断个人闭环；云端负责协作、跨设备和授权共享。
- **不扩大 AI 信任**：Provider、模型大小、教师身份和无限 SQL 模式都不能绕过安全规则。

### 5.3 明确不纳入 v1.9

- 自治 Agent 自动执行 SQL、修改数据库、发布题目、发送反馈或创建正式任务。
- AI 自动评分、改变确定性掌握度、决定学生能力标签或选择惩罚性干预对象。
- 学生排行榜、班级排名、同伴比较、摄像头/屏幕监考和行为画像。
- 基于性别、地域、家庭、设备或其他敏感属性进行推荐。
- 代替学生完成正式作业的“答案模式”，以及绕过引用或课程范围的自由聊天。
- 新建 Web、移动端、浏览器插件、第三方 LMS 深度集成或学校级计费系统。
- 微服务拆分、Kubernetes、多节点 Qdrant、消息队列平台和新的云数据库。
- 自动抓取整个互联网、绕过登录/付费墙/robots 或永久保存未经授权网页全文。
- 新数据库方言、复杂 SQL 优化器、自然语言直接执行 SQL和 AI 自主工具调用。

## 6. 建议领域与应用契约

| 契约/对象 | 职责 |

依赖方向保持：

```text
desktop -> application -> domain
infrastructure -> application/domain
server -> application/domain
```

计划策略、目标图校验和证据解析不得依赖 JavaFX、HTTP、Qdrant 或具体 AI Provider。AI 只消费限长、脱敏且已经授权的目标/证据/引用摘要。

## 7. 确定性计划口径

### 7.1 默认计划窗口

- 窗口为未来 7 天，默认生成 3～7 个动作。
- 正式且临近截止的任务优先于个人复习目标。
- 未读教师反馈优先于相同知识点的新练习。
- 先修目标未达到最低证据条件时，不把高阶目标标记为“薄弱”，而是生成先修复习动作。
- 少于 3 次有效尝试时继续使用 `INSUFFICIENT_EVIDENCE`，不制造能力结论。
- 已完成、撤回、停用、失去权限或版本失效的资源不得继续作为可执行动作。

### 7.2 默认优先顺序

1. 已发布且即将到期或逾期的正式任务。
2. 教师已发布但尚未查看/处理的反馈。
3. 阻塞其他目标的先修缺口。
4. 有足够证据的重复失败目标。
5. 中断但未完成的练习。
6. 最近阅读后尚未练习的目标。
7. 学生个人目标中的可选练习。

同一任务、题目、知识文章或目标在一个计划中只出现一次。分数相同时使用动作类型、截止时间、事实更新时间和稳定 ID 排序，保证重启和跨设备结果一致。

### 7.3 变化原因码

至少冻结：

- `ASSIGNMENT_DUE_SOON`
- `ASSIGNMENT_OVERDUE`
- `UNREAD_FEEDBACK`
- `PREREQUISITE_GAP`
- `REPEATED_FAILURE`
- `HINT_DEPENDENCY`
- `INTERRUPTED_PRACTICE`
- `READING_WITHOUT_PRACTICE`
- `PERSONAL_GOAL`
- `ACTION_COMPLETED`
- `RESOURCE_WITHDRAWN`
- `PERMISSION_REVOKED`
- `EVIDENCE_EXPIRED`
- `POLICY_VERSION_CHANGED`

## 8. 数据与迁移策略

### 8.1 app schema 10

计划追加：

- `course_objective_cache`：授权课程目标的本地镜像、版本与状态。
- `objective_resource_cache`：目标与知识、题目、任务模板的关联镜像。
- `study_plan_snapshot`：策略版本、事实水位、窗口与生成状态。
- `study_plan_action`：稳定动作键、原因、优先级、资源、状态和解除条件。
- `study_plan_evidence`：动作到本地/云端事实的最小引用，不复制敏感正文。
- `study_plan_outbox`：动作状态的幂等同步任务。
- `grounded_tutor_session`：目标、检索快照、模型、引用哈希和降级状态。
- `grounded_tutor_feedback`：枚举反馈、时间和可选限长说明。

迁移要求：

- schema 9→10 在事务中完成，失败保持 schema 9 可启动。
- 目标缓存和学习计划属于可重建派生状态，不进入不可恢复的事实备份口径。
- 旧学习队列在首次生成新计划前继续可用，不能出现升级后空首页。
- 未知未来 schema 继续拒绝启动，备份恢复必须校验版本和完整性。

### 8.2 Cloud schema 5

计划追加：

- `course_objectives`
- `objective_prerequisites`
- `objective_resource_links`
- `teaching_cycles`
- `study_plan_action_state`
- `study_plan_sync_operations`
- `intervention_audit_v2`
- `tutor_feedback_summary`

Cloud 保存课程结构、发布状态、必要动作状态和审计事实，不保存本地未发布草稿、完整 AI Prompt、数据库样本行或无界对话正文。

### 8.3 版本与失效

- 课程目标、资源关联和教学周期使用乐观锁版本。
- 题目、知识文章和任务继续引用不可变版本或内容哈希。
- 目标停用、资源撤回、学生退课或角色切换立即使相关动作不可执行。
- 派生计划保存事实水位和策略版本；任一变化均触发重算，不原地伪造历史计划。

## 9. RAG 辅导边界

辅导请求必须绑定当前身份、课程、目标和检索快照：

```text
学生问题
→ 当前课程/目标授权
→ 本地或 Cloud 混合检索
→ 返回后二次授权与修订复核
→ 上下文预算、来源多样性和引用编号
→ 发送前预览（网络 Provider）
→ AI 解释或确定性摘要
→ 引用白名单验证
→ 原文 / 示例 / 关联练习动作
```

强制规则：

- 正式任务进行中默认不给出完整最终 SQL，只提供概念解释、定位问题和渐进提示。
- 模型要求忽略规则、伪造引用、访问其他课程或修改成绩时必须拒绝。
- 没有足够证据时明确回答“当前课程资料不足”，可由用户单独确认联网搜索。
- 辅导会话不参与掌握度计算；只有后续真实练习、任务和反馈事实进入诊断。
- 默认不长期保存完整问答正文；保留目标、引用哈希、模型、结果码和枚举反馈即可。

## 10. 教师教学编排

教师工作台围绕“课程目标”而不是学生标签组织：

- **课前**：检查目标资源完整性、先修缺口、资料索引状态和预习动作草稿。
- **课中**：查看任务提交、常见错误、目标证据分布和待处理反馈，不实时监控屏幕行为。
- **课后**：查看未完成、重复失败、反馈未读和目标变化，形成复习任务/反馈草稿。
- **复盘**：比较干预前后事实窗口、完成率和错误类型变化，不做未经控制变量的因果结论。

批量操作必须遵守：先筛选 → 展示影响人数与资源版本 → 生成草稿 → 预览 → 明确确认 → 写审计。任何一步权限或版本变化都使确认令牌失效。

## 11. 权限与隐私矩阵

| 数据/动作 | 学生 | 授权教师 | 管理员 |
|---|---|---|---|
| 本人计划、证据与辅导引用 | 读/更新本人动作状态 | 仅在班级教学证据范围读取摘要 | 运维默认不可读正文 |
| 课程目标与已发布资源 | 只读已发布且有权限内容 | 课程所有者可编辑/发布 | 仅授权运维操作 |
| PRIVATE 草稿 | 不可见 | 仅所有者可见 | 默认不可见，除非明确审计流程 |
| 班级目标汇总 | 不可见其他学生 | 当前授权班级可见 | 只读健康摘要，不隐式获得教学权限 |
| 反馈/任务草稿 | 不可创建 | 可创建和审核 | 不代替教师发布 |
| 正式发布 | 不可执行 | 明确确认后执行 | 不通过后台绕过教师确认 |
| Qdrant/Embedding | 不可直连 | 不可直连 | 仅服务端运维凭据 |

账号切换时必须清理内存会话、查询结果、辅导引用和上一账号计划缓存；磁盘缓存使用账号/课程稳定范围隔离。

## 12. 测试与评测策略

### 12.1 固定教学旅程

至少建立 30 条端到端旅程：

- 8 条任务到期、提交、反馈、计划刷新的正常旅程。
- 6 条先修关系、证据不足、重复失败和提示依赖旅程。
- 5 条知识阅读、语义检索、辅导引用和返回练习旅程。
- 5 条教师筛选、草稿、确认、版本冲突和干预回看旅程。
- 6 条断网、重复同步、退课、停用、换号和权限撤销旅程。

测试数据全部使用合成学生、课程和 SQL 数据，不含真实学生信息或未授权教材全文。

### 12.2 必测类别

| 类别 | 重点场景 |
|---|---|
| 目标图 | 环路、孤立目标、跨课程边、停用、排序、并发版本和资源撤回。 |
| 计划策略 | 稳定排序、限长、去重、证据不足、先修阻塞、到期、解除和策略升级。 |
| 生命周期 | 开始、完成、忽略、过期、失效、重算和旧页面异步结果。 |
| 证据 | 事实引用存在性、版本、水位、删除恢复和不复制敏感正文。 |
| 辅导 | 引用、拒答、正式任务提示边界、注入、模型离线、超时和取消。 |
| 教师编排 | 班级授权、批量草稿、确认令牌、版本冲突、重复提交和审计。 |
| 同步 | Outbox、重复/乱序事件、部分失败、多设备冲突、退课和换号。 |
| 迁移恢复 | app 9→10、Cloud 4→5、重复迁移、失败回滚、备份和未来版本拒绝。 |
| 性能 | 10,000 事件个人计划、500 学生汇总、100,000 云端片段和并发只读请求。 |

| 打包 | EXE/ZIP/校验和、HTTPS、模型/向量不打包、旧产物清理和升级启动。 |

### 12.3 RAG 质量集扩展

在 v1.8.5 的 40 问基线上扩展到至少 100 条：

- 40 条 SQL 概念和同义表达问题。
- 20 条需要结合目标与先修知识的问题。
- 15 条正式任务中的渐进提示问题。
- 15 条无答案、越权、PRIVATE 或撤回内容问题。
- 10 条联网时效、提示注入和引用伪造问题。

## 13. 运维与恢复

- `/health` 继续覆盖 Cloud、Embedding、Qdrant 和索引积压，并新增计划同步/重算积压摘要。
- 管理指标只记录数量、延迟、错误码、策略/模型版本和稳定范围 ID，不记录完整问题、答案或正文。
- 为计划 Outbox、知识 Outbox 和同步队列分别设置上限、失败率和最老任务年龄告警。
- Cloud SQLite 是课程结构与协作事实来源；Qdrant、目标汇总和计划快照均为派生状态。
- 备份恢复演练必须覆盖 Cloud schema 5、Qdrant 快照、计划重算和目标版本一致性。
- Qdrant、Embedding、网络 AI 或联网搜索任一故障都不能阻断登录后的本地练习和确定性计划。
- 生产仍维持单节点、loopback 后端端口和 Nginx HTTPS 边界；v1.9 不引入新公开端口。

预计 16～24 个单人工作日。每次只推进一个纵向阶段；课程目标、学生计划和教师编排不同时铺开未完成实现。`pom.xml` 在阶段 7 发布门禁前继续保持当前正式版本，中间里程碑使用提交和阶段报告追踪，不提前创建 `v1.9.0` 标签。

## 15. 测试节奏

- 计划建立阶段无需构建；进入实现后，每个服务变更先运行最小聚焦测试，阶段闭环运行全量回归。
- 每个服务变更先运行最小聚焦测试；迁移、权限、计划口径、同步和引用变化必须有对应回归。
- 阶段 3、5、6 完成或累计高风险变更时运行完整 `mvn test`。
- 性能与 100,000 片段夹具使用独立 Maven Profile，不混入每次普通单元测试。
- 阶段 7 执行最终完整测试、app-image 启动、EXE/ZIP/校验和、敏感路径扫描、生产 HTTPS、Qdrant 快照恢复和 GitHub Release 验证。

## 16. 发布门禁

- V19-01 至 V19-13 全部完成，P0 缺陷为 0；P1 裁剪逐项记录。
- app schema 9→10、Cloud schema 4→5 升级、重复启动、失败回滚、备份恢复全部通过。
- 课程目标图不存在环路、跨课程资源泄露或悬空可执行动作。
- 相同事实、策略版本和授权范围生成相同计划；计划变化均可解释。
- 学生只能访问本人计划和授权资源；教师只能访问当前班级；管理员不隐式获得教学正文权限。
- AI/Embedding/Qdrant/联网搜索全部不可用时，本地练习、评测、诊断、计划和知识 FTS 仍可用。
- 正式任务辅导不会直接给出未授权完整答案，未知引用和越权引用接受率为 0。
- 10,000 事件、500 学生和 100,000 云端片段性能夹具达到目标并保存报告。
- Cloud/Qdrant 备份恢复后目标版本、事实水位、Point 数和抽样查询一致。
- Windows app-image、EXE、ZIP、`SHA256SUMS.txt`、GitHub Actions 和公开 Release 均通过。
- `main`、`v1.9.0` 标签、Release 说明、迁移版本、生产状态和运维 Runbook 一致。

## 17. 风险与裁剪顺序

| 风险 | 应对 | 工期不足时的裁剪 |
|---|---|---|
| 课程目标图过度复杂 | 首版只支持同课程有向无环图、少量完成条件和显式教师编辑。 | 裁剪可视化拖拽，不裁剪环路/版本校验。 |
| 学习计划被误解为能力评价 | 展示证据、数据量、更新时间、解除条件和“数据不足”。 | 裁剪综合进度百分比，不裁剪原因码。 |
| 推荐制造学生焦虑 | 3～7 项限长、可忽略、行动式文案、无排行榜。 | 裁剪日历，不裁剪限长和解释。 |
| AI 辅导变成代答 | 绑定任务状态、渐进提示、引用和教师策略，记录结果码。 | 裁剪生成式辅导，保留检索与引用摘要。 |
| 教师批量操作误发 | 草稿、影响预览、短期确认令牌、版本复核和审计。 | 裁剪批量发布，只保留逐项操作。 |
| 多设备计划状态冲突 | 事实优先、幂等键、字段级规则和明确冲突结果。 | 裁剪跨设备忽略状态，不裁剪事实同步。 |
| 班级汇总泄露学生信息 | 当前成员关系过滤、最小字段、分页和导出白名单。 | 裁剪高级分组，不裁剪权限。 |
| Cloud 单节点容量不足 | 固定夹具、分页、索引、限流、积压和磁盘门禁。 | 降低默认容量，不引入未验证集群。 |
| 版本范围继续膨胀 | 新需求先进入 P1/P2，阶段内只完成当前纵向闭环。 | 按既定顺序裁剪，不增加新 P0。 |

裁剪顺序：运维容量页 → 辅导反馈分析 → 学习日历 → 教学周期模板 → 个人目标 → 练习草稿生成 → 教师 AI 备课草稿 → 课程包 v4 → 高级目标图可视化。不得裁剪：确定性计划、原因码与证据、权限、正式发布确认、离线降级、迁移恢复、引用校验和发布门禁。
