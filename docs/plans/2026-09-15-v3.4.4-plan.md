## 1. 目标与范围

v3.4.4 定位为**体验补齐版本**：两块纯前端 UI 重做（知识页、连接入口）+ 一项全栈 AI 设置恢复。不改 SQL 安全边界；不改检索与 AI 请求的后端语义；IPC 合同保持 additive-within-v1（仅 AIS 组新增方法）。

现状盘点（调研结论，均以基线为准）：

- **知识助教排在正文下方**：`KnowledgePage.tsx` main 区文档阅读（:445-472）与知识助教（:473-521）纵向堆叠；教师角色其后还有官方知识库、Obsidian 导入、单篇管理面板继续下堆（:522-762），阅读与提问都被管理面板推离首屏。
- **知识助教单问单答**：`ask`（:170-183）每次调用 `ai.knowledge.ask`，回答渲染在 `Feedback` 框（:506-519），引用是纯文本段落（:512-517）不可点击跳转；无会话历史、无取消（对比 `DataSqlPage.tsx:1252-1264` 的 requestId 取消模式）。
- **检索结果无高亮、无归属**：结果项（:362-371）只有标题 + snippet，无关键词高亮、无计数、无清除、无课程/章节归属；课程树（:375-398）与分页文章列表（:399-437）两套导航同屏并存，侧栏信息密度高。
- **连接入口深藏**：连接管理在 `DataSqlPage.tsx` 侧栏的 `<details>` 折叠块内（ConnectionManager :292-741，summary :446-454）；顶栏 `topbar-actions`（`App.tsx:359-453`）只有通知（:360-443）、Ctrl K 搜索（:444-451）、版本徽标（:452）。新用户要先找到数据页再展开两次才能见到连接表单。
- **连接选择双轨**：DataSqlPage 本地 `connectionId`（:68）与后端 `selected` 标记（`ConnectionSummary.selected`，`shared/types.ts:356-372`）脱节——页内下拉只改本地（:112-123），管理面板「设为当前」才写后端（:364-371），两处可长期不一致。
- **连接后端零缺口**：`data.connections/save/test/select/delete/dialects` 契约与 Java 侧选中持久化齐备，连接入口搬家是纯前端任务。
- **本地/网络 AI 设置确实无 UI，后端能力完好**：设置页（`SettingsPage.tsx`）6 个面板（外观、题库更新、本机环境、备份、更新通知、关于）无 AI 项，Ollama 只出现在本机环境检测文案；`ui-web/src/shared/ipc.ts:20-23` 仅 4 个 `ai.*` 使用端点，`AiApiSection.java:26-28` 与 `LocalAppContract.java:10-56` 白名单同样只有这 4 个，无任何 provider 配置方法。后端 `SwitchableAiModelProvider.java:37-44`「有网络配置走 OpenAI 兼容、否则本地 Ollama」双通道路由完好；`PersistentNetworkAiSettingsService` 多 Profile 持久化与 API Key DPAPI 加密完好（`AiServiceConfig.java:51-57` 装配 `<dataDirectory>/ai-providers.json` + `ai-provider-keys/`）；`HttpAiProviderProbeService`（测试连接探测）注册于 `AiServiceConfig.java:59` 但全库零调用。历史 UI 是 v1.6.0 JavaFX「AI 助手」页（commit `3933293`：`ai-assistant.fxml` + `AiAssistantController`，含「网络 AI / 本地 Ollama」切换与「API Key 已由 Windows DPAPI 加密保存」文案），v3 迁移计划未列 Provider 管理页，React UI 自第一行起就没有 AI 设置。

### 明确不做

- 不改 SQL 执行与安全边界：`data.connection.*` 契约与 Java 侧连接语义零改动；「测试通过才能保存」闸与凭据内存暂存机制（`DatabaseCredentialSession`）原样保留。
- 不改检索后端（FTS5/向量管道）与 `ai.knowledge.ask` 请求/响应语义；助教会话历史是前端会话概念，每次提问仍为单轮检索问答。
- 不做助教流式输出（现为单次响应，列入积压）。
- 不做本地 Ollama 模型下载/管理 UI；AI 面板对本地通道只读展示状态，模型选择下拉列入积压。
- 不做多个网络 Provider 同时生效/路由策略：沿用既有「单激活 Profile，停用回本地」语义。
- 不动课程活动（EditorPage/ActivityFlow）与顶栏既有元素（通知、搜索、版本徽标）。

## 2. 任务清单

### A. 知识页 UI 优化（KUI-1…4）——对应要求 1

  - 教师四块管理面板（官方知识库、Obsidian 增量导入、单篇与索引管理）整体包进页面底部一个 `<details>`「教师管理」折叠块，展开后内部布局不变；学生角色照旧不渲染。

- **KUI-3（P1）知识助教会话化与引用可点**：

  - 加载态用占位卡替代按钮 busy。
  - 测试：多轮渲染、引用点击切换文档、生成中不可重复提交、清空对话。
- **KUI-4（P2）文档阅读头部**：文档卡顶部加标题、课程/章节、版本号（`KnowledgeArticleDetail` 既有字段），与「标记为已读」同行；markdown 标题目录（TOC）导航列入积压。

### C. AI 设置回归（AIS-1…2）——对应要求 3

调研结论（证据见第 1 节）：网络 AI 设置不是 v3.4.x 某次改动丢失，而是 v3.0 JavaFX→Tauri/React 重写时**从未迁移**。后端「本地 Ollama / 网络 OpenAI 兼容」双通道路由、多 Profile 持久化、API Key DPAPI 加密、连接探测服务全部完好可用，只缺前端与 IPC 配置入口。本组任务恢复 UI，能力全部复用既有 Java 服务，不重新实现加密与路由。

- **AIS-1（P1）桥端点与契约登记**：`AiApiSection` `supportedMethods()` additive 新增 `ai.provider.list/save/activate/remove/test`：
  - list 返回 Profile 元数据（id、名称、端点、模型、启用/激活状态），**不返回任何密钥材料**；save 创建/更新（API Key 只写不回显）；activate/remove 切换「网络 AI / 本地 Ollama」与删除（复用 `AiProviderProfileService` 与 `SwitchableAiModelProvider` 既有语义）；test 复用零调用的 `HttpAiProviderProbeService` 做连通探测（顺带让该 Bean 重新有主）。
  - 契约三处同步登记：`LocalAppContract.java` 白名单、`contracts/ipc/v1/manifest.json`、`lib.rs` 白名单 + 超时预算。
  - 测试：`AiApiSectionTest` 五类方法分发（fake service）；契约三处一致性测试；安全断言——list 响应无密钥字段、save 的密钥不落日志。
- **AIS-2（P1）设置页「AI 模型」面板**：`SettingsPage.tsx` 新增独立面板组件（参照 `BankUpdateSettings` 模式，置于「本机环境与组件」之后、「备份与本地数据」之前）：
  - 面板头显示当前生效通道：「网络 AI · <Profile 名称>」或「本地 Ollama（http://localhost:11434）」。
  - Profile 列表（名称/端点/模型/激活标记）+ 新建/编辑 Dialog（名称、端点 URL、模型名、API Key 密码框——编辑时留空表示沿用已存密钥，显示「已保存，留空不修改」占位）+「测试连接」；操作：启用（切网络 AI）/停用（回本地 Ollama）/删除（确认）。
  - 帮助文案写明降级关系：网络 AI 不可用时自动回落本地 Ollama，均不影响本地 SQL 学习主流程（既有 `SwitchableAiModelProvider` 语义，UI 如实呈现）。
  - `shared/types.ts` 加 `AiProviderProfile` 视图类型、`shared/ipc.ts` 加方法联合类型、`app/queries.ts` 加 provider 查询；`SettingsPage.test.tsx` 补面板渲染、启停、测试连接、密钥不回显断言。

## 7. 决策记录（用户本轮未答复处的默认口径，实施前可调整）

1. **顶栏连接 chip 全局可见**（所有页面、所有角色）：「放在通知按钮旁边」即全局顶栏位置；数据与 SQL 页本身无角色限制，chip 可见性与之一致。
2. **教师管理面板收拢不删除**：四块管理面板整体移入知识页底部 `<details>`，功能与权限判定不变。
