## 1. 目标与范围

v3.6.0 定位为**知识库质量版本**：先修复已定位的正确性缺陷（知识助教检索失效、删除残留、重复导入），再把检索质量（分块、嵌入、召回）做实，最后补齐体验件（索引进度、过滤 UI、分页）。安全边界不动：owner/visibility 过滤语义、AI 不碰 JDBC、检索失败降级路径全部保持；桥契约只做 additive 演进。

现状盘点（2026-09-18 调研与诊断结论，均以基线为准）：

- **知识助教带上下文提问必然失败（已复现，本版最高优先）**：前端把文档上下文拼进问题文本
  （`useAssistantTurns.ts:28`，前缀形如 `（课程：… / 章节：… / 资料标题：…）`，构造见
  `AssistantWindow.tsx:17-19`），注释声称"由 Java 端消费"，但 Java 端从未解析——`AiApiSection.aiKnowledgeAsk`
  （`AiApiSection.java:58-73`）把整段文本原样送入检索；FTS 查询构建 `toFtsQuery`
  （`SqliteKnowledgeService.java:807-820`）按空白切词后**全部 AND 连接**，前缀装饰词在任何资料中都不存在，
  检索恒 0 命中，`DefaultGroundedKnowledgeExplanationService.java:70-73` 返回"未检索到可以支撑回答的课程知识"。
  本机打包版 app.db 只读副本复现：带前缀 AND 查询 0 条，仅"关系模型"17 条。
- **数据层完好**：174 篇文章全部 PUBLISHED、2947 个分块、两个官方 bundle（official-db-concepts 1.0.1、
  thomas-calculus 1.1.1）均在；用户报告的"删过一次记录"不是本故障成因。
- **本地向量索引从未建成**：app.db 中 `knowledge_embedding_profiles` 为 0 行，说明 Ollama 嵌入从未成功写入，
  检索自始至终只在 FTS5 关键词路径上跑（降级路径本身符合设计，但语义检索能力形同虚设）。
- **删除留残留**：单篇删除走 `KnowledgeDocumentService.deleteDocument`，不同步清理 Lucene 向量
  （孤儿向量直到手动 rebuildAll）；2026-09-17 sidecar 日志多笔 `knowledge.article` →
  `COURSE_KNOWLEDGE_NOT_FOUND`（删除后仍可从某入口点开已删文章，入口待实施时复现定位）。
- **分块质量低**：`SqliteKnowledgeService.chunk()`（:434-462）固定 800 字符段落硬切，无 overlap，
  代码块/表格拦腰切断（v1.8.5 计划 §2.2 已列为缺口，一直未做）。
- **FTS 中文召回有限**：分词器为 `unicode61`（`SqliteSchemaMigrator.java:178-183`），无中文分词，
  连续 CJK 文本成整块 token；查询侧硬 AND 进一步放大失配。
- **过滤未下推**：过滤搜索（`SqliteKnowledgeService.java:411-417`）先 FTS 取 50 条再内存过滤，窄过滤欠召回。
- **索引无进度**：`SqliteKnowledgeIndexService` 同步跑在调用线程、单批 100、无进度事件、不可取消；
  UI 仅显示 pending 计数，大 bundle 导入阻塞 IPC。
- **搜索无分页**：`knowledge.search` 只有 limit 无 offset。
- **桌面/云端嵌入配置漂移**：桌面默认 `embeddinggemma`（512 维），服务器 `BAAI/bge-small-zh-v1.5`；
  桌面切换模型不校验已建索引维度（服务端有按批校验），存在静默混维度风险。

### 明确不做

- 云端知识文章的桌面消费端（`HttpCloudApiClient.publishCloudKnowledge`/`searchCloudKnowledge` 现无调用方；
  服务端与 Qdrant 管线保留现状，桌面接入另行立项）。
- 多轮会话/流式知识助教（v3.5.0 计划 §118 backlog）、知识树活动深链（`backlog.md`）。
- 双写 schema（`knowledge_chunks` FTS5 + `knowledge_chunks_v2`）收敛——动 FTS5 触发器链风险大、收益低。
- 云端 Qdrant/FastEmbed/服务器索引管线改动。
- 自动合并/去重删除用户内容（KBF-3 只提示不合并）。

## 2. 任务清单

### A. 知识库正确性（KBF-1…3）——第一批，先做

- **KBF-1（P0）知识助教上下文改为结构化传递**：IPC `ai.knowledge.ask` 参数 additive 增加可选
  `context: { course, section, title }`；前端 `useAssistantTurns`/`AssistantWindow` 不再把前缀拼进问题文本，
  改传结构化字段；`AiApiSection.aiKnowledgeAsk` 用 course/section 构造 `CourseKnowledgeSearchFilter`
  （filter 契约无 title 字段，title 仅作展示，不参与过滤；owner/visibility 语义沿用 `allLocal`），
  问题文本保持纯净。旧前端不带 context 时行为等于现状 `allLocal`，向后兼容。
  - 兜底：若需在 v3.6.0 之前紧急恢复知识助教，可先单独停发前缀（前端单点改动）作为临时手段，
    完整结构化方案仍按本项交付。
  - 测试：桥层参数→filter 映射用例（带/不带 context）；explanation 服务"结构化上下文提问能命中既有文章"用例；
    前端 `useAssistantTurns` 用例更新（问题不含前缀、context 字段断言）。
- **KBF-2（P1）删除一致性**：单篇删除同步调用 `KnowledgeVectorStore.deleteArticle` 清理向量；
  复现定位 2026-09-17 日志中删除后仍可点开已删文章（`COURSE_KNOWLEDGE_NOT_FOUND`）的残留入口并修复
  （候选：搜索结果未刷新、页面状态陈旧），确保删除后搜索、列表、向量三处一致。
  - 测试：删除后向量无残留、搜索无残留命中、再点开报错路径的用例。
- **KBF-3（P2）跨来源重复导入提示**：同一内容以 bundle/手动/Obsidian 导入会并存（现仅 legacy 单文档有
  字节级哈希去重）。导入时按规范化内容哈希检测既有文章并提示（是否仍导入由用户决定），不自动合并。
  - 测试：哈希命中/未命中、跨来源场景用例。

### B. 检索质量（KBQ-1…3）——第二批，本版核心

- **KBQ-1（P0）结构感知分块**：替换 `chunk()` 硬切为标题层级感知分块：代码块/表格不跨块、受控 overlap、
  标题路径随块存储（沿用 `knowledge_chunks_v2` 既有 heading 字段语义）；chunker 版本号入库
  （`knowledge_embedding_profiles` 或 job 表 additive 字段），版本或嵌入配置变化触发自动全量重建
  （复用 `KnowledgeIndexService.rebuildAll`）；若 KBX-1 未先行落地，重建暂走现状同步路径并在 UI 明示。
  - 测试：分块边界用例（代码块/表格/超长段落/overlap/空内容拒绝）；版本变化触发重建用例；schema 迁移用例。
- **KBQ-2（P1）本地嵌入链路打通 + 模型一致性校验**——**已移回积压清单**（2026-09-18 用户确认本机
  Ollama 未安装向量模型，功能暂缓；启动时由 `KnowledgeChunkUpgradeService` 之外的嵌入路径自行就绪后再启用）。
  先定位本机向量索引从未写入的原因
  （Ollama 未运行/模型未拉取/调用失败被降级吞掉），打通并留下可观测证据（profile 行、日志分类）；
  桌面端补 profile 校验：已建索引的 provider/model/dimensions 与当前配置不符时自动触发全量重建并提示，
  不再静默混维度（对齐服务端按批校验语义）。
  - 测试：profile 失配检测与自动重建用例；嵌入失败降级（`degraded=true`）分类用例。
- **KBQ-3（P1）过滤下推与召回修正**：owner/visibility/course/section 过滤下推到 FTS SQL join
  （消除先取 50 再内存过滤的欠召回）；评估 unicode61 对中文查询的影响，必要时把硬 AND 放宽为 OR + bm25 排序。
  改动仅限检索层召回/排序语义，owner/visibility 安全过滤必须在 SQL 层保持，不得退回前端/内存过滤。
  - 测试：过滤下推与内存过滤结果等价性用例；中文短语召回用例（"关系模型"类查询命中数不回退）。

### C. 知识库体验（KBX-1…3）——第三批

## 3. 风险与边界

- KBQ-1 是本版唯一 schema 级改动：需 `SqliteSchemaMigrator` additive 迁移 + 版本判定 + 自动全量重建 +
  旧索引降级路径；实施时先用小库验证再打包，迁移失败必须 fail-safe（保留旧索引可检索）。
- KBQ-3 放宽 AND 不得弱化安全过滤：owner/visibility 条件必须留在 SQL 层；排序变化不得改变引用可见范围。
- KBF-1 改桥契约：仅 additive；`desktop.bridge` 契约测试与前端类型同步必须同 change 提交。
- 全程不改变：SQL 安全路径、AI 不碰 JDBC、多语句封锁、检索失败降级为关键词的既有行为。
