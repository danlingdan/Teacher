  （`mvn test` 780/0/2、`npm test` 159、`npm run build`、`cargo test --lib` 5）；发布说明见
  [v3.5.0](../releases/v3.5.0.md)，署名更新清单已部署并经公网验证。
- 基线：撰写时 `main` @ `a68f57c`（`pom.xml` 3.4.4，工作区仅余用户自有改动）。文中 `file:line` 以该基线为准，实施时以现场为准。
- 来源：用户 2026-09-16 指示"3.5.0 主要提升 SQL 教学体验"。本计划将 v3.3 之后的 SQL 教学相关积压（表结构区增强、课程化练习路径等）与 SQL 工作台/练习反馈的可实证缺口收敛为四个任务组。
- 性质：任务清单，编号前缀 SFE（SQL 反馈深化）、SCH（Schema 助学）、WBE（工作台效率）、EPATH（课程化练习路径）、REL（文档与发布），不与既有计划的 LEG / SET / CLS / SQL / KNW / DB / DOC / CMP / KSR / CXN / OKB / PUB / KUI / CTB / AIS / REL 冲突。

## 1. 目标与范围

v3.5.0 定位为**SQL 教学体验版本**：让学生在"写 SQL → 看反馈 → 懂错在哪 → 知道下一步练什么"的闭环上获得实质提升，并让 Schema 本身成为教学工具。安全边界不动：判分保持确定性（不做 AI 判分）、所有新执行路径仍走 Java 单语句解析/风险分析/确认/审计。

现状盘点（调研结论，均以基线为准）：

- **练习反馈只有对错，缺少"差在哪"**：判分是确定性的（`SqlExerciseEvaluationService.evaluate`，结果集比对 + 关键字结构归一化匹配，见 v3.3 计划 W 系列），错题本有"错题回顾 → 重新作答 → 对比反馈"三步（`WrongBookFlow.tsx:26`），但失败时的差异呈现依赖既有文本反馈，没有行列级"提交结果 vs 期望结果"的可视化对比，学生经常只看到"结果不一致"而不知道差一行还是差一列。
- **数据库报错是生肉**：SQLite 原始错误（如 `FOREIGN KEY constraint failed`、`near "...": syntax error`）直接透出，没有教学化解读（这个错误对应哪个完整性约束、考查哪个知识点）。
- **执行计划是生肉**：工作台"执行计划"（`DataSqlPage.tsx:302` 起，对语句自动包裹 `EXPLAIN QUERY PLAN`，仅支持 SQLite 连接，:396）输出计划行原文，未翻译成"全表扫描 / 索引命中"这类教学结论。
- **Schema 不参与教学**：元数据服务读取 tables/columns/indexes（v3.4.3 CXN-2），**未读外键**（`JdbcDatabaseMetadataService` 无 `getImportedKeys`）；侧栏表结构只能看不能点，没有"点列名插入编辑器"、没有样例数据预览、更没有外键关系图——演示库（Student/Course/SC/SPJ，含自引用先修课与完整外键，用户手册"数据库、SQL 与 AI 安全"节）天然适合画 ER 简图，前端也已有受限 Mermaid 渲染能力（`KnowledgeRenderer.tsx` `MermaidDiagram`，`securityLevel: "strict"`），链路现成。
- **工作台缺少效率件**：无 SQL 格式化、无教学常用语句模板（JOIN / GROUP BY / 子查询骨架）、长语句全靠手敲。
- **练习组织与教材脱节**：题库支持频道更新（v3.1.0 W5）但练习没有"按教材章节组织"的路径视图（v3.3 计划第 7 节已把"课程化练习路径（按教材章节组织）"列为后续候选）；知识点定义/掌握快照（mastery_snapshot）已在库中，但 SQL 练习入口没有按知识点/章节的导航。
- **v3.3 明确的后续候选中，本版只取"课程化练习路径"**；存储过程教学（需第二评测引擎）、事务故障注入判分、AI 判分/语义比对、课堂投影/实时协同继续不做（见"明确不做"）。

| # | 方向 | 现状结论 | 任务 |
| --- | --- | --- | --- |
| 1 | 练习反馈深化 | 确定性判分已有，缺行列级差异与错误教学化解读 | SFE-1…3 |
| 2 | Schema 助学 | 元数据无外键、侧栏不可交互、无样例预览、无 ER 简图 | SCH-1…3 |
| 3 | 工作台效率 | 无格式化、无语句模板 | WBE-1…2 |
| 4 | 课程化练习路径 | 题库有频道无路径，知识点/掌握快照未接入口 | EPATH-1…3 |

### 明确不做

- 不做 AI 判分、模糊/语义比对（v3.3 起持续保持确定性判分边界）。
- 不做存储过程教学与第二评测引擎（H2/PostgreSQL 引入评估另立计划）。
- 不做事务原子性故障注入判分。
- 不做课堂投影、教师实时协同视图、课堂统计大屏（依赖云端闭环，另行立项）。
- 不改变练习会话/评测库隔离架构、单机存储模型与 SQL 安全路径；多语句仍仅限 v3.3 练习沙盒场景。
- 样例数据预览必须走既有 Java 只读执行路径（`query_only` 沙盒语义之外的一般连接强制只读语句 + 行数上限），不在前端拼任意 SQL。
- 不做 ER 图编辑/建模工具，只做从外键元数据生成的只读简图。

## 2. 任务清单

### A. SQL 反馈深化（SFE-1…3）——学生"懂错在哪"

- **SFE-1（P1）结果集行列级对比**：评测失败（结果类题目）时，Java 侧把提交结果与期望结果做行列对比（行数、列数、首个差异行列定位、行多重集合差异摘要），`ExerciseEvaluationResult` additive 扩展差异载荷（行数上限沿用结果上限语义，防超大局”；超出上限时降级为摘要）；练习失败反馈与错题本"对比反馈"步骤渲染并排对比表（提交 vs 期望，差异单元格高亮）。
  - 测试：`SqlExerciseEvaluationService` 实现层补差异构造用例（行差/列差/序差/超上限降级）；前端对比表渲染用例。
- **SFE-2（P1）SQLite 错误教学化解读**：执行/评测错误在既有错误分类基础上追加"教学解读"映射（外键失败 → 指出违反完整性、关联 demo 库对应约束；语法错误 → 定位 near 词并给常见成因；唯一/非空/CHECK 同理）。实现为 Java 侧纯映射表（错误分类 + 消息模式 → 教学文案），不改安全路径；前端错误反馈区追加解读块。
  - 测试：映射表单测（约束/语法/唯一/非空各一）+ 未知错误原样透传用例。
- **SFE-3（P2）执行计划教学解读**：`EXPLAIN QUERY PLAN` 行做模式化解读（`SCAN 表` → 全表扫描、`SEARCH 表 USING INDEX` → 索引命中、`TEMP B-TREE` → 排序/去重临时结构等），在计划原文下方给出逐条白话结论与优化提示（如"可考虑在连接列上建索引"）。仅 SQLite 连接（沿用既有 explainSupported 判定）。
  - 测试：解读映射单测；前端渲染用例。

### B. Schema 助学（SCH-1…3）——让 Schema 成为教具

- **SCH-1（P1）外键元数据**：`JdbcDatabaseMetadataService` 读取 `getImportedKeys`（按表聚合：表、列、引用表、引用列），`DatabaseTable` record additive 扩展 `foreignKeys`（新增 record）；单表读取失败降级空列表（沿用 CXN-2 索引降级模式）；`data.schema` additive 扩展，前端类型同步。演示库为首要受益者（Course 自引用、SC/SPJ 复合外键）。
  - 测试：demo 库建库脚本断言外键读取完整（自引用/复合各一）；失败降级用例。
- **SCH-2（P1）表结构可交互**：侧栏表结构树中列名/表名可点击 → 按安全规则插入当前 SQL 编辑器光标处（表名插入 `表名`，列名插入 `表.列`）；表节点追加"样例数据"动作 → 经既有 Java 只读路径执行 `SELECT * FROM 表 LIMIT 5`（行数上限与超时沿用 execute 语义，只读语句无需确认）并在下方只读表格展示。
  - 测试：插入光标行为、样例预览请求参数与只读断言、错误态。
- **SCH-3（P1）外键关系简图**：基于 SCH-1 外键数据生成 Mermaid `erDiagram` 源码，在数据页以"关系图"入口弹出只读渲染（复用 `MermaidDiagram` 严格模式，只读展示不可编辑）；无外键的连接显示"该连接没有外键关系"。
  - 测试：demo 库 erDiagram 源码生成快照（Student/Course/SC/SPJ 全覆盖）；无外键空态。

### C. 工作台效率（WBE-1…2）

- **WBE-1（P1）SQL 格式化**：编辑器工具栏"格式化"按钮，前端本地实现轻量格式化（关键字大小写归一、换行缩进按子句层级、逗号分列；纯文本处理，不经网络、不改语义），Monaco 内直接替换文本并可撤销（保留 undo 栈）。
  - 测试：格式化用例（SELECT/JOIN/GROUP BY 样例逐字断言）、撤销行为、空/超长输入不崩。
- **WBE-2（P2）教学语句模板**：编辑器旁"模板"入口（JOIN 三表、分组统计、子查询、INSERT…SELECT 等教学常用骨架），点击插入光标处；模板内容为前端常量，与 demo 库表结构命名对齐。
  - 测试：模板插入与占位符存在性断言。

### D. 课程化练习路径（EPATH-1…3）——知道下一步练什么

- **EPATH-1（P1）路径数据模型**：题库 additive 扩展"章节路径"结构（章节序 → 章节（对应教材/知识章节名）→ 题目 id 列表 + 知识点标签），随题库版本分发（沿用 bank_version 单调版本 + 清单分块通道，不新增服务端端点）；旧客户端忽略新字段（v3.1.0 的字段演进模式）。
  - 测试：bank store 新字段存取、旧版本客户端忽略、版本回滚。
- **EPATH-2（P1）练习页路径视图**：练习与实验页新增"学习路径"入口：按章节分组展示题目（完成态/掌握态来自既有 session 与 mastery 数据），点击进入既有练习流；不改变既有推荐与错题本入口。
  - 测试：路径渲染（分组/状态徽标）、点击进入练习流参数、无路径数据时回退现状。
- **EPATH-3（P2）章节 ↔ 知识文章联动**：路径章节与课程知识文章（`course_knowledge_articles` 的 course/section）按名称映射，章节行提供"相关阅读"跳转知识页深链（`?article=`）；无映射不显示。
  - 测试：映射命中/未命中两态。

### E. 文档与发布（REL-1…2）

- **REL-1（P1）guide 回写**：`docs/guide/08-user-manual.md` 补差异对比反馈、错误/执行计划教学解读、表结构交互与关系图、格式化与模板、学习路径章节；`docs/guide/README.md` 索引核对。
- **REL-2（P1，发布时）**：版本 3.4.4 → 3.5.0（`pom.xml`、`tauri.conf.json`、`Cargo.toml`、`package.json`）；`docs/releases/v3.5.0.md`；本计划与索引回写；发布门禁按 `sqlteacher-windows-release` 技能（含发布后签名更新清单替换与公网验证——v3.4.4 已写入技能的强制步骤）。

## 3. 里程碑与排序

| 阶段 | 内容 | 备注 |
| --- | --- | --- |

## 5. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 差异对比在大结果集下失控 | 差异载荷设行数上限，超限降级摘要；上限复用既有 maxRows 语义 |
| 错误解读映射误判（把 A 错误解释成 B） | 映射只基于错误分类与消息模式精确匹配，未命中原样透传；文案标注"常见原因"而非绝对断言 |
| 外键读取在部分方言行为不一 | 沿用 CXN-2 降级模式：单表失败返回空列表，不阻塞整棵结构树；演示库/SQLite 为主验证对象 |
| 样例预览被用于绕过只读 | 只允许表名参数由 Java 侧构造 `SELECT * LIMIT`，前端不传 SQL 文本；语句仍走既有只读执行路径 |
| 格式化破坏语义 | 纯文本重排不改 token 顺序（仅大小写/空白/换行），用例逐字断言；撤销可恢复 |
| 路径模型破坏旧客户端 | additive 字段 + 旧版本忽略（v3.1.0 演进模式）；bank_version 单调回滚机制沿用 |
| 范围膨胀（课堂协同等大件混入） | 明确不做清单锁定；新增方向一律进积压节 |

## 7. 决策记录（默认口径，实施前可调整）

1. **范围四组**：反馈深化、Schema 助学、工作台效率、课程化练习路径；课堂协同/第二评测引擎/事务注入判分不入本版。
2. **判分边界不变**：差异对比只做"展示层"增强，判分结论仍由确定性评估给出。
3. **样例预览与关系图只读**：不提供编辑/建模能力，执行一律走 Java 只读路径。
4. **路径随题库分发**：不新建服务端端点，客户端旧版本忽略新字段。
