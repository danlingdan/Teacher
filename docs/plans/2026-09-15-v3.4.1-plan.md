## 1. 目标与范围

v3.4.1 定位为"易用性修复 + 教学数据完整性修正 + 一个云端协作小功能"，对应六项反馈：

| # | 反馈 | 调研结论（根因） | 任务 |
| --- | --- | --- | --- |
| 1 | 设置页"题库分发"UI 错误（小字标签挤在卡片左上角被裁切） | CSS 塌陷：题库卡片无任何内边距，11px eyebrow 小字顶到 15px 圆角边缘被 `overflow:hidden` 裁切 | SET-1 |
| 2 | "题库分发"与"外观与使用体验"应像其他设置一样可折叠 | 设置页 5 个区块中 3 个已用 `<details>/<summary>`，唯独这两个区块是普通 `<section>` | SET-1、SET-2 |
| 3 | 学生无法主动加入班级，建议每班生成班级码 | 班级只存在于云端协作；唯一入册路径是教师按邮箱添加成员；全库无 joinCode/inviteCode 概念 | CLS-1…6 |
| 4 | 数据库连接下方平铺全部表，表多时不便 | 每张表 `<details open>` 硬编码默认展开，无搜索、无计数、无分组，侧栏被撑爆 | SQL-1 |
| 5 | 检索课程知识页里"活动"为什么在知识里、点不动 | 活动不是检索结果，是常驻课程树里的纯 `<span>`（无点击行为）；另有检索命中映射不到文章时渲染成禁用按钮的第二处"点不动" | KNW-1、KNW-2 |
| 6 | SPJ 表没有外键，是否满足三大完备性 | demo.db 7 张表 **0 外键 / 0 CHECK / 0 UNIQUE / 0 DEFAULT**，且本地 SQLite 连接从未开启 `foreign_keys` pragma——即使声明外键也不会强制 | DB-1…5 |

### 明确不做

- 不在本版开启 app.db 的全局 `foreign_keys`（影响面广，需独立审计，见第 6 节）。
- 不做知识页课程树活动点击跳转（KNW-1 取"移除"方案，备选方案挂起记录）。
- 不做表结构浏览器按表懒加载列与虚拟滚动。
- 不做班级码有效期、停用开关、一课多码、加入审批流。
- 不改 SQL 安全边界（多语句门、高危确认门、FORBIDDEN 语义维持 v3.3 表述）；练习数据集外键属于补强教学口径，不放宽任何执行路径限制。

### E. 演示库与教学数据集完整性（DB）——对应反馈 6

- **DB-1（P1）demo.db 补全三大完整性**：DDL 硬编码在 `SqliteAppDatabaseInitializer.java:99-256`，7 张表现状 **0 外键 / 0 CHECK / 0 UNIQUE / 0 DEFAULT**——SPJ（:170-177）SNO→S、PNO→P、JNO→J 三条外键全缺；SC（:137-145）缺对 Student/Course 的引用；Course（:129-135）Cpno 无自引用约束。仅有主键 + 少量 NOT NULL（实体完整性），参照完整性与用户自定义完整性缺失，用户截图属实。动作：① DDL 补外键——SPJ 3 条、SC 2 条、Course.Cpno 自引用（列保持可 NULL 表示无先修课）；② 初始化顺序改为 `PRAGMA foreign_keys=OFF` → DROP 全部（现顺序 :105-113 父表在前，外键开启会因隐式 DELETE 报约束失败，自引用 Course 尤其如此）→ CREATE 全部 → `PRAGMA foreign_keys=ON` → 种子 INSERT（现顺序已验证 FK 安全：S/P/J :212-233 先于 SPJ :236-254，Course 按 Cno 升序满足自引用）；③ 升级无需迁移——demo.db 每次启动无条件全量重建（`initialize` :41-42；备份恢复路径 `SqliteApplicationBackupService.java:162-185` 走同一 DDL），存量库下次启动自动变为新结构。用户自定义完整性的最小补强：SC.Grade 加 `CHECK (Grade BETWEEN 0 AND 100)`；若实施中发现练习或演示依赖越界值，降级为仅保持现有 NOT NULL 并在本文档记录。
- **DB-2（P1）外键运行期强制——否则外键只是装饰**：SQLite 默认 `foreign_keys=OFF`，本地全链路从未开启（`JdbcConnectionFactory.java:35-59` 只设 busy_timeout + WAL；全项目仅云服务端 store 开启）。不加 pragma，DB-1 的外键声明不会拦截任何违规 DML。动作：`JdbcConnectionFactory` 的 demo 库连接分支开启外键强制，让 SQL 控制台/NL2SQL 对 demo 库的违规写入真实报"FOREIGN KEY constraint failed"——这正是教学要演示的参照完整性行为；更新日志明示该行为变化。**app.db 不在本版开启**（连接级开关可快速回滚；app 库全局开启另版处理，见第 6 节）。
- **DB-3（P1）spj-demo-v1 练习数据集对齐**：`src/main/resources/exercise/exercise-bank-spj.dsl:8-28` 小写 s/p/j/spj 四表同样 0 外键，而 school-core-v2 的 enrollment 已带外键（`exercise-bank.dsl:16-17`），两个教学数据集口径不一。动作：补与 demo.db 相同口径的外键，bump 数据集 VERSION 触发版本化重应用（`ExerciseBankApplier`/`ExerciseBankWriter` 机制）；核对 `ExerciseDatasetSchemaSummary.java:85`（会把 `pragma_foreign_key_list` 展示给学生）的摘要变化，更新 `JdbcExerciseCatalogServiceTest`/`JdbcExercisePracticeServiceTest` 相关断言。
- **DB-4（P2）练习沙箱连接外键一致性**：沙箱与评测库同为裸连接（`JdbcExercisePracticeService.java:261,330`、`DeterministicSqlExerciseEvaluationService.java:290,544,559`）。动作：一次性沙箱连接开启 foreign_keys，使数据集外键在练习中真实生效；跑练习题库全量回归确认无既有题依赖违规数据（`ExerciseDatasetSqlPolicy` 白名单只放行 CREATE TABLE/INDEX 与 INSERT，已确认不拦外键列定义）。
- **DB-5（P2）测试补强**：`SqliteAppDatabaseInitializerTest` 补每表 `pragma foreign_key_list` 计数断言 + 开启 FK 的连接插入孤儿 SPJ 行必须失败的行为断言（现 :47-53 只数行数）；回归 `ReleaseVerificationApp`（:39-98 仅向 Student 插父表行，已评估 FK 安全）与 `SqliteApplicationBackupService` 演示库恢复路径。

| 阶段 | 内容 | 备注 |

| M1 | SET-1/2、SQL-1、KNW-1/2 | 纯桌面 UI，低风险先行；`npm --prefix ui-web test` + `npm run build` 验证 |

## 6. 移至后续版本的已知积压（本轮评估结论）

- **app.db 全局 foreign_keys 开启**：迁移链 1–23 已大量使用外键，风险预计低，但全局开启影响 app 库全部既有读写路径，需独立审计后作为独立小版本处理。
- **知识页课程树活动可点击跳转**（KNW-1 备选方案）：若后续希望"活动可点"而非"移除"，需评估 `learning_activity_definition.source_kind='SQL_EXERCISE'`（legacy-sql 投影）到练习页的路由映射，涉及跨页导航设计，本版不做。
- **表结构浏览器按表懒加载列 / 虚拟滚动**：教学库表数量级小，过滤 + 默认收起已覆盖诉求；表达数百规模再议（届时需扩展 `data.schema` IPC 与 `JdbcDatabaseMetadataService`）。
- **班级码增强**：有效期、停用开关、一课多班多码、加入审批流。
- **表结构浏览增强**：表名点击插入编辑器、右键查看表数据等（超出本轮"布局不合理"诉求范围）。
