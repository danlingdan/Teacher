## 1. 背景与结论

2026-09-08 对练习题目体系做了一次全链路独立审查（题目来源 → 导入 → 会话 → 评测 → 进度），
确认执行架构是健全的：会话库与评测库隔离、判定全部由确定性 Java 代码完成、AI 仅产出
须经确定性校验与教师确认的草稿、学生 SQL 有风险分析与只读/超时/行数四层约束。这些设计不变。

审查同时确认了四类真实问题，本计划据此收敛为一条主线：**把"题目内容"当作需要验收的输入，
在系统入口处把关，并让题目内容可以随版本升级送达存量安装**。

1. **导入不验货**：`ExerciseTextCodec` 只做结构校验，导入全程不执行 setup SQL、不验证参考
   SQL 可执行、不验证参考 SQL 能通过其自身判分规则。坏题目包可以顺利入库，直到学生提交时
   才暴露为"永远判不过"。
2. **错误归因错位**：参考 SQL 执行失败时，评测返回 `SQL_EXECUTION_FAILED` 并提示学生检查
   自己的语法，误导答题者。
3. **判分契约与题面契约不对齐**：`compareColumns` 严格比较列名，但预置题 join-01、
   subquery-04 的题面未声明必需别名 `course_name`，失败反馈也不展示期望列名；aggregate-03
   /04 的"按班级升序"在 SQLite 二进制排序下产出 一班→三班→二班；filter-01 数据使 WHERE
   形同虚设；join-03 数据使 LEFT JOIN 考查点落空；subquery-02/03 题面承诺的结构（子查询、
   NOT EXISTS）未由 `KEYWORDS` 机制兑现。
4. **内置题库不可升级**：`DefaultExerciseCatalogSeeder` 以 `insert or ignore` 写入数据集，
   题目仅有一次性 hints 升级补丁，任何内容修正都无法到达存量安装。
5. **选题 UI 便利性不足**：目录仅支持对标题+知识点的单一子串搜索，平铺列表每页 10 条翻页，
   无难度/知识点/完成状态筛选，学生看不到自己的作答状态（进度仅教师端可见）。

除上述审查结论外，维护者在计划制定时提出新的能力需求：题库在本地内置一份基线，同时能够
通过服务器获取更新，以增量（流式）方式应用到客户端。该需求纳入为本计划 W5，并复用 W1/W3
建立的校验与升级通道。

## 2. 目标与非目标

### 2.1 目标

- 教师导入（含 AI 草稿）的题目包在入库前通过确定性自测；预览阶段即呈现自测结论。
- 评测失败可区分"学生 SQL 问题"与"题目数据/参考答案异常"。
- 判分规则、题面承诺、反馈信息三者一致；学生能从反馈得知期望的结果形状（列名）。
- 内置题库成为随版本携带、按版本升级的内容包，内容修正可到达全部存量安装。
- 预置题目内容缺陷随数据集版本升级一次性修复。
- 选题目录支持筛选、状态标记与分组浏览，减少翻页与盲选。
- 题库支持服务器分发与增量更新：客户端仅下载差异分块、校验后原子应用；离线或服务器
  不可达时本地题库完整可用，不影响练习主流程。

### 2.2 非目标

- 不改变判分内核语义（仍是确定性结果比对），不引入任何 AI 判分。
- 不改变既有云端课程包（JSON）与 `cloud.course.exercise.publish` 流程；网络题库是本计划
  新增的独立分发通道（见 W5），与课程包互不复用、互不影响。
- 不重构练习会话/评测的隔离架构与安全层级。
- 前端不引入新的组件或虚拟列表依赖。
- 除下述 v2 数据集内容外，不改动教材示例库（demo.db）与工作台数据源。

## 3. 已核实基线

- 题库存储：`app-data/app.db` 的 `exercises` / `exercise_datasets`；会话与作答在
  `exercise_sessions` / `exercise_attempts`；学习事件异步写入 `learning_events`。
- 内置 seed：`DefaultExerciseCatalogSeeder`（数据集 `school-core-v1` + 20 题，
  `insert or ignore`，`upgradeSeedHints` 为唯一升级路径）。
- 导入链路：`teaching.exercise.parse` → `ExerciseTextCodec.decode`（结构校验）→
  `teaching.exercise.import` → `JdbcExerciseManagementService.importPackage`（事务；同 ID
  数据集必须逐字节一致；题目引用数据集必须存在）。全程无 SQL 执行与安全检查。
- 评测链路：`practice.submit` → 风险分析（单条 SELECT）→ 会话库执行（`query_only`、10s、
  500 行）→ `DeterministicSqlExerciseEvaluationService` 在一次性评测库上比对
  columns/rows/order/row_count/keywords（评测库行上限 5000）。
- 参考 SQL 失败路径：`evaluate` 中期望查询抛出 `SQLException` 时统一归类为
  `SQL_EXECUTION_FAILED`。
- 表结构摘要：`ExerciseDatasetSchemaSummary.fromSetupSql` 以正则解析 setup SQL。
- 选题 UI：`EditorPage.tsx` 目录为 `title + knowledgePoint` 子串过滤 + 每页 10 条分页；
  `practice.catalog` 返回的 `ExerciseSummary` 不含任何作答状态字段。
- 云端链路现状：服务端 `SqlTeacherCloudServer` 基于 JDK `HttpServer`，loopback 绑定，
  `/api/v1/*` 路由 + Vxx store（SQLite）惯例，admin 接口已有鉴权；桌面端经
  `HttpCloudApiClient` 调用；生产由 Nginx 以 `https://api.sqlteacher.tech` 反代。当前没有
  任何题库分发接口；IPC 事件流已定义 `import.progress` 事件类型可复用。

## 4. 工作项拆解

### W1 导入验证与安全闸（优先级最高）

- **W1.1 导入自测（dry-run）**：`parsePackage` 与 `importPackage` 对包内每个数据集在临时
  内存库执行 setup SQL（失败即整包拒绝，报出语句级错误）；对每道题执行参考 SQL，并以该题
  自身的判分规则跑一次完整评测，参考 SQL 必须能通过自己的规则。解析预览响应中逐题返回自测
  结论，教师确认界面可见"哪些题通过自测"后再导入。
- **W1.2 setup SQL 白名单**：导入与会话/评测库初始化两处共同生效——setup SQL 拆分后仅允许
  `CREATE TABLE` / `CREATE INDEX` / `INSERT` 语句（复用 `SqlRiskAnalysisService` 或等价
  确定性分析），拒绝 `ATTACH`、`PRAGMA`、`DELETE`、`UPDATE`、`DROP`、`ALTER` 及其他语句
  类型。在初始化处重复把关以覆盖"白名单上线前已导入的旧包"。
- **W1.3 错误归因**：评测阶段区分期望结果生成失败与学生失败，新增内部错误码（如
  `REFERENCE_SQL_FAILED`）。学生端提示"题目数据异常，请联系教师"，教师端工作台可定位到
  具体题目；不向学生暴露参考 SQL。

### W2 判分契约对齐

- **W2.1 契约决策**：题面是唯一契约。期望列名必须在题面显式声明；`compareColumns` 判定
  保持严格（数量、名称、顺序）。预置题与导入题面均按此要求整理。
- **W2.2 反馈透明**：`columns` 分项失败时，反馈展示期望列名与实际列名（只给列名，不给参考
  SQL 与期望数据行）。
- **W2.3 结构承诺兑现**：题面承诺的查询结构（"使用子查询""NOT EXISTS"等）要么配置
  `requiredSqlKeywords`，要么修改措辞不再承诺。预置题 subquery-02/03 按此处理；导入自测
  （W1.1）以同一规则校验参考 SQL，防止"题面要结构、参考答案不含结构"的包入库。

### W3 题库可升级通道与预置内容修正

- **W3.1 内置题库改为版本化自导入**：内置题库表达为随应用携带的文字 DSL 包（资源文件，
  复用 `ExerciseTextCodec` 与导入校验），启动时按 `(id, version)` 与库中现状比较后
  upsert：库中版本更低则更新，更高或相等则跳过；数据集内容变化必须启用新 ID
  （`school-core-v2`）。`upgradeSeedHints` 补丁逻辑退役。旧数据集 `school-core-v1` 保留
  不删（历史 attempt 可追溯）；题目 ID 保持稳定以延续进度历史；作答中的旧版本会话由既有
  `EXERCISE_SESSION_STALE` 机制自然关闭。
- **W3.2 预置内容修正（随 v2 数据集与题目版本升级发布）**：
  - join-01、subquery-04 题面声明 `course_name` 列名（W2.1 契约）；
  - `school-core-v2` 数据集：新增成绩低于 60 分的学生使 filter-01 的 WHERE 生效；新增一门
    无人选修的课程使 join-03 的 LEFT JOIN 生效；班级命名改为可按 Unicode 自然排序的
    `A班/B班/C班` 消除"一班→三班→二班"的反直觉顺序；
  - 数据集 DDL 显式声明 `FOREIGN KEY`，支撑 W3.3 的关系展示；
  - 全部受影响参考 SQL 的期望结果随数据变化重新生成，由 W1.1 自测兜底验证。
- **W3.3 表结构摘要内省化**：`ExerciseDatasetSchemaSummary` 改为在内存库上以
  `PRAGMA table_info` / `PRAGMA foreign_key_list` 内省生成，替代正则解析；预览摘要中展示
  主外键对应关系（如 `enrollment.student_id → student.id`），消除"id 与 student_id 是否
  一致"的解读困惑；正则实现退役或保留为内省失败时的降级路径。

### W4 选题目录 UI

- **W4.1 目录契约扩展**：`practice.catalog` 按当前 owner 聚合 `exercise_attempts`
  返回每题作答状态（尝试次数、是否已通过、最后尝试时间）；数据仅保存在本机。
- **W4.2 列表改造**：题目按知识点分组展示；提供难度、知识点、状态（未做/未通过/已通过）
  筛选；列表项带状态徽标（通过 ✓、尝试次数）；默认排序让未完成的入门题优先。
- **W4.3 浏览与搜索**：保留子串搜索并与筛选条件组合；分组标题显示计数；移除每页 10 条的
  翻页控件，改为分组全量渲染（当前题库量级）+ 组内"显示更多"截断，为题库增长预留简单
  截断策略，不引入虚拟列表依赖。
- **W4.4 状态保持**：筛选与分组状态写入 URL 查询参数（沿用既有 `exercise` 参数先例），
  刷新与返回不丢失。
- **W4.5 前端测试**：vitest 覆盖筛选组合、分组渲染、状态徽标与 URL 状态保持。

### W5 网络题库：服务器分发与流式更新

设计原则：网络题库内容与教师导入内容同等对待（不可信输入，过同一套确定性校验）；分发与
应用分离（服务器只负责存取版本化内容，客户端决定差集并原子应用）；任何网络失败不阻塞
本地练习主流程。

- **W5.1 版本化分发模型（清单 + 分块）**：题库组织为清单（manifest）+ 分块（block）。
  清单包含单调递增的题库版本号 `bankVersion`、全部数据集与题目的 `(id, version, SHA-256)`
  及引用关系；分块是单个数据集或题目的文字 DSL 片段。客户端拉取清单后在**本地**计算差集，
  仅下载缺失或哈希不一致的分块（增量更新），分块可并行下载、单块失败仅重试该块。
- **W5.2 服务端接口**：`SqlTeacherCloudServer` 新增只读接口 `GET /api/v1/bank/manifest` 与
  `GET /api/v1/bank/block/{type}/{id}`（按 id 返回当前版本块，带内容哈希与缓存头）；内容
  存于服务端 SQLite 新 store（沿用 Vxx store 惯例）。管理端 `POST /api/v1/admin/bank`
  （复用既有 admin 鉴权）接收完整文字 DSL 包：服务端先执行与客户端相同的确定性校验与
  W1.1 自测，全部通过才落库为新 `bankVersion`（版本不合法或回退发布被拒绝）。生产经
  Nginx HTTPS 暴露，Java 服务保持 loopback 绑定不变。
- **W5.3 客户端同步服务与 IPC**：基础设施层新增题库同步服务，HTTP 访问复用
  `HttpCloudApiClient` 惯例（显式超时、强制 HTTP/1.1）；IPC 新增 `practice.bank.check` 与
  `practice.bank.update`（同步更新 `contracts/ipc/v1/manifest.json`、`LocalAppContract`、
  `shared/ipc.ts`），更新过程经既有 `import.progress` 事件流式上报阶段与进度（检查 →
  下载 n 项 → 校验 → 应用），支持取消。客户端在 app.db 记录已应用的 `bankVersion` 与清单
  哈希。
- **W5.4 统一应用通道**：下载的分块重组为文字 DSL 包后，走与教师导入完全相同的确定性
  校验（结构解码、setup SQL 自测、语句白名单），再复用 W3.1 的版本化 upsert 通道入库。
  应用在单一事务内完成：任一校验/写入失败即整体回滚，本地题库保持上一个可用状态；重试
  天然幂等（按 id + version + 哈希对齐）。客户端拒绝 `bankVersion` 不高于已应用版本的
  清单（防降级）；内置基线包与网络更新共用同一 upsert 逻辑，版本号统一单调推进。
- **W5.5 隐私与失败安全**：更新检查仅 `GET` 清单并在本地差集，不携带任何学生数据、作答
  记录或本机信息；服务器不可达、校验失败、下载中断均给出可重试的明确状态，绝不阻塞
  本地练习。更新入口：设置页与练习目录的"题库更新"，默认手动检查（不做启动自动联网）。
- **W5.6 教师发布入口（次要）**：教学工作台新增"发布题库包到服务器"（教师角色，配置服务器
  admin 凭据），将 `exportPackage` 导出的文字 DSL 包提交到 W5.2 管理端；发布前客户端本地
  先跑一次相同自测。与既有 `cloud.course.exercise.publish` 课程包流程互不影响。

## 5. 验收

按验证阶梯从窄到宽：

- 聚焦单测（`mvn -q test -Dtest=...`）：
  - 导入自测：合法包通过；参考 SQL 语法错误、参考 SQL 结果不满足自身规则、setup SQL 执行
    失败、同 ID 数据集内容不一致的包均被整包拒绝且错误指明题目/语句；
  - 白名单：含 `ATTACH`/`PRAGMA`/`DELETE`/多语句混入的 setup SQL 在导入与库初始化两处均被
    拒绝；
  - 错误归因：参考 SQL 失败返回新错误码且反馈文案不指向学生；
  - 升级通道：模拟存量 v1 库（20 题旧数据）启动后升级到 v2：题面与数据集更新、旧
    `school-core-v1` 保留、历史 attempt 不变、进行中会话按既有机制关闭；
  - 目录契约：owner 维度作答状态聚合正确；
  - 网络题库（W5）：清单差集计算正确（仅下载缺失/哈希不一致分块）；分块哈希校验失败拒绝
    应用；应用事务原子且幂等（中断重试后题库一致）；`bankVersion` 低于或等于已应用版本时
    拒绝（防降级）；服务端 admin 发布坏包（自测不通过、版本回退）被拒；更新请求不含任何
    学生数据（审查请求内容）。
- 广度验证：`mvn -q test -Pfast`，因触及数据库初始化、seed 与服务端接口，合并前跑全量
  `mvn test`；前端 `npm --prefix ui-web test` 与 `npm --prefix ui-web run build`。
- 手工验收：教师导入含坏参考 SQL 的包 → 预览即报错且不入库；存量库升级后目录展示新题面
  与 v2 数据；学生目录按"未通过"筛选可见状态徽标；本地起服务端发布新一版题库 → 客户端
  检查更新 → 流式进度展示 → 应用后目录出现新题，中途断网重试路径可恢复，离线时练习
  完全可用。
- 文档：教师手册补充导入自测与白名单规则、题面列名契约要求、网络题库更新与发布操作；
  运维记录补充服务端题库接口与发版流程（部署脚本需携带题库内容）；`docs/releases/v3.1.0.md`
  增补本范围条目；实现完成后按惯例补实施/验收记录。

## 6. 风险与回退

- **升级通道风险**：upsert 逻辑必须保证"库中版本更新则跳过"，防止回退降级；数据集采用
  新 ID 而非原地改内容，避免破坏"同 ID 同内容"的既有约束与历史会话。
- **预置数据变更的连带影响**：数据集 v2 改动会影响全部依赖它的参考 SQL 期望结果，统一由
  W1.1 自测与重跑的聚焦测试兜底；如个别题需保留旧数据集，允许题目继续引用 `school-core-v1`。
- **白名单兼容性**：存量导入包若含白名单外语句，升级后将无法通过初始化把关；发布说明中
  明示该兼容性变化，教师可按手册整改后重新导入。
- **网络内容风险**：服务器下发内容视为不可信输入，必须完整通过结构解码、自测与白名单后才
  能应用；任何校验失败整体回滚。防降级与哈希清单要求服务端与客户端版本语义一致，IPC 契约
  变更随 `contracts/ipc/v1/manifest.json` 版本化。
- **运维与发版纪律**：题库内容成为服务端部署物的一部分，需纳入既有分阶段部署与备份/回滚
  流程（见云运维技能）；服务端仅经 Nginx HTTPS 暴露，Java 保持 loopback 绑定。
- 回退方式：内置包随应用发布，回退版本即回退内容；不提供库内降级；网络题库回退通过发布
  更高 `bankVersion` 的修正版本完成，客户端不回滚已应用版本。
