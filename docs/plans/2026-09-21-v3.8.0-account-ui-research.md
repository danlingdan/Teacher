## 核心结论（先说重点）

1. **账号体系不是从零开始**。云端账号体系（注册/登录/双令牌会话/改密/会话管理/导出删除/班级角色模型/
   限流/审计）自 v1.11 起持续建设，已相当完整。真正的缺口集中在**凭证生命周期闭环**：
   密码找回在公网环境实际不可用（无真实邮件通道 + 邮箱验证不可达 + 重置完成无客户端入口）、
   无资料管理、教师角色无自主授予路径。v3.8.0 应定位为"账号闭环补全 + 账号体验整合"，而非重建账号系统。
2. **UI 的工程底子好，短板集中在一致性与观感档次**。语义 token、暗色/高对比/紧凑密度、ARIA + axe 测试、
   三层错误兜底、命令面板都已具备；但 4002 行单文件 CSS 半途 token 化（183 处硬编码 hex）、5 处原生
   `window.confirm`、Unicode 字符当图标、断点稀疏、四个千行页面，这些是"优化 UI 显示"最值得动的根因与抓手。
3. **行业启示与本项目方向高度吻合**：教育软件账号体系的主流答案是"轻注册 + 教师建班邀请码入班 +
   角色由授予产生 + 进度绑定账号 + 本地模式保留"——本项目已天然站在这条光谱的正确位置，
   缺的是进度/数据的账号归属完整性和凭证自助管理。UI 侧行业趋势（仪表盘三问、三区练习布局、
   教师三层下钻、克制的游戏化、bento/柔和阴影/深色默认）与现有设计方向一致，属精修而非转向。

## 1. 账号体系调研

### 1.1 行业共性模式（外部调研结论）

对 10 个中国产品（超星学习通、雨课堂、中国大学MOOC、腾讯课堂、ClassIn、小猿AI、作业帮、洋葱学园、
云班课、希沃白板，补充国家中小学智慧教育平台）与 11 个国际产品（Khan Academy、Duolingo、Coursera、edX、
Canvas LMS、Moodle、Google Classroom、Codecademy、DataCamp、LeetCode/力扣、SQLZoo/SQLBolt，补充 Code.org）
的调研归纳出八条共性模式：

| # | 模式 | 采用者与要点 |
| --- | --- | --- |
| 1 | **轻注册（社交/邮箱登录为主）** | 雨课堂"微信即身份"；Duolingo/Coursera/DataCamp/Codecademy 用 Google/Apple 等；希沃微信扫码。教育产品普遍把身份外包给成熟身份源，注册摩擦趋零 |
| 2 | **邀请码/二维码入班（全球第一共识）** | 学习通、雨课堂、云班课、ClassIn、Google Classroom、Canvas、Khan、Duolingo Schools、Code.org 全部是"教师建班→发码→学生自助加入"；中国偏二维码+暗号，国际偏 6–8 位短码 |
| 3 | **机构名单导入与码并存** | ClassIn 后台导入、Canvas SIS/邮箱添加、MOOC 学校云学号认证、Google Workspace 管理员授予；正规学校场景用名单，社交场景用码 |
| 4 | **角色由组织授予，个人不可自改** | Google Classroom（仅管理员改角色）、Canvas（学校分配）、MOOC 学校云（教师认证审核）、ClassIn（机构后台）。自学型产品（Duolingo/力扣）则几乎无角色概念——**有班级才有角色** |
| 5 | **进度=账号，强绑定** | 中国大学MOOC 换邮箱=丢学习记录；Codecademy 重置进度需联系客服；力扣中美国际账号互不互通。进度云端绑定账号是持续学习的基础，但**必须提供导出**以避免锁死 |
| 6 | **本地/免账号模式保留一极** | SQLZoo/SQLBolt 完全无账号（进度存 localStorage，清数据即失）；国家智慧平台未注册可浏览部分资源；Khan 游客可学但进度不存。工具型产品可以零账号，平台型至少"未登录可看" |
| 7 | **儿童友好凭证与监护人流程** | Khan/Duolingo 对 13 岁以下用"用户名+家长邮箱"；Code.org 图片登录；国家智慧平台家长代注册+学籍号。合规（COPPA/个保法 31 条）驱动的设计定式 |
| 8 | **离线=内容可下，进度必上云** | Khan/Coursera 支持视频下载但进度云端同步；Duolingo 离线能力反而缩水。纯 Web 小工具直接放弃离线同步 |

**适合本项目（单开发者、桌面优先、面向高校）采用的做法**：零摩擦本地优先（已有）、一键"本地→云"升级
路径、注册只做一种凭证（邮箱+密码）、纯邀请码入班（已有 6 位班级码）、进度绑定账号但可导出（导出已有）、
邮箱重置密码。**不建议复刻**：学校 SSO/LDAP/LTI（需客户 IT 部门）、短信验证码与手机号实名（持续成本+
合规负担）、防沉迷/青少年模式全套（平台级义务，无社交/消费/UGC 即可规避主要触点）、双账号体系
（连大厂都因此产生海量客服工单）、第三方 OAuth（需逐家注册开发者资质与审核，个人维护成本高）。

**未成年人合规最小集**：本软件面向高校数据库课程（用户基本为成年人），不提供社交/UGC/内购，
按《未成年人网络保护条例》与《个人信息保护法》31 条的触点很少；若未来面向 K12 需补年龄声明与
监护人同意流程及专门的儿童个人信息处理规则。本版不需要做。

### 1.2 本软件账号体系现状（代码调研结论）

**已有的（可直接复用，无需重建）：**

- **服务端认证骨架完整**（`src/main/java/com/sqlteacher/server/`）：`SqlTeacherCloudServer.java` 注册了
  `/api/v1/auth/register|login|refresh|logout|change-password|request-password-reset|reset-password`、
  `/api/v1/account/*`（export/delete/bind-email/verify-email）、`/api/v1/sessions/*` 全套路由。
  不透明 Bearer Token（32 随机字节、库中仅存 SHA-256 哈希），access 8 小时/refresh 30 天、refresh
  旋转+重放失效；会话表带 `device_label`/`last_seen_at`（`CloudSchemaMigrator` 迁移 1/8）。
- **密码存储规范**：`server/Hashes.java` PBKDF2-HMAC-SHA256、310,000 迭代、16 字节随机盐、常时比较、
  用后清零；登录对不存在/禁用账号做同成本假哈希防时间侧信道枚举。
- **防护与审计成体系**：`AuthRateLimiter`（5 次/15 分钟锁定）+ 每端点配额（register 10/邮箱/时、
  reset 3/邮箱/时、sync-upload 1/分等）；`admin_audit`/`export_audit` 落审计；
  `CloudServerHardeningIntegrationTest` 越权矩阵测试。
- **角色与班级模型完备**：`users`/`user_roles`（ADMIN/TEACHER/STUDENT，注册默认 STUDENT）、
  `classrooms(join_code)` 6 位班级码、`classroom_members`（TEACHER/STUDENT）、`requireTeacher`+
  成员校验；桌面端 `DesktopAccessProfile` 能力集 → 桥 `requireTeacher()` → UI `RoleGuard` 三层强制。
- **学习数据账号归属管道已通**（v3.7.0）：`learning_events.owner` 与 `sql_history.owner_id` 按账号隔离，
  `POST /api/v1/sync/events` 按 `(user_id, event_id)` 幂等上传/回拉，白名单脱敏+服务端二次收敛，
  限流/容量上限/180 天保留齐备；自动同步默认开（2026-09-20 用户决策）。
- **客户端账号 UI 已有三块**：`ui-web/src/features/auth/AuthPage.tsx`（登录/注册/找回三 tab）、
  `CloudPage.tsx` 账号卡（改密/会话管理/导出/删除）、`useAccountSecurity.ts` hook；
  会话经 `PersistentCloudSessionService` + Windows DPAPI 加密持久化、到期前自动 refresh。

**缺口（本次调研确认、当前仍存在）：**

| # | 缺口 | 证据与影响 |
| --- | --- | --- |
| 1 | **密码重置闭环断裂（P0）**：UI 只能发重置请求，无"输入重置凭证完成重置"的界面；`HttpCloudApiClient.resetPassword` 已实现但桥与 UI 均未接 | `AuthPage.tsx`；`HttpCloudApiClient.java:162-163`；`AccountApiSection.java` 白名单无 `account.password.reset` |
| 2 | **重置链接落地页不存在**：邮件正文链接指向 `https://api.sqlteacher.tech/reset-password?token=...`，云服务器没有该页面 | `V111AccountStore.java:173` |
| 3 | **邮箱验证不可达 → 重置实际失效**：`requestPasswordReset` 只对 `email_verified=1` 发信；bind-email/verify-email 服务端接口存在但 IPC 白名单与 UI 均无入口，自注册用户 `email_verified` 恒为 0，重置邮件静默不发 | `V111AccountStore.java:162`；`AccountApiSection.java` |
| 4 | **无真实邮件通道**：`FileMailSender` 只写服务器 `<data>/mails` 目录，注释"由运维中继到真实 SMTP"，仓库内无中继实现 | `FileMailSender.java` |
| 5 | **教师角色无自主授予路径**：注册即 STUDENT，TEACHER 只能由已有教师 `addMember(role=TEACHER)` 时附带晋升或 bootstrap admin；管理员接口只有 disable/restore/revoke-sessions，无角色管理端点 | `CloudClassroomStore.java:127`；`SqlTeacherCloudServer` admin 路由 |
| 6 | **无资料管理**：注册后不能改 displayName、不能绑定/换绑邮箱（流程未 UI 化）；会话 `device_label` 硬编码"桌面设备" | `CloudAuthenticationStore.java:256` |
| 7 | **本机数据归属不彻底**：仅 `learning_events`/`sql_history` 有账号归属；guest 期间的记录永不归属、永不上传，无"登录后并入账号"路径；mastery 等本地表不分账号（v3.7.0 计划已声明不上报，可接受） | `InMemoryLearningEventOwnerContext.java`；v3.7.0 计划缺口表 |
| 8 | **限流器单进程内存态**：重启清零，依赖 Nginx 层与审计兜底；单实例部署下可接受，属可选补强 | `AuthRateLimiter` 类注释 |

## 2. UI 调研

### 2.1 行业 UI/UX 模式（外部调研结论）

1. **学习仪表盘三问**：首屏回答"我学到哪了、接下来做什么、坚持了多久"。Khan Academy 2026-05 改版把
   "下一步该聚焦什么"作为 Learner Dashboard 第一信息；Codecademy 2024-03 改版首屏核心是"从上次中断处
   继续"+ 每周目标；Duolingo 用 streak/XP 承载。学习分析研究（LAD）一致表明"可行动+动机化"的反馈
   比纯描述/预测更有效。
2. **游戏化有边界**：Hanus & Fox (2015) 经典实验表明积分+徽章+排行榜随时间降低大学生内在动机；
   排行榜对领先者正激励、对落后者负激励，XP 榜诱发刷分。对成人学习者的共识：进度感/掌握度/自主性
   有效；若做坚持度，**"周连续"比"日 streak"更契合大学节奏**且必须配"冻结/补签"安全网。
3. **教师端三层下钻**：Canvas New Analytics（周活动图+缺交清单+CSV）与 Moodle 学习分析（风险预测+
   一键发消息）的共同结构是 **班级概览 KPI → 学生×知识点热力图 → 预警列表+学生画像卡 → 可行动按钮**；
   预测类数据需配描述性解释，避免黑箱数字。
4. **SQL/编程练习页三区范式**：左说明/右编辑器/底部结果区（DataCamp 分屏、SQLBolt 叙事+就地练习）；
   查询结果必须渲染真实表格网格（表头冻结、行列高亮），LeetCode 以 JSON 文本展示 SQL 结果被社区
   公认为反面教材；错误信息按"哪里错+为什么+怎么改"三段式就近内联展示（NN/g）。
5. **2025–2026 视觉趋势**：bento grid 瓷砖式仪表盘、大圆角、柔和阴影营造"可触摸感"、深色模式近普及
   （约 82% 用户偏好）、玻璃拟态仅作层次点缀（正文/数据区禁用）、中性可变字体黑体、空状态被视为
   "教学机会"（给 CTA/示例/下一步）、渐进式披露引导。
6. **导航**：顶层入口多且 IA 深时侧栏胜出（教育产品主流）；命令面板（Cmd+K）是"频繁跳转到某课程/
   某学生"产品的天然增强；面包屑只作深层结构的辅助。
7. **无障碍基线**：正文对比度 ≥4.5:1、正文 ≥16px、全键盘可达、焦点可见；深色模式下低对比灰字与
   玻璃模糊是重灾区。

### 2.2 本软件 UI 现状（代码调研结论）

**技术栈**：Tauri 2 + React 19.1 + TypeScript 5.8 + Vite 7；react-router 7（HashRouter，路由集中在
`ui-web/src/App.tsx:82-153`）；服务态用 @tanstack/react-query 5；**无 UI 组件库、无图标库、无 Tailwind**，
样式为单个全局 `ui-web/src/App.css`（4002 行）+ 极小 `shared/ui/ui.css`；组件全部自研
（`ui-web/src/shared/ui/index.tsx`：Button/Toaster/FormField/Stepper/Feedback/EmptyState/Dialog/
DataTable/TreeView）；编辑器 Monaco 0.56；知识渲染 react-markdown+katex+mermaid。

**信息架构**：左侧固定深色侧边栏（248px）+ 顶部 topbar；7 个工作区——今天（学习概览 hero+指标+建议
队列）、课程与知识（双栏阅读+导入+助教子窗口）、练习与实验（SQL 练习/课程活动/自由编程/错题本四 tab
+Monaco）、数据与 SQL（表树+SQL 工作台+NL2SQL+ER 图）、教学空间（教师/管理员，题库+本机学情+学生
画像）、班级与云端（1567 行：账号/班级/任务/同步/账号安全）、设置（1331 行）；另有登录页与知识助教
子窗口。Ctrl+K 命令面板、Ctrl+1-7、Ctrl+, 快捷键体系完整。127 个 IPC 方法经单一 Rust 命令白名单转发
Java sidecar，四处契约同步（LocalAppContract/桥/manifest.json/Rust ALLOWED_METHODS）。

**强项**（行业基线对照下大多已达标）：

- 语义 token ~40 个 + `.theme-dark` 完整覆盖；暗色/高对比/紧凑密度/三档字体/减少动效全联动，
  Monaco 主题跟随（`shared/monacoTheme.ts`）。

## 3. 综合结论：v3.8.0 的定位

1. **账号体系 = "补全闭环"而非"重建"**：四项 P0/P1 围绕一个目标——让公网用户能真实完成
   "注册 → 验证邮箱 → 找回密码 → 管理资料与设备"的完整生命周期。技术底座（PBKDF2/token/限流/审计/
   导出删除）全部复用，云端无新表（`email_verifications`/`reset_tokens` 已建），主要工作是
   SMTP 通道、验证码化交互、IPC/UI 接线与一个教师授予决策。
2. **UI = "一致性治理为主、观感升级为辅"**：先做根因治理（token 化收尾+CSS 拆分、消灭双轨确认、
   统一交互原语），再做档次提升（真图标、中等宽度走查、今天页/教师端呈现精修）。信息架构与
   设计方向经行业对照确认正确，不需要推倒重来。
3. **不碰的红线**：排行榜/监考/行为画像不做；第三方 OAuth、短信验证码、SSO/LTI、青少年模式不做
   （成本与合规负担超出单开发者收益，行业调研支持此取舍）；离线优先原则不动；角色班级模型
   仅最小化扩展（教师授予通道，需用户确认解除 v3.3 边界的范围）。
