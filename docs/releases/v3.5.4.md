# SQLTeacher v3.5.4

> 发布日期：2026-09-18（已公开，GitHub Release Latest 见 releases/README）
>
> v3.5.4 是**缺陷修复与更新体验版本**：修复应用内"下载更新"在首次下载时必然失败的
> 问题——更新包写盘输出流缺少 `CREATE` 打开选项，`.part` 部分文件不存在时
> `Files.newOutputStream` 直接抛 `NoSuchFileException`，因此真实下载从未开始过；
> 界面上只显示一条裸 Windows 路径作为"错误说明"。v3.5.3 修复的 302 主机白名单
> 解决的是更早一步的主机校验拒绝；本次修复打通其后的写盘环节。同时对整条更新
> 链路做了一次系统审查，新增"重装官方安装包"入口与下载取消能力。SQL 安全边界、
> 判分逻辑、桌面数据库 schema 均无变化。
>
> 测试执行：本地全量（CI 凭据跳过，LEG-15 回执绑定 tag 提交）——`mvn test` 792 通过 /
> 0 失败 / 2 跳过，`npm test` 175 通过，`npm audit --omit=dev` 0 漏洞，`npm run build`
> 通过，`cargo test --lib` 5 通过，`ReleaseVerificationApp` 5 项 PASS；产物校验和、
> ZIP 内容安全扫描、无控制台启动与 portable 冒烟均通过。
> 网络层验证：经云端中继全量下载安装包，SHA-256 与签名清单一致。

## 主要变化

### 修复

- **应用内更新首次下载必然失败，弹窗只显示一条 `.part` 裸路径**（用户报告，截图与
  sidecar 日志佐证）：`SecureUpdateService.downloadOnce` 打开部分文件输出流时只传
  `WRITE + TRUNCATE_EXISTING`（或 `WRITE + APPEND`）——`Files.newOutputStream` 在
  显式给出选项时不会附带 `CREATE`，而首次下载时 `.part` 文件尚不存在，于是每次
  都抛 `NoSuchFileException`，文件从未落地（`updates/` 目录始终为空），部分下载
  恢复机制也从未有机会生效。修复：写盘泵提取为包私有 `pumpToPart` 并在两种模式
  下都加上 `CREATE`；新增回归测试覆盖"全新目录首次下载必须建文件"、206 续传追加、
  200 重建截断、超清单大小与短读两类完整性失败。
- **下载失败的界面文案透传裸异常消息**：`IOException` 的 `getMessage()` 在
  Windows 上往往只是一条文件路径，被 `UPDATE_DOWNLOAD_FAILED` 原样带进更新弹窗，
  用户看到的"错误说明"就是一条路径。修复：`IOException` 统一转为可操作的中文
  原因（"更新下载中断，请检查网络后重试"），原始异常保留在异常链中供日志排查。
- **下载中无法取消、弹窗被模态锁死**（整链审查发现）：278MB 安装包在弱网下可长时
  下载，此前进度弹窗期间无法关闭也无法中止。修复：前端下载中提供「取消下载」，
  经既有 `system.cancel` 通道中止；Java 侧在每个进度帧检查取消标记，下一个 64KB
  块前生效，已下载部分按原设计保留供断点续传，桥接层把主动取消还原为标准
  `CANCELLED` 响应而不是伪装成下载失败。
- **同一进程并发下载无守卫**（整链审查发现）：两路下载会交错写坏同一个 `.part`
  文件。修复：`SecureUpdateService.download` 以原子门限制进程内单下载并发，第二路
  立即得到 `UPDATE_DOWNLOAD_IN_PROGRESS` 明确失败；跨进程由桌面单实例约束兜底。
- **「启动安装程序」报"无法启动安装器"**（用户实测发现，日志确诊
  `CreateProcess error=740, The requested operation requires elevation`）：下载与
  完整性校验均已通过，但 Tauri NSIS 安装器要求管理员提权，而 `ProcessBuilder` 走
  `CreateProcess` 无法弹出 UAC（资源管理器双击走 ShellExecute 所以能装）。修复：
  改经 explorer 壳启动安装器，复用系统 ShellExecute 的提权提示；同时补"校验不
  通过的文件必须拒绝启动"（`UPDATE_INSTALL_NOT_READY`）的回归测试。

### 新增

- **更新下载中继：GitHub 直链失败自动切换第一方回退源**（v3.5.2 积压项落地）：国内部分
  网络 GitHub 直连被重置，而 v1.11.3 规划的镜像站 DNS 至今未部署（仍为 NXDOMAIN）。本次
  不新增域名/证书，让既有 `api.sqlteacher.tech` 兼任下载中继（服务端 nginx `/gh/` +
  `/gh-asset/` 反代，部署与验证记录见
  [2026-09-18 更新下载中继](../operations/2026-09-18-update-download-relay.md)）：
  - 客户端下载源顺序 = GitHub 直链 → 云端中继 `/gh/<github 原路径>`（始终启用，主机与
    签名清单同源受信任）→ 镜像站（仍按设置开关，保留 mirror/download 主机逻辑）；
  - 中继完整承载 302 与 Range，断点续传在中继上同样生效；
  - 请求头部超时由 20 分钟收紧为 2 分钟：连接后迟迟不返回头部的源在分钟级放弃并切换；
  - 新增 30 秒零进度停滞检测：停滞源的已下载字节保留，切换下一源后续传；
  - 验证：本机（GitHub 直连曾失败的国内网络）经中继全量下载 278,649,497 字节，
    SHA-256 与云端签名清单完全一致，实测吞吐 ≈1.68 MB/s（278MB 约 3 分钟）。
- **设置页「重装官方安装包」入口**（用户需求：方便测试 + 给用户重装选项）：在
  "更新、通知与帮助"面板新增始终可见的重装面板——跳过"是否有新版本"的门控，直接
  获取最新签名清单并下载官方安装包、启动安装。用途：修复安装、同版本重装，以及
  开发期对已发布清单做端到端下载验证。配套新增 `settings.update.forceDownload`
  IPC 方法（四处契约清单同步：`contracts/ipc/v1/manifest.json`、Java
  `LocalAppContract`、Rust 方法白名单、TS 方法联合），服务层新增
  `UpdateService.latest()`（仅签名与格式校验，不做版本/灰度门控）。

### 审查记录（不改行为）

- 启动弹窗的自动检查经 `settings.update.check` 走 `check(manual=true)`，绕过了 24
  小时节流与按流量计费暂停策略；影响限于每次启动一次清单请求（≤128KB），且
  "手动检查仍可用"本就是策略语义，暂保持现状。
- Rust 桥对 `settings.update.forceDownload` 与既有 `settings.update.download`
  同样给予 30 分钟超时预算（278MB 弱网下载的最坏情况仍可能触及，届时可重试并续传）。
