# SQLTeacher v2.3.0

> 启动日期：2026-08-11
>
> 发布日期：2026-08-11
>
> 发布基线：v2.2.0

## 版本目标

v2.3.0 以逐界面检查和修复为主。每项改动均以真实界面问题为入口，完成定位、完整修复和风险相称的验证。

## 修复说明

- 问题按确认顺序编号为 `UI-001`、`UI-002`……，编号不复用；
- 每项记录界面与现象、原因、修复内容、涉及文件和验证结果；
- 同一问题若经过多轮调整，在原编号下追加结果，不拆成虚假的独立完成项；
- 未实际验证的项目不标记为完成，受限项写明剩余风险；
- 本文档汇总 v2.3.0 正式版本中已经落地并验证的用户可见变化。

## 修复记录

### UI-001 首页版本、快速入口布局与学习诊断反馈

- 界面与现象：首页标题仍显示历史文案“SQLTeacher 2.0 · Alpha.6”；“快速开始”的两行卡片相互覆盖；“下一步学习”长期停留在读取文案，刷新过程缺少可见反馈，管理员账号还会进入不适用的个人学习诊断流程；
- 原因：版本文字直接写在 `home.fxml`；快速卡片的 `TilePane` 行高与卡片 CSS 最小高度相互冲突；诊断控制器只更新最终状态，未表达局部加载、空数据和失败状态，也未按当前桌面身份区分个人学习诊断的适用范围；
- 修复：标题版本改为读取 JAR 构建清单中的 `Implementation-Version`；快速入口改为有明确行列位置的两列 `GridPane`，并统一卡片高度；刷新期间按钮显示“正在刷新”并禁止重复点击，成功结果带刷新时间，空队列和失败均有占位反馈；管理员直接显示“个人诊断不适用、可切换学生身份”的说明，不再发起个人学习队列刷新；点击可用的下一步学习项时显示正在打开的即时反馈；
- 涉及文件：`home.fxml`、`HomeController.java`、`MainWindowController.java`、`pages.css`、中英文资源文件及首页相关回归测试；
- 验证：`mvn -q test "-Dtest=HomeControllerTest,DesktopFxmlResourceTest,DesktopVisualResourceTest,AppI18nTest"` 通过；`mvn -q test -Pfast` 通过，共 449 项测试、0 项失败。

### UI-002 “我的练习”两阶段作答流程

- 界面与现象：导航标题“我的练习”下再次出现“闯关练习”，操作顺序依赖长段文字说明；选题列表、题目详情、SQL 编辑器、空结果表和反馈区同时出现，学生尚未确认题目就面对完整作答界面；班级任务入口还会自动开始练习；
- 原因：页面只有一个始终展开的 `SplitPane`，选题与作答没有独立界面状态；控制器在题目选中后只切换按钮可用性，班级任务定位题目后直接调用开始操作；
- 修复：页面改为“1 选择题目 → 2 作答与提交”的可视化步骤条；第一阶段只显示题目列表和题目预览，SQL 编辑器、运行结果和提交操作位于默认不参与布局的第二阶段；点击“确认题目并开始作答”并成功创建隔离会话后才切入编辑器；作答页提供“返回选题”，安全关闭当前会话后恢复预览；首页推荐和班级任务只预选并展示题目，不再自动开始；移除重复的“闯关练习”标题和操作顺序说明；
- 涉及文件：`student-exercise.fxml`、`StudentExerciseController.java`、`pages.css`、中英文资源文件及桌面 FXML/视觉回归测试；
- 验证：`mvn -q test "-Dtest=DesktopFxmlResourceTest,DesktopVisualResourceTest,AppI18nTest"` 通过；`mvn -q test -Pfast` 通过，共 449 项测试、0 项失败。

### UI-003 线性操作统一为分步流程

- 界面与现象：多个页面存在明确的“选择或配置 → 执行 → 查看结果”顺序，但所有区域同时展开，用户需要依赖说明文字判断下一步；未开始操作时也会看到空编辑区、空结果区或大段表单；
- 原因：各页面分别使用标题、按钮和占位文案表达流程，没有共享的步骤状态组件，也没有统一约束后续阶段何时参与布局；
- 修复：新增可复用的 `WorkflowSteps` 组件，以编号、连接线和完成/当前状态表达进度；活动工作区改为先预览、确认后运行、最后查看评测；AI 助手在生成前隐藏结果区，并展示生成与审阅阶段；连接设置和题库管理先选择对象，再展开配置表单，成功测试/保存后进入完成阶段；数据库学习分别为学习目标、模型草稿和练习数据三个子流程建立独立步骤状态，其中模型与数据的后续审阅区默认隐藏；SQL 练习以步骤状态反馈编写、安全检查和结果；“我的练习”改用同一组件维持选题与作答流程；
- 范围边界：课程地图、知识浏览、看板和普通设置等非线性浏览页面不强制套用步骤条，避免把可自由探索的界面误改为向导；
- 涉及文件：`WorkflowSteps.java`、活动工作区、AI 助手、连接设置、题库管理、数据库学习、SQL 练习和“我的练习”的 FXML/控制器，中英文资源文件、页面样式及桌面资源回归测试；
- 验证：`mvn -q test "-Dtest=WorkflowStepsTest,DesktopFxmlResourceTest,DesktopVisualResourceTest,AppI18nTest,AiAssistantControllerTest"` 通过；`mvn -q test -Pfast` 通过；完整 `mvn test` 通过，共 492 项测试、0 项失败、0 项错误、2 项按环境条件跳过。

### UI-004 当前步骤文字对比度

- 界面与现象：活动工作区等页面的当前步骤使用紫色背景，但步骤文字也是接近背景色的紫色，难以辨认；
- 原因：步骤组件把用于普通强调文字的 `-st-accent-fg` 令牌错误地用作强调色背景上的前景色；
- 修复：为明暗主题分别增加高对比的 `-st-accent-strong` 背景，并增加白色 `-st-text-on-accent` 前景令牌；当前步骤统一改用这组令牌，视觉对比度分别达到 6.30:1 和 6.40:1；
- 涉及文件：`tokens.css`、`pages.css`、`DesktopVisualResourceTest.java`；
- 验证：新增明暗主题当前步骤对比度不得低于 4.5:1 的自动化门禁。

### UI-005 按课程隔离活动目录

- 界面与现象：“数据库学习”的目标活动列表混入 C、C++、Java、Python 等编程课程内容；通用“实验工作区”把所有课程的活动平铺在同一个长列表中，课程增加后难以快速定位；
- 原因：数据库学习目标服务在读取课程地图后直接扁平化全部已发布课程；实验工作区同样丢弃了课程层级，只保留活动列表；
- 修复：数据库学习目标固定从内置“数据管理”课程读取已启用活动，不再通过活动标题或类型猜测归属；实验工作区增加“课程”选择器，只展示当前课程的已启用活动，空课程不进入选择器；从课程地图、推荐等入口打开指定活动时，仍会自动切换到该活动所属课程；
- 扩展约束：新增课程必须保留课程 ID 和课程层级，任何课程专属页面按课程 ID 取内容；通用目录先选课程再选活动，不再跨课程平铺；
- 涉及文件：`DefaultLearningGoalCatalogService.java`、`ActivityWorkspaceController.java`、`activity-workspace.fxml`、中英文资源文件及课程隔离回归测试；
- 验证：覆盖数据库目标排除其他课程、禁用活动过滤、空课程隐藏、不同课程活动不混合，以及工作区必须存在课程选择器。

### UI-006 普适性本地开发环境检测

- 界面与现象：代码 Runner 已能使用本机 Java、Python 或 MSVC 时，“设置 → 开发环境”仍可能显示未安装；界面和安装包 ID还写死 Visual Studio 2022；
- 原因：设置页与 Runner 使用两套检测逻辑；设置页只检查 PATH、Adoptium/Python 的少数目录和 `Program Files (x86)` 下的 Visual Studio，遗漏 `JAVA_HOME`、Oracle/Microsoft/Corretto/Zulu JDK、Python Launcher、用户安装目录以及安装在 `Program Files` 下的 Visual Studio 2026；
- 修复：新增共享 Windows 工具链发现器，设置页、实际 Runner 和开发者终端统一使用；Java 支持当前运行时、`JAVA_HOME`、`JDK_HOME`、PATH、常见 JDK 厂商与 IntelliJ `.jdks`；Python 支持全部 PATH 候选、`py.exe` 解析出的真实解释器、用户/系统目录和 pyenv-win，并跳过不可执行的 WindowsApps 别名；C/C++ 支持 PATH、Visual Studio Installer/`vswhere`、`VSINSTALLDIR`、Visual Studio 2022/2026 并行实例、LLVM、MSYS2、MinGW、Cygwin、Chocolatey 和 Scoop；
- 版本修正：安装目标及界面更新为 Visual Studio 2026 Build Tools，WinGet 包 ID 使用当前的 `Microsoft.VisualStudio.BuildTools`；已安装的兼容工具链不要求由 SQLTeacher 安装，也不限定厂商；
- 涉及文件：`WindowsToolchainDiscovery.java`、组件服务、本地 Runner、开发者终端、环境设置控制器、中英文资源、Runner 配置指南及相关回归测试；
- 验证：覆盖构建 JDK 非 Temurin 发现、不可用 Python 别名跳过、2026 WinGet 包 ID，以及设置页与 Runner 共用发现路径。

### UI-007 编程活动语法高亮与本地补全

- 界面与现象：Java、Python、C、C++ 编程活动虽然使用带行号的代码编辑器，但源码始终为单色，也没有任何补全入口；
- 原因：`CodeArea` 只配置了等宽字体和行号，没有安装语言样式计算或补全交互；
- 修复：新增多语言语法高亮，区分关键字、字符串、注释、数字以及 Java 注解、Python 装饰器和 C/C++ 预处理指令；增加 `Ctrl+Space` 本地补全菜单，候选由各语言基础词、常用标准标识符和当前源码已有标识符组成；切换活动时释放高亮订阅和补全菜单，避免遗留监听；
- 边界：补全不调用 AI、不联网、不执行源码，也不冒充完整语言服务器；运行、隔离评价和安全边界保持不变；
- 涉及文件：`CodeSyntaxHighlighter.java`、`CodeCompletionCatalog.java`、`CodeEditorSupport.java`、`ActivityInteractionPane.java`、页面样式、中英文资源、Runner 配置指南及编辑器回归测试；
- 验证：覆盖四种语言的样式分类、样式跨度不改变源码长度、关键字补全、当前源码标识符补全和光标前缀替换边界。

### UI-008 云端班级登录状态与学生权限界面

- 界面与现象：云端班级页面已经显示当前账号和角色，顶部状态仍提示“请登录云端账号”；学生身份也能看到发布班级任务的表单与按钮，造成学生似乎可以发布任务的错误印象；
- 原因：状态栏使用 FXML 初始文案，控制器加载已有会话时只更新账号标签，没有同步登录状态；“添加成员”区域误用了 `assignmentCreationPane` 标识，导致控制器隐藏的是成员管理子区域，而真正的任务发布表单没有进入教师权限容器；任务学情统计区域也缺少独立的身份可见性绑定；
- 修复：页面初始化时根据实际云端会话显示“已登录云端账号”或登录提示，并使用成功/提示状态样式；修正任务创建容器的 FXML 绑定，学生仅显示已发布任务列表和“开始所选任务”，任务创建、生命周期操作及任务学情统计只对教师和管理员显示；
- 权限边界：服务端任务创建、更新和状态变更继续强制校验班级教师权限；新增回归测试证明学生即使绕过界面直接请求接口，创建任务和把草稿发布为正式任务也会返回 HTTP 403；
- 涉及文件：`cloud-center.fxml`、`CloudCenterController.java`、中英文资源文件、桌面 FXML 回归测试和云端服务权限测试；
- 验证：`mvn -q test "-Dtest=DesktopFxmlResourceTest,AppI18nTest,SqlTeacherCloudServerTest"` 通过，学生任务创建与发布越权请求均被拒绝。

### UI-009 课程资料傻瓜化主流程与高级设置

- 界面与现象：课程知识中心把课程、章节、知识点、目标 ID、私有状态、检索、联网搜索、AI、索引、导入和发布操作平铺在同一屏幕；学生首次进入就要理解内部标识和索引状态，空表还显示英文占位，无法判断应该从哪里开始；
- 原因：原页面直接暴露知识库的存储、检索和教师维护模型，没有按普通阅读、精确检索和教师管理三个使用层次组织，也没有从问题到资料再到阅读的可视化流程；AI 辅导还强制要求手工填写内部目标标识；
- 修复：主界面改为“输入问题 → 选择资料 → 阅读与练习”三步流程；顶部只保留问题输入、“查找资料”和“AI 帮我解释”，左侧资料列表简化为标题、课程、章节，右侧集中展示正文、检索结果、关联练习和 AI 解释；点击本地检索结果会直接定位并打开对应资料；所有空状态改为可理解的中文行动提示；
- 高级设置：课程、章节、知识点、学习目标标识、私有资料筛选、联网搜索和索引维护集中到默认折叠的“高级设置与资料管理”；教师的批量导入、新版本、发布、转私有、停用和删除继续完整保留在该区域，学生身份完全隐藏教师资料管理和私有资料选项；
- AI 易用性：普通用户不再需要填写学习目标 ID；优先使用高级设置中的显式值，否则自动采用当前资料、知识点或通用课程上下文，同时继续执行既有的上下文预览与发送确认；
- 涉及文件：`knowledge-center.fxml`、`KnowledgeCenterController.java`、页面样式、中英文资源、课程资料控制器测试及桌面 FXML 回归测试；
- 验证：`mvn -q test "-Dtest=KnowledgeCenterControllerTest,DesktopFxmlResourceTest,DesktopVisualResourceTest,AppI18nTest"` 通过；覆盖普通提问区位于高级设置外、技术标识与教师管理位于折叠区、批量导入仍保留，以及 AI 上下文自动推导。
