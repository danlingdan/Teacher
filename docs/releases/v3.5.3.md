## 主要变化

### 修复

- **首页干预卡片点"继续"跳到知识页而不是对应题目**（用户报告，截图佐证）：
  `continueAction` 的第一个分支条件是 `type === "REVIEW_KNOWLEDGE" || knowledgePoint`，
  只要动作携带知识点就被路由到 `/knowledge`——而诊断服务生成的 RETRY_EXERCISE 动作
  （如"巩固：选择列"）总是同时带知识点和题目 ID，点"继续"永远进不了练习页。
  修复：路由决策抽为 `shared/actionRoute.ts` 纯函数并按"动作类型优先、
  exerciseId/knowledgePoint 逐级兜底"排序，RETRY_EXERCISE 正确跳到
  `/practice?exercise=…`；COMPLETE_ASSIGNMENT/REVIEW_FEEDBACK 仍进云端页。
  附 5 个路由决策单元测试。
- **做完了题目目录仍显示"未做"**（用户报告，截图佐证）：练习页的题目目录、错题本、
  学习路径都从本地作答历史聚合而来，且 React Query 查询带 30 秒 staleTime；开始作答、
  运行、提交成功后没有任何失效动作，同页停留时这些查询不会重取——目录徽标停留在
  "未做"（后端 `exercise_sessions`/`exercise_attempts` 聚合数据本身是正确的，属纯前端
  状态刷新缺陷）。修复：会话创建与作答成功后精确失效
  `["practice", catalog/wrongbook/paths]` 三组查询（前缀匹配，覆盖全部分页/筛选参数），
  并补提交后目录必须重取的回归测试。

### 移除

  前端查询/组件/类型/孤立 CSS、`practice.recommend` IPC 方法（同步收紧四处契约清单：
  `contracts/ipc/v1/manifest.json`、Java `LocalAppContract`、Rust 桥白名单、TS 方法联合）、
  `ExerciseCatalogService.recommendNextExercise` 及其确定性推荐实现与 `RecommendationView`。
  相关测试同步收敛（目录聚合测试保留错题本与状态断言，删除推荐断言）。目录状态徽标、
  错题本、学习路径不受影响。

### 官方知识库 1.1.0（用户决定）

- **托马斯微积分并入官方知识库**：官方分发调整为**双官方包**，各自作为独立课程在知识页
  展示（课程 → 章节两级，不再散成一章一节）：
  - `official-db-concepts`（数据库系统概念）保持 1.0.1 不变；
  - `thomas-calculus`（托马斯微积分）**v1.1.0**：166 篇知识点、927 张插图，来源为用户

- 配套改造：`package-v3.ps1` 知识库门禁从"恰好一个 zip"放开为"多个 zip、bundleId 唯一、
  逐包校验和"；首启引导本就逐个扫描导入（`KnowledgeBundleBootstrapService`），无需改 Java。
- 数据迁移：本机曾误导入合并版单包（174 篇混在一个课程），已备份 `app.db` 后定点清理

  云端多通道分发留待后续版本。

### 知识页体验修复（用户反馈）

- **callout 全部消失修复（用户报告）**：`normalizeMarkdown` 重构时误将剥掉 `>` 前缀后的
  内容推回输出，导致所有块引用行丢失前缀、callout 结构散架（浏览器实测复现：
  `[!example]` 沦为顶层裸文本）。修正为所有分支统一推送 `prefix + 内容`，并新增
  浏览器级人工验证页（`ui-web/debug-render.html`，vite dev 手动访问，不入构建）。
- **课程/章节/条目三级字号归位**：课程名 16px/800，章节 13px/600 弱化色，知识点条目
  13px/1.5 行高（此前条目继承了正文大字号，且课程名 14px 反而小于章节标题）。
- **课程树默认收起**：双库并存的目录很长，课程与章节默认折叠、点击逐级展开
  （此前两层全部默认展开）。
- **知识库可删除**：新增 `knowledge.bundle.remove` IPC（契约四处同步），
  `KnowledgeBundleService.removeBundle` 按包硬删其导入的全部文章（子表先行，同导入期
  替换语义）、删除包状态行与图片资产目录，用户自建文档（bundle_id 为空）不受影响；
  面板对每个已装包提供"删除 → 确认删除"两步确认。
- **"知识库更新"面板列出全部已装知识库**：`knowledge.overview` 新增 `bundles` 数组
  （bundleId/version/source），面板逐包列显示名、版本与来源（内置/云端/手动导入）；
  云端检查仍针对官方数据库通道，面板文案已注明。
- **Markdown 渲染对齐 Obsidian 官方语法**（help.obsidian.md → Callouts / Advanced
  formatting，本批 166 篇笔记实际含 1452 个 callout，为观感决定性因素）：
  - Callout 按官方 13 类标准类型配色（note/abstract/tip/success/question/warning/
    failure/danger/bug/example/info/todo/quote），亮暗两套色板；别名（summary/tldr、
    hint/important、check/done、help/faq、caution/attention、fail/missing、error、cite）
    归一到标准类型样式，原始类型保留为附加类；
  - 未知类型（如笔记中的 definition 316 处、theorem 138 处）按官方行为回退 note 观感，
    标识类保留；
  - 折叠 callout（`[!type]+` / `[!type]-`）渲染为可折叠 details/summary，+ 默认展开、
    - 默认收起；
  - `==高亮==` 渲染为 mark；`%%注释%%` 按官方行为在阅读视图不渲染；
  - **多行 aligned 公式报错修复（用户报告）**：块引用内 `$$\begin{aligned}…\end{aligned}$$`
    与公式内容同行时，remark-math 的 flow 围栏识别失败（同行内容被当围栏元数据吞掉），
    KaTeX 收到残体报 `Expected 'EOF', got '&'`，整段公式以红字漏出。`normalizeMarkdown`
    新增按行规范化：把与内容同行的 `$$` 围栏归位到独立行（自动保留块引用前缀 `>`，
    单行成对 `$$…$$` 不受影响）。
  - **`\tag{…}` 编号公式报错修复（用户报告）**：行内模式不支持 `\tag`。独占一行的成对
    `$$…$$`（即使紧贴段落）现拆分为三行进入 flow/display 模式，`\tag` 编号正常渲染；
    句中行内公式携带 `\tag` 时按解析器限制剥离编号标记、保留公式本体。
  - **图片尺寸**：新增 remark-breaks 依赖，同时支持 Obsidian `![alt|300]` / `![300]`
    宽度语法（`|尺寸` 后缀此前在打包改写时被丢弃，现保留进 alt 并在渲染端换算为像素宽，
    超宽图片不超过容器）。本批笔记 875 个嵌入图中 655 个带尺寸后缀。
  - 托马斯微积分包因内容修复升为 **v1.1.1**，引导自动升级已装的 1.1.0。
  - 尚未对齐（记录待办）：行内 #标签徽章、`![[文档]]` 嵌入 transclusion（当前显示为
    占位徽章）。

## 兼容性说明

- **桌面数据库 / IPC 契约版本 / 题库 DSL**：无任何变更；本修复为桌面 UI 查询失效逻辑，
  不触及 Java 侧与后端聚合 SQL。
- **SQL 安全**：无边界变化。
- **行为差异**：运行或提交作答后，目录徽标/推荐/错题本/学习路径立即反映最新作答状态
  （此前要等页面重挂载或窗口焦点触发才更新）。注意徽标按尝试次数渲染：只"开始作答"
  而尚未运行/提交时徽标仍为"未做"，首次运行或提交后才变为"未通过"/"已通过"。
- **云端**：无变更。
