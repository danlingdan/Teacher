# SQLTeacher v3.2.0

> 发布日期：未发布（本地候选，版本号已定）
>
> 安全修复与合理性重校：封堵风险分析旁路，云端认证加固，本地数据完整性修复，SQL 安全模式按输入来源分级。

## 主要变化

### 安全修复（P0）

- **封堵 MySQL 可执行注释旁路**：此前 `/*! ... */` 中的内容会被当作纯注释从风险分析中剥离，而服务器实际会执行它——`SELECT * FROM t /*!40001 INTO OUTFILE '...' */` 这类语句被判为只读查询直接放行。现在 MySQL 方言族与未知服务器方言会把可执行注释的内容保留在分析文本中，注释里隐藏的文件写入、危险函数、多语句都会被既有检查拦截；良性的版本化注释（如 `/*!40001 SQL_NO_CACHE */`）照常放行。
- **本地 AI 调用全面钉扎 HTTP/1.1**：主 AI 生成路径（Ollama）与桌面端 embedding 此前仍使用 JDK HttpClient 默认 HTTP/2，在部分 Windows 机器上对明文本机调用会触发已知的 h2c 死锁。现在全部出站 HTTP 客户端经统一工厂构建并钉扎 HTTP/1.1，并新增守护测试防止未来遗漏。
- **云端认证端点限速与锁定**：登录连续失败 5 次锁定 15 分钟（成功登录清零），注册与密码重置邮件按账户和来源 IP 限频；对不存在的账号执行等时哈希计算以拉平响应时间差；Nginx 示例配置增加 `limit_req`。

### SQL 安全模型重校（v3.2.0 行为变化）

本地教学产品的威胁模型是"学生操作自己的本地教学库"，措施强度据此按输入来源分级：

- **SQL 安全模式现在真正生效**：此前设置页的"SQL 开发者模式"开关在桌面上不产生任何效果（预览与执行两层使用了不一致的判定）。现在两层使用同一策略。首次进入 SQL 工作台会请在"教学模式（推荐，写操作逐条确认）"与"开发者模式（INSERT/CREATE 免确认）"之间选择；全新安装默认教学模式，配置文件缺失或损坏时也回落教学模式（不再静默进入开发者模式）。
- **语句分级调整**：`DROP`、`TRUNCATE`、`GRANT`、`REVOKE`、`DROP DATABASE` 从"一律拒绝"改为"明确确认后可执行"——学生终于可以在工作台上练习 `DROP TABLE` 了；`DROP DATABASE` 的确认弹窗附备份强提示。用户/角色管理与写文件类操作（`INTO OUTFILE`、`COPY ... TO FILE/PROGRAM`）保持一律禁止；多语句拦截不受模式影响。
- **文件读取函数分级**：`LOAD_FILE`、`FILE_READ`、`CSVREAD`、`read_csv`、`pg_read_file` 等读取本机文件的函数从"禁止"改为"高风险确认后可执行"；写入类文件操作仍然禁止。
- **CTE 与复合查询放行**：`WITH ... SELECT`（含 RECURSIVE）与 `(SELECT ...) UNION (SELECT ...)` 不再被误判为不支持语句——SQL 课程可以正常提交 CTE 答案了。`WITH ... DELETE` 等变异形式按主语句定级。
- **本地错误信息更透明**：连接失败、执行失败等错误现在附上具体原因与错误分类（SQLState、vendorCode、根因摘要，其中密码片段与文件路径自动脱敏），便于对照自己的连接配置自查；日志与服务端维持既有脱敏。

### 云服务端加固

- `/sync/events` 与题库发布接口的请求体纳入统一大小上限（分别 1 MiB / 2 MiB，超限返回 413），同步事件单条 `payloadJson` 限制 16 KB。
- 匿名问题报表限流改用反向代理传入的真实客户端地址（`X-Forwarded-For` 末位），并新增每 installId 维度限额，防止换标识绕过。
- 绑定邮箱功能修复：此前"验证邮箱"从不更新账户邮箱；现在令牌原子消费并真正更新邮箱，验证邮件按账户与目标邮箱限频，防滥用作邮件轰炸跳板。
- 密码重置令牌的失败尝试计数从死代码变为实际生效（5 次失败后令牌作废）；干预确认令牌比较改用常量时间算法。

### 本地数据完整性

- **备份恢复不再有 WAL 残留风险**：恢复前对目标库执行 WAL checkpoint 并删除 `-wal`/`-shm` 侧车文件，恢复动作全程互斥；恢复成功后自动重置知识索引状态并清空本地向量索引，检索结果不再与恢复后的数据错位。
- **干预状态按自然键匹配**：此前干预候选的 ID 把"尝试次数/最后提交时间"计入哈希，被干预学生每提交一次就生成新 ID，教师已处理（已确认/已忽略）的干预项会反复重现。现在 ID 只由"班级+作业+学生+原因"决定，处理结果稳定生效。**升级注意：已处理过的干预项会在升级后首次刷新时重现一次，重新确认即可，此为一次性迁移行为。**
- **练习进度与会话按学习者隔离**：练习进度统计与进行中会话现在校验 owner，同机切换账号后不再串扰。
- **云端队列降级更精细**：单个同步操作失败只跳过该项并记日志，不再让整个学习队列静默降级为本地缓存；教师端干预状态读取对脏数据降级处理，不再让整个刷新崩溃。

### AI 与网络

- **移除 AI 每日 100 次配额**（本地 Ollama 与云端 AI 一致）：长文本输入预算与超时限制保留。重度使用 NL2SQL 的学生不再被本地免费模型上的次数限制卡住。
- 网络云 AI 的 HTTP 客户端按配置指纹缓存复用，不再每次调用新建连接池。
- 云端会话 401/403 改为按状态码类型化判定：令牌被服务端吊销/过期后客户端会干净登出，而不是反复报同步失败。

### 界面修复

- 修复代码活动（CODE）中 Ctrl+Enter 提交的是编辑器挂载时的旧代码而非当前内容的问题；F1 请求提示不再绕过按钮禁用状态。
- 数据加载补齐加载中/空结果/失败三态：知识检索不再静默等待或空白；设置页保存、备份恢复、重置学习等操作失败现在有明确提示；运行环境探测失败不再永久显示"正在探测"。
- 云端页面快速切换班级时，迟到响应不再覆盖当前班级的任务列表；创建班级后自动选中新班级。
- 任务快照加载失败时明示"正在显示本地预览"，不再无提示回退。

## 兼容性说明

- **安全模式默认值变化**：全新安装默认教学模式。从未触碰过开关的存量用户升级后，写操作将开始要求确认——在设置中切换到开发者模式即可恢复无打扰；首次进入 SQL 工作台会出现一次性模式选择引导。
- **语句分级变化**：依赖"DROP/GRANT 一律被拒"旧行为的流程（如有）需要改为走确认弹窗；用户/角色管理语句仍被拒绝。
- **干预状态一次性重现**：见上文"本地数据完整性"，属预期迁移行为。
- **请求体上限**：同步事件单条 payload 超过 16 KB 将被拒绝（错误码 `PAYLOAD_TOO_LARGE`）；现网客户端正常使用不受影响。
- AI 相关接口无每日次数限制（移除）；AI 历史记录格式不变。
