# SQLTeacher v3.6.0

> 发布日期：2026-09-18（已公开，GitHub Release Latest 见 releases/README）
>
> v3.6.0 是**知识库质量版本**：修复知识助教带文档上下文提问必然失败的缺陷——前端把
> "课程/章节/标题"上下文拼进问题文本，而 Java 端从未解析该前缀，FTS 硬 AND 查询被
> 前缀装饰词整体吞掉命中，导致主流程"查什么都失败"（用户报告并经 app.db 复现）。
> 上下文改为结构化字段进入检索过滤。同期修复单篇删除残留（应用库外键从未开启、
> `on delete cascade` 从不生效）、失效文章引用的 404 请求风暴、班级任务"选择练习"
> 空下拉等缺陷；检索层完成结构感知分块升级与过滤下推；索引与一批高频界面交互改为
> 后台/可折叠/自适应。SQL 安全边界、判分逻辑、云端服务端代码均无变化。
>
> 测试执行：本地全量（CI 跳过，LEG-15 回执绑定 tag 提交）——`mvn test` 与
> `npm test`、`npm run build`、`cargo test --lib`、`ReleaseVerificationApp` 全部
> 通过后出具回执；产物校验和、ZIP 内容安全扫描、portable 冒烟启动均通过。
> （具体数字见 verification-receipt.json 与发布部署记录。）

## 主要变化

### 修复

- **知识助教带上下文提问必然返回"未检索到"**：前端把阅读上下文拼成
  `（课程：… / 章节：… / 资料标题：…）` 前缀塞进问题文本，注释声称"由 Java 端消费"但
  Java 端从未解析；`toFtsQuery` 将其按空白切词后全部 AND 连接，前缀装饰词在任何课程
  资料中都不存在，检索恒 0 命中。修复：`ai.knowledge.ask` 新增结构化 `context`
  参数（courseTitle/sectionTitle），Java 端映射为课程/章节检索过滤，问题文本保持纯净；
  旧前端不带 context 时行为不变（桥契约 additive）。本机 app.db 只读副本复现：
  带前缀 AND 查询 0 条、仅"关系模型"17 条，修复后问题文本纯净检索正常。
- **单篇文章删除后残留"可打开的文章残影"**（用户手测发现）：应用库连接从未开启
  `PRAGMA foreign_keys`（初始化器中的两处 PRAGMA 属演示库），`on delete cascade`
  从不生效；旧删除路径只清底层文档行，文章/修订/分块全部残留，再次删除报
  `COURSE_KNOWLEDGE_NOT_FOUND`。修复：新增 `CourseKnowledgeService.deleteArticle`
  聚合删除——按子表在先显式清理 混合分块→索引作业→阅读进度→知识点链接→修订→文章→
  FTS 分块→底层文档（对齐官方包 `hardDeleteArticle` 先例），并同步清理 Lucene 向量
  （清理失败不推翻删除结果，可经重建索引收敛）；旧路径遗留的孤儿残影也可被聚合删除清除。
- **失效文章引用引发连续 404 请求风暴**（sidecar 日志佐证）：官方知识库整包更新会
  硬删重建、文章 ID 全部换新，前端持有的旧引用（深链/阅读态）对同一失效 ID 反复自动
  重试。修复：文章拉取失败立即刷新课程列表并丢弃死条目、给出"文档暂时无法打开"指引、
  禁用该查询自动重试（react-query v5 中 queryFn 内 invalidate 会被吞，自愈挂在
  error 态 effect 上）。
- **班级任务"选择练习"下拉恒为空**：`practice.catalog` 返回条目本就只含启用题目且
  无 `enabled` 字段，前端误按 `item.enabled` 过滤，全部条目被滤空。
- **修改密码表单左右不一致**：当前密码/新密码两字段在两列网格中因提示文字产生高度、
  基线错位；改为纵向等宽排列并补齐提示。

### 检索质量

- **结构感知分块（KBQ-1）**：替换固定 800 字符段落硬切——标题处开新块（边界对齐章节）、
  围栏代码块与表格不从中间截断、超长块按行边界二次切分。新增迁移 26
  `knowledge_index_meta` 记录分块算法版本（`structure-aware-v1`），版本不一致时启动
  后台自动重切全部文章（本机 174 篇已实测完成）；「重建检索索引」同步升级为
  "重切 + 整体重建"（`KnowledgeIndexService.rebuildContent`）。
- **过滤下推与召回兜底（KBQ-3）**：owner/可见性/课程/章节/知识点过滤全部下推到 FTS
  SQL（过去先取 50 条再内存过滤，窄过滤欠召回）；AND 无命中时放宽为 OR + bm25 排序
  兜底（unicode61 分词器无中文分词，硬 AND 对多词中文查询过脆）。安全过滤始终留在
  SQL 层。
- **重复导入确认（KBF-3）**：单篇导入先做归一化内容查重（BOM/CRLF/连续空行收敛），
  命中既有文章时列出候选并经用户确认后才以新文章导入；不做自动合并。字节级完全相同
  的强制导入仍受 `content_hash` 唯一约束（既有防线保留）。

### 体验

- **知识页检索**：新增课程/章节过滤下拉（带可见标签与说明，契约既有能力首次暴露）；
  结果超过一页时「加载更多」分页（offset 游标）；索引有待处理任务时每 3 秒自动刷新进度。
- **知识助教**：阅读区右下角新增悬浮入口（长文阅读随处可达）；子窗口尺寸随显示器
  自适应（约 46% 宽 × 88% 高逻辑尺寸，修复固定 440×720 过小）；修复长标题/引用导致的
  横向溢出。
- **单篇导入**：新增「选择文件…」系统文件选择器（txt/md/pdf/docx），路径输入保留为后备。
- **索引后台化（KBX-1）**：导入/修订/可见性变更后的增量索引与手动重建全部移出 IPC
  调用线程，立即返回、进度经状态轮询呈现。
- **教学空间**：「题库管理」「学习进度」改为默认收起的可折叠卡片，分页大小 50→15；
  「学习进度」与「完整学情分析」合并为「本机作答记录」折叠卡（注明仅本机试做/练习
  记录，班级学情见「班级与云端」），无记录时整卡隐藏。
- **班级与云端**：「可见班级」「任务学情」「我的作品集」改为默认收起的折叠卡片。

### 明确延后

- **本地嵌入链路打通与嵌入模型一致性校验（KBQ-2）**：用户确认本机 Ollama 未安装向量
  模型，语义检索暂无运行对象；连同分块受控 overlap 一并移回积压清单
  （`docs/plans/backlog.md`），安装向量模型后启动。
- Obsidian 整库批量导入暂不参与单篇导入的交互式同内容查重（逐文件弹窗不可行，批量
  跳过策略另行处理）。
- 双写 schema（`knowledge_chunks` FTS5 + `knowledge_chunks_v2`）收敛、云端知识文章
  桌面消费端、多轮/流式助教：维持不做（见计划"明确不做"）。

## 升级与兼容

- 桥契约仅 additive：`ai.knowledge.ask` 新增可选 `context`、`knowledge.search` 新增
  可选 `offset/courseTitle/sectionTitle/knowledgePoint` 与 `hasMore` 响应字段、
  `knowledge.index.rebuild` 响应改为 `{started:true}`（原为同步报告，前端已同步）。
- 数据库迁移 26（`knowledge_index_meta`）为纯新增表；首次启动会自动用新分块算法
  重切全部文章（后台执行，日志可见 `Knowledge chunks upgraded`）。
