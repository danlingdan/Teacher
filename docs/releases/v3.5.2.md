## 主要变化

### 修复

- **下载更新必然失败（应用 operation failed）**：`SecureUpdateService` 跟随 GitHub Releases
  的 302 重定向时，会在每一轮对目标主机做 `requireAllowed` 白名单校验。GitHub 已把资产下载
  目标从 `objects.githubusercontent.com` 迁移到 `release-assets.githubusercontent.com`，白名单
  未同步，导致 v3.5.1 及之前版本点击"下载更新"100% 失败（本机 sidecar 日志确认为
  `update download host is not allowed`）。现把新 CDN 主机补入两处白名单并保持一致：
  下载侧 `SecureUpdateService.ALLOWED_HOSTS` 与清单侧 `UpdateManifest` 的 URL 主机校验；
  HTTPS 强制、SHA-256 完整性校验、Ed25519 清单签名校验等其余安全边界不变。
- **更新失败原因不再被吞**：`SecureUpdateService.download` / `launchInstaller` 原先抛
  `IllegalStateException`，会被 `LocalAppProtocolServer` 的兜底 catch 统一替换成
  "Local application operation failed"，真实原因（磁盘不足、完整性校验失败、TLS 握手被重置、
  无法启动安装器等）到不了界面。现改为抛带结构化错误码的领域异常
  （`UPDATE_DOWNLOAD_FAILED` / `UPDATE_DOWNLOAD_CORRUPTED` / `UPDATE_DOWNLOAD_CANCELLED` /
  `UPDATE_INSTALL_NOT_READY` / `UPDATE_INSTALL_FAILED`），协议层原样透传错误码与中文原因，
  界面与日志可直接定位失败类型；协议层对 `SqlTeacherException` 的既有处理与重试语义不变。

## 兼容性说明

- **桌面数据库 / IPC 契约版本 / 题库 DSL**：无任何变更；契约版本仍为 `3.0-v1`，无新端点，
  白名单方法集不变。
- **SQL 安全**：无边界变化；本版本不触及 SQL 执行、风险分析、NL2SQL 路径。
- **行为差异**：更新下载/安装失败时界面显示真实的中文原因与错误码（此前一律显示笼统的
  "Local application operation failed"）；更新清单 URL 允许落在 GitHub 的两个资产 CDN 主机
  （`objects.githubusercontent.com` 与 `release-assets.githubusercontent.com`），非 HTTPS 或
  白名单外主机的拒绝行为不变。
- **云端**：无 schema 变更、无新端点；`/api/v1/app/update-manifest` 内容格式不变。
- **更新通道**：本版本发布后，公网 update-manifest 应从 3.5.1 切换到 3.5.2（发布回写清单）。

## 已知限制与后续积压

- GitHub 直连的 TLS 握手在部分网络环境仍可能被重置（本机日志曾见
  `Remote host terminated the handshake`）；此类网络层故障不属于客户端缺陷，可在设置中开启
  更新镜像缓解。修复后此类失败至少会显示真实原因而非笼统文案。
- 下载白名单与镜像主机清单为代码内静态配置，后续如新增分发主机需要同步改代码并补测试
  （`SecureUpdateServiceTest` 已钉住当前清单）。
- `V111AccountStoreTest.resetTokenIsInvalidatedAfterFiveFailedAttempts` 在全量并发下出现过
  1 次偶发失败（单独重跑与全量重跑均通过）：`newestTokenNotIn` 依赖 `Files.list` 的目录顺序
  取"最新"重置邮件，顺序并无保证。与本次改动无关，留待后续版本修正测试的选择逻辑。
