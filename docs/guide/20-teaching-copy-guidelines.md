# 教学界面文案规范

> 适用于 SQLTeacher 2.0.1 及后续版本。

界面文字首先帮助学生完成学习任务、帮助教师作出教学判断。内部架构、数据模型和安全实现仍应记录在开发文档、日志与审计数据中，但不应成为普通教学页面的主要说明。

## 写作顺序

一段教学界面文字优先回答以下问题：

1. 当前可以学习或完成什么；
2. 用户现在需要做什么；
3. 系统会检查哪些可理解的要求；
4. 完成、未完成或失败后下一步是什么。

例如使用“正在检查你的答案”“还有两项要求未完成”，不使用“正在进行确定性评价”“评价器返回失败状态”。安全警告可以保留准确的权限、网络、文件与后果说明，但不展示与用户操作无关的类名、服务分层或内部原因码。

## 不同位置的口径

- 学生页面：使用任务、操作、结果、提示和下一步语言。
- 教师页面：使用课程目标、学生提交、答题记录、反馈和教学安排语言。
- 管理页面：可以说明版本保留、权限与审计后果，但应先解释实际影响。
- 专业课程内容：保留课程本身需要教授的术语；不要为了简化界面而改写知识定义。
- 错误与安全提示：先说明发生了什么和如何处理，再按需附上可供支持人员定位的错误编号。

## 维护约束

新增或修改主教学流程文案时，应同步维护中英文资源。主流程不得直接出现“确定性服务”“评价器”“活动定义”“安全边界”等内部实现表达；相关回归检查位于 `AppI18nTest`。
