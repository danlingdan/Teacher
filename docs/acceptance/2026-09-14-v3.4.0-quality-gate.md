## 已知限制与移交事项

以下为评估后明确移交 v3.5.0+ 的积压（计划第 7 节有完整记录）：

- 学习队列 N+1 批量端点、interventions 分析批量化、干预状态机产品规则（需跨端/产品决策）。
- Monaco 体积优化（收益/风险比一般，挂起）。
- `uiI18n` 调用点 key 化字典改造（本版已交付去重+构建期完整性检查，第二步移 3.5.0 评估）。
- surefire 按类并行（与 SQLite 临时目录/WSL runner 测试存在资源竞争风险，暂不启用）。
- 干净 Windows 10/11 全新安装/升级走查与生产云端贯通验证，随本次发布流程执行并记录于运维记录。
- BUG-4 sidecar 孤儿进程防护的两处实现偏差经评估作为工程决策接受、不做高风险重写：①退出关停用 `RunEvent::Exit` 而非计划提到的 `ExitRequested`——`Exit` 在应用真正退出时恰好触发一次，而 `ExitRequested` 可能触发后被 `prevent_exit` 取消，反而会在应用继续运行时误杀 sidecar，故 `Exit` 更可靠；②未用 `CREATE_SUSPENDED` 挂起后再入 Job——kill-on-close Job Object 已覆盖崩溃/强杀对整个 sidecar 进程树的回收（BUG-4 的核心目标），`CREATE_SUSPENDED` 仅能消除一个理论孙进程竞态窗口（`LocalAppHost` 启动阶段不派生子进程、assign 紧随 spawn 微秒级完成），而正确实现需以 unsafe `CreateProcessW`+`ResumeThread` 重写整条 spawn 路径（classpath/管道继承/编码），回归风险远大于收益。
