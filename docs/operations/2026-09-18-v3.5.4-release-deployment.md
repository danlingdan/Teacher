## 发布过程（含 GitHub 资产上传故障处置）

- 门禁：本地全量 `mvn test` 792 通过 / 0 失败 / 2 跳过；`npm test` 175 通过、
  `npm audit --omit=dev` 0 漏洞、`npm run build` 通过；`cargo test --lib` 5 通过；
  `ReleaseVerificationApp` 5 项 PASS；产物哈希、ZIP 内容安全、无控制台启动、
  portable 冒烟均通过（LEG-15 回执 a77284d 绑定 tag 提交，CI 接受并跳过重复测试）。
- tag `v3.5.4` 推送后 CI 工作流在 **Upload release assets** 步骤连续两次
  `HTTP 500: Error saving asset`（uploads.github.com，均为 ~280MB 大文件；工作流自
  v3.5.3 以来零改动，判定为 GitHub 服务端故障），第三次重试在上传步骤长时间无输出，
  手动取消。
- **处置**：按用户决定改用本地构建产物发布。因 CI 构建与本地产物字节不同（NSIS/ZIP
  时间戳），本地重新生成 `update-payload.json` 并用同一把受信密钥
  （`release-2026-01`，`UpdateManifestTool` 签名，客户端校验只依赖公钥+哈希一致性）
  重新签名清单；SHA256SUMS.txt/SBOM 一并替换为与本地构建一致的版本。
  `gh release upload --clobber` 上传 7 项资产全部成功（本机上行实测 ≈7.4 MB/s）。
- `gh release edit --draft=false --latest` 发布；`releases/latest` 指向 v3.5.4，
  非草稿、非预发布，7 项资产齐全。
